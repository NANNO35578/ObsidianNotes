# 第二章：音视频基础

## 2.1 音频基础

### 2.1.1 声音的本质

声音是**机械波**，通过空气、液体或固体介质传播。在数字音频处理中，我们需要将连续的模拟信号转换为离散的数字信号。

### 2.1.2 音频数字化

#### 采样（Sampling）
将连续的模拟信号在时间轴上离散化。

- **采样率（Sample Rate）**：每秒采样的次数，单位Hz
  - 电话质量：8kHz
  - 语音通话：16kHz
  - 音乐质量：44.1kHz（CD标准）
  - 高质量音频：48kHz

**奈奎斯特定理**：采样率必须至少是信号最高频率的2倍，才能完整还原信号。

#### 量化（Quantization）
将采样得到的幅度值转换为数字值。

- **位深度（Bit Depth）**：表示每个采样值的精度
  - 8位：256个级别
  - 16位：65536个级别（常用）
  - 24位：16777216个级别（高保真）

#### 编码（Encoding）
将量化后的数字信号按照一定格式存储。

### 2.1.3 音频格式

#### 未压缩格式
- **PCM（Pulse Code Modulation）**：脉冲编码调制
  - 文件大小 = 采样率 × 位深度 × 声道数 × 时长
  - 例如：44.1kHz × 16bit × 2声道 = 1.41Mbps

#### 压缩格式
- **MP3**：有损压缩，适合音乐
- **AAC**：有损压缩，效率高于MP3
- **OPUS**：有损压缩，专为实时通信设计
- **G.711**：电话质量，低延迟
- **G.722**：宽带语音，高质量

### 2.1.4 声道

- **单声道（Mono）**：1个声道
- **立体声（Stereo）**：2个声道（左右）
- **多声道**：5.1、7.1等（环绕声）

## 2.2 视频基础

### 2.2.1 图像的本质

图像是由**像素(Pixel)** 组成的二维数组，每个像素包含颜色信息。

### 2.2.2 颜色空间

#### RGB
- **红（Red）、绿（Green）、蓝（Blue）**三原色
- 每个颜色分量通常用8位表示（0-255）
- 一个像素需要24位（3字节）

#### YUV
- **Y**：亮度（Luminance）
- **U、V**：色度（Chrominance）
- 优势：人眼对亮度更敏感，可以压缩色度信息
- 常用格式：
  - **YUV420**：色度信息减半，节省50%空间
  - **YUV422**：色度信息减半（水平方向）
  - **YUV444**：不压缩色度信息

### 2.2.3 视频参数

#### 分辨率（Resolution）
图像的像素尺寸。

常见分辨率：
- **480p**：640×480（SD）
- **720p**：1280×720（HD）
- **1080p**：1920×1080（Full HD）
- **2K**：2560×1440
- **4K**：3840×2160（Ultra HD）

#### 帧率（Frame Rate）
每秒显示的帧数，单位fps（frames per second）。

常见帧率：
- **24fps**：电影标准
- **30fps**：视频通话常用
- **60fps**：流畅视频
- **120fps**：高帧率视频

#### 码率（Bitrate）
单位时间内传输的数据量，单位bps（bits per second）。

码率计算：
```
码率 = 分辨率 × 帧率 × 每像素位数 × 压缩比
```

例如：1080p@30fps，未压缩需要：
```
1920 × 1080 × 30 × 24 = 1,492,992,000 bps ≈ 1.49 Gbps
```

实际应用中，通过编码压缩，码率可以降低到：
- **1-2 Mbps**：可接受的视频通话质量
- **3-5 Mbps**：高质量视频通话
- **8-10 Mbps**：高清直播

### 2.2.4 视频格式

#### 未压缩格式
- **RAW**：原始像素数据，文件巨大
- **YUV**：YUV颜色空间存储

#### 压缩格式（编码）
- **H.264（AVC）**：最常用，兼容性好
- **H.265（HEVC）**：效率更高，但计算复杂
- **VP8/VP9**：开源编码，WebRTC常用
- **AV1**：新一代开源编码，效率更高

## 2.3 音视频同步

### 2.3.1 时间戳（Timestamp）

为了同步音视频，需要给每个数据包打上时间戳：

- **PTS（Presentation Time Stamp）**：呈现时间戳
- **DTS（Decode Time Stamp）**：解码时间戳

### 2.3.2 同步策略

1. **音频为主**：以音频时间戳为基准，调整视频
2. **视频为主**：以视频时间戳为基准，调整音频
3. **系统时钟**：使用系统时钟作为统一基准

### 2.3.3 音画不同步的原因

- 网络延迟不一致
- 编码延迟不同
- 播放缓冲不同
- 设备性能差异

## 2.4 数据量计算

### 2.4.1 音频数据量

```
数据量（字节/秒） = 采样率 × 位深度/8 × 声道数
```

示例：
- 44.1kHz, 16bit, 立体声：
  ```
  44100 × 16/8 × 2 = 176,400 字节/秒 ≈ 172 KB/s
  ```

### 2.4.2 视频数据量

未压缩：
```
数据量（字节/秒） = 宽度 × 高度 × 帧率 × 每像素字节数
```

示例：
- 1080p, 30fps, RGB24：
  ```
  1920 × 1080 × 30 × 3 = 186,624,000 字节/秒 ≈ 178 MB/s
  ```

压缩后（H.264）：
- 1080p@30fps：约 2-5 Mbps（250-625 KB/s）

## 2.5 音视频采集与播放

### 2.5.1 音频采集流程

```
麦克风 → 音频驱动 → 应用层 → 编码器 → 网络传输
```

### 2.5.2 视频采集流程

```
摄像头 → 视频驱动 → 应用层 → 编码器 → 网络传输
```

### 2.5.3 播放流程

```
网络接收 → 解码器 → 音频/视频渲染 → 扬声器/显示器
```

## 2.6 常见问题

### 2.6.1 音频问题

- **噪音**：环境噪音、设备噪音
- **回声**：扬声器声音被麦克风采集
- **断断续续**：网络抖动、缓冲不足

### 2.6.2 视频问题

- **卡顿**：帧率不稳定、网络延迟
- **模糊**：分辨率低、码率不足
- **花屏**：丢包、解码错误

## 2.7 实践建议

1. **理解采样和量化**：这是数字音视频的基础
2. **掌握YUV格式**：视频编码常用格式
3. **学会计算数据量**：有助于理解带宽需求
4. **了解常见参数**：分辨率、帧率、码率的关系
