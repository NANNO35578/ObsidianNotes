# 第一章：RTC基础概念

## 1.1 什么是RTC

**RTC（Real-Time Communication）**，即实时通信技术，是一种能够在互联网上实现低延迟、高质量音视频传输的技术。

### 核心特点

- **低延迟**：通常要求端到端延迟 < 400ms
- **实时性**：音视频数据实时传输，无需下载
- **交互性**：支持双向或多向通信
- **高质量**：在保证低延迟的同时，尽可能保证音视频质量

### RTC vs 传统流媒体

| 特性 | RTC | 传统流媒体 |
|------|-----|-----------|
| 延迟 | < 400ms | 数秒到数十秒 |
| 交互性 | 双向交互 | 单向传输 |
| 协议 | UDP + RTP | TCP + HTTP/HLS |
| 应用场景 | 视频通话、会议 | 点播、直播 |

## 1.2 RTC的应用场景

### 1. 视频通话
- 一对一视频通话（如微信视频、FaceTime）
- 多人视频会议（如Zoom、腾讯会议）
- 在线教育（如在线课堂、1对1辅导）

### 2. 游戏语音
- 游戏内语音聊天
- 游戏直播解说
- 团队协作语音

### 3. 直播互动
- 连麦直播
- 互动直播
- 虚拟主播

### 4. 远程协作
- 远程办公
- 远程医疗
- 远程面试

### 5. IoT应用
- 智能监控
- 智能门禁
- 远程控制

## 1.3 RTC技术栈概览

### 核心技术组件

```
┌─────────────────────────────────────┐
│         应用层（业务逻辑）             │
├─────────────────────────────────────┤
│     信令层(信令服务器)                 │
├─────────────────────────────────────┤
│  媒体处理层（编解码、音视频处理）   │
├─────────────────────────────────────┤
│   传输层（RTP/RTCP、UDP/TCP）       │
├─────────────────────────────────────┤
│   网络层（STUN/TURN/ICE、NAT穿透）  │
└─────────────────────────────────────┘
```

### 1. 信令层
- **作用**：建立连接、协商媒体参数、交换网络信息
- **协议**：WebSocket、SIP、自定义协议
- **内容**：SDP（Session Description Protocol）交换

### 2. 媒体处理层
- **音频处理**：采集、编码、解码、播放、降噪、回声消除
- **视频处理**：采集、编码、解码、渲染、美颜、滤镜
- **编解码器**：OPUS、AAC（音频）；H.264、VP8/VP9（视频）

### 3. 传输层
- **RTP（Real-time Transport Protocol）**：实时传输协议
- **RTCP（RTP Control Protocol）**：RTP控制协议
- **传输方式**：UDP（低延迟）、TCP（可靠传输）

### 4. 网络层
- **STUN（Session Traversal Utilities for NAT）**：NAT类型检测
- **TURN（Traversal Using Relays around NAT）**：中继服务器
- **ICE（Interactive Connectivity Establishment）**：连接建立

## 1.5 关键术语

### 延迟相关
- **端到端延迟（E2E Latency）**：从发送端采集到接收端播放的总时间
- **网络延迟（Network Latency）**：数据包在网络中传输的时间
- **编码延迟（Encoding Latency）**：音视频编码所需时间
- **缓冲延迟（Buffering Latency）**：接收端缓冲数据的时间

### 质量相关
- **码率（Bitrate）**：单位时间内传输的数据量（bps）
- **帧率（Frame Rate）**：每秒显示的帧数（fps）
- **分辨率（Resolution）**：图像的像素尺寸（如1920x1080）
- **采样率（Sample Rate）**：音频每秒采样次数（Hz）

### 网络相关
- **NAT（Network Address Translation）**：网络地址转换
- **防火墙（Firewall）**：网络安全设备
- **丢包率（Packet Loss Rate）**：丢失数据包的比例
- **抖动（Jitter）**：数据包到达时间的波动

## 1.6 学习建议

1. **建立整体认知**：先理解RTC的整体架构，再深入细节
2. **理论与实践结合**：每学一个概念，尝试用代码实现
3. **关注性能指标**：延迟、质量、带宽是RTC的核心指标
4. **持续实践**：通过实际项目加深理解
