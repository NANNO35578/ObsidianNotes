````markdown title:""
## 问题分析

我发现了主要问题。代码使用的是 Drogon 的异步 HTTP 客户端，但 [main.cc](vscode-webview://1l76ge18dv3tqgh8mv1mdd73i8ipmb6gd2dmkc3kqkvpsode06gm/EsClient/main.cc:5-40) 中的主函数存在**异步操作未等待完成**的问题。

### 核心问题

在 [main.cc](vscode-webview://1l76ge18dv3tqgh8mv1mdd73i8ipmb6gd2dmkc3kqkvpsode06gm/EsClient/main.cc:25) 中调用 `es.indexDocument()` 和 [main.cc](vscode-webview://1l76ge18dv3tqgh8mv1mdd73i8ipmb6gd2dmkc3kqkvpsode06gm/EsClient/main.cc:30) 中调用 `es.search()` 时：

1. `HttpClient::sendRequest` 是**异步操作**，通过 callback 返回结果
2. main 函数发送请求后**立即返回**，不等待异步操作完成
3. 程序在请求可能还未发送或完成时就退出了

```cpp

    if (result != ReqResult::Ok) {

    }
});
```

### 解决方案

需要使用 `std::promise`/`std::future` 或 Drogon 的事件循环来等待异步操作完成。参考 [test_main.cc](vscode-webview://1l76ge18dv3tqgh8mv1mdd73i8ipmb6gd2dmkc3kqkvpsode06gm/EsClient/test/test_main.cc:14-30) 的模式：

    std::cout << "ElasticSearch Client Example" << std::endl;
    EsClient es;
    
    std::promise<void> done;
    std::future<void> done_future = done.get_future();

    // 1. 插入笔记
    string noteJson = R"({
        "note_id": 1001,
        "user_id": 123,
        "title": "Elasticsearch 学习",
        "content": "今天学习了ES全文检索",
        "tags": ["学习","技术"],
        "created_at": "2026-04-02T12:00:00Z"
    })";
    
    std::string index("notes");
    std::string id("1001");
    
    // 2. 搜索笔记
    std::string content("学习");
    
    // 创建 HTTP 客户端的事件循环
    auto client = es.getClient();  // 需要暴露 getter
    
    client->setLoopThreadNum(1);
    client->start();
    
    // 执行搜索（会等待异步结果）
    es.search(index, content, [&](const string& result) {
        cout << "搜索结果：" << endl;
        cout << result << endl;
        done.set_value();  // 通知完成
    });
    
    // 等待操作完成
    done_future.wait_for(std::chrono::seconds(5));
    
    return 0;
}
````

````markdown title:""
> **Outlining CRUD logic**
> 
> The user needs a logic outline for a CRUD workflow using drogon with notes stored in MariaDB and integrated with Elasticsearch.
> 
> For Create: Write to the database and index the document. For Read: Query the database for simple requests or search in Elasticsearch for more complex ones. For Update: Modify the database record and reindex in Elasticsearch. For Delete: Remove the document from both Elasticsearch and the database. Additionally, consider consistency, error handling, and asynchronous indexing after data commits.

下面是基于 MariaDB+Elasticsearch 的笔记服务在 Drogon 后端下，针对笔记的四种基本操作（CRUD）推荐的设计思路／流程。

1. 新建（Create）
    
    - 在一个事务中先向 MariaDB 插入笔记记录，获取主键 ID
    - 事务提交后（或通过事务钩子／事件），异步向 Elasticsearch 发起索引请求，文档 ID 与数据库主键保持一致
    - 索引失败时，写入重试队列（如内存队列或消息队列），避免丢数据
2. 读取（Read）  
    a) 按 ID 读取
    
    - 直接从 MariaDB 根据主键查全量字段  
        b) 搜索列表
    - 在 Elasticsearch 中执行全文／过滤／分页查询，获取符合条件的文档 ID 列表及高亮片段
    - 根据 ID 列表去 MariaDB 批量拉取完整记录，并按 ES 返回顺序排序
    - 将 ES 高亮片段合并到返回结果中
3. 更新（Update）
    
    - 在一个事务中先更新 MariaDB 中对应记录（标题、正文、标签等）
    - 事务提交后，异步向 Elasticsearch 发起同 ID 文档的部分更新（_update API）或整体替换（索引 API）
    - 同样，更新失败写入重试队列／告警
4. 删除（Delete）
    
    - 在一个事务中从 MariaDB 删除（或标记删除）记录
    - 事务提交后，异步向 Elasticsearch 发起删除请求（delete API）
    - 删除失败时，重试或人工介入
5. 异常和一致性保障
    
    - 所有 ES 写操作均在 DB 提交后异步触发，避免“ES 写成功但 DB 回滚”的不一致
    - 引入重试队列（内存队列、RabbitMQ/Kafka 等），保证 ES 与 DB 最终一致
    - 定时全量或增量 Re-index（如周/天），检测并修复遗漏文档
6. 批量操作与性能优化
    
    - 批量索引／删除时使用 ES 的 Bulk API
    - 大批量修改可先在 DB 打标签标记，再离线脚本或定时任务批量同步到 ES
    - 搜索时只从 ES 获取最必要的字段（ID、摘要、高亮），免除网络传输冗余
7. 事务钩子或消息驱动
    
    - 利用 Drogon ORM 的事务回调钩子，或在业务层提交后发布内部消息（event bus）
    - 专门的索引服务监听这些消息并调用 ES 接口，做到业务逻辑与索引逻辑解耦

---

这样设计，既保证了主数据在关系库中的事务一致性，又能利用 Elasticsearch 做高效的全文检索和聚合。
````

### 接口核心说明
1. 搜索基于 Elasticsearch 全文检索，支持模糊匹配
2. 匹配权重：title(3x) > tags(2x) = summary(2x) > content(1x)
3. 结果排序：相关度分数降序 → 更新时间降序
4. 关键字高亮使用 `<mark>` 标签，分别返回 `highlight_title` 和 `highlight_content`
5. 列表不返回完整内容，查看详情需调用 `/api/note/detail`
