## 工作内容概括

本周实现系统最核心的两个智能模块。AI 标签生成：调用 DeepSeek API 对笔记内容进行语义分析，Prompt 工程要求返回 5 个精准标签；服务端解析 LLM 响应后自动创建/复用标签，并写入 `note_tag` 关联表，替换旧标签。

推荐系统采用基于标签的兴趣模型 + ES 检索的混合策略：
- **新用户**（近 30 天行为数 < 20）：冷启动融合「用户笔记标签 Top3 + 最新标签 Top2 + 搜索历史 Top2 + 全局热门 Top3」；
- **老用户**：基于 `user_tag_stat` 计算兴趣分数 `score = (1×view + 3×like + 7×collect) × e^(-0.1×Δt)`，取 Top 5 标签；
- 将标签集合作为关键词在 ES 的 `tags` 字段中检索 `is_public = true` 的笔记；
- 若结果为空则兜底返回最新公开笔记。

同步实现浏览、点赞、收藏 API，并确保每次行为异步更新 `user_action` 与 `user_tag_stat`。最后对全部后端 API 进行联调测试，修复参数校验、ES 查询异常、事务边界等问题。

## 工作记录（精简版）

### 一、AI 标签生成

**接口**：`POST /api/notes/{id}/tags/ai`

**Prompt 设计**：

```
请根据以下笔记内容，提取 5 个最精准的关键词标签。
要求：
1. 每个标签不超过 10 个字符
2. 标签应覆盖笔记的核心主题
3. 直接返回标签列表，不要解释

笔记内容：
{note_content}
```

**处理流程**：
1. 调用 DeepSeek API（`DsService`），超时 10s；
2. 解析响应文本，按行/逗号提取标签名；
3. 对每个标签：查 `tag` 表，存在则取 id，不存在则插入；
4. 删除该笔记旧标签关联，写入新的 `note_tag` 记录；
5. 返回生成的标签列表。

**成本核算**：2000 字笔记约 3000 tokens，DeepSeek 单价 ¥0.003/1K tokens，单次约 ¥0.009。

### 二、推荐系统

**新老用户判定**：统计 `user_action` 近 30 天行为数，< 20 为新用户。

| 用户类型 | 标签来源 | 数量 |
|----------|----------|------|
| 新用户 | 笔记标签 Top3 + 最新标签 Top2 + 搜索历史 Top2 + 全局热门 Top3 | 10 |
| 老用户 | 兴趣分数 Top 5 + 搜索历史 Top 2 + 全局热门 Top 3 | 10 |

**兴趣分数公式**：

```
score = (1 × view_count + 3 × like_count + 7 × collect_count) × e^(-0.1 × Δt_days)
```

ES 召回：将标签集合作为 `terms` 查询 `tags` 字段，过滤 `is_public=true`，按相关度排序，分页返回。

### 三、用户行为统计

| 行为 | 接口 | 异步更新 |
|------|------|----------|
| 浏览 | `/api/note/view` | `note.view_count++` + `user_action` 插入 + `user_tag_stat` 更新 |
| 点赞 | `/api/note/like` | `note.like_count++` + `note_like` 插入 |
| 收藏 | `/api/note/collect` | `note.collect_count++` + `note_collect` 插入 |

所有计数更新通过 `INSERT ... ON DUPLICATE KEY UPDATE` 实现原子性。

### 五、本周问题

- **DeepSeek API 偶发超时**：高峰期响应 > 10s。增加 1 次重试（指数退避），仍失败则返回空标签，不阻塞用户。
- **推荐结果重复**：同一笔记在连续分页中出现。解决：ES 查询增加 `search_after` 深分页机制，避免 `from+size` 重复。
