# 01.从源代码到可执行文件
![['attachments/01-1.png]]

1. _从源代码到exe需要经过哪几个时期？_	
	- 预处理期-> 编译期-> 汇编期-> 连接期-> 执行期	

2. _不同时期里：谁？在做什么事情？_
	- 预处理期: _预处理器_ 将处理所有`#`开头的指令 即宏，指令和头文件，生成 `.i`文件
	- 编译期: _编译器_ 将 `.i`文件编译成汇编语言 主要进行词法分析、语法分析、优化等操作
	- 汇编期: _汇编器_ 将 汇编语言转换成目标文件`.obj`/`.o`
	- 连接期: _链接器_ 将目标文件链接成可执行文件`.exe`
	- 执行期: _操作系统_ 加载可执行文件运行程序

3. _如果:出现语法错误是哪个时期出了问题？_
	- 编译期: 如果在源代码中有错误的语法，例如漏掉分号或使用了未定义的变量，编译器在编译期会检测到这些错误，并给出相应的错误提示。例如：`printf("Hello, World") // 缺少分号`

4. _如果产生LNK错误是哪个时期什么原因导致的呢？_
	- 连接期: LNK 错误通常是由于链接器无法找到某个符号或目标文件造成的。这可能是因为缺少库文件、未定义的函数或变量，或者目标文件未正确生成。例如：如果在代码中声明了一个函数但没有提供实现，链接器在连接期会报告错误。
```cpp
// 声明但未定义 
	void myFunction();
	
	int main() { 
	   myFunction(); // 调用未定义的函数 LNK错误
	   return 0; 
	}
```

# 02.基本数据类型
![['attachments/02-1.png]]
1. _基本数据类型分几大类和对应的小类？_
	1. 整型 (Integer Types)
		- **短整型** (`short`)
		- **整型** (`int`)
		- **长整型** (`long`)
		- **长长整型** (`long long`)
		- **无符号整型** (`unsigned short, unsigned int, unsigned long, unsigned long long`)
	2. 字符型 (Character Type)
		- **字符型** (`char`)
		- **宽字符型** (`wchar_t`)
	3. 浮点型 (Floating Point Types)
		- **单精度浮点型** (`float`)
		- **双精度浮点型** (`double`)
		- **扩展精度浮点型** (`long double`)
	4. 布尔型 (Boolean Type)
		- **布尔型** (`bool`)

2. _不同类型的字节数分别是多少？_
	1. 整型 (Integer Types)
		- **short**: 2 字节
		- **int**: 4 字节
		- **long**: 4 字节（在某些平台上为 8 字节）
		- **long long**: 8 字节
		- **unsigned short**: 2 字节
		- **unsigned int**: 4 字节
		- **unsigned long**: 4 字节（在某些平台上为 8 字节）
		- **unsigned long long**: 8 字节
	2. 字符型 (Character Type)
		- **char**: 1 字节
		- **wchar_t**: 2 字节或 4 字节（取决于平台）
	3. 浮点型 (Floating Point Types)
		- **float**: 4 字节
		- **double**: 8 字节
		- **long double**: 8 字节或 16 字节（取决于平台）
	4. 布尔型 (Boolean Type)
		- **bool**: 1 字节

3. _基本数据类型的存储原理包括哪些？_
	1. **整型存储**: 以int为例 占32位 最左侧为符号位(0为正1为负) 余下位存储该int的二进制值 该32位码称为*源码* 对源码处理得到*反码* 若为正数不做操作(源码与反码相同) 若为负数则保留符号位余下位按位取反得到反码 然后对反码操作得到*补码* 同样正数不做操作 负数则在反码基础上加一 最终得到计算机实际存储的反码 因此可以得到int类型表达范围为$[-2^{31}, 2^{31}-1]$(-1为全1)
	2. **浮点存储**: 内存空间按——*符号位+指数区+尾数区*的形式进行存储分配。其中：float 的内存空间(4 个字节 32 位): 1 个符号位+8 个指数区+23 个尾数区。double 的内存空间(8 个字节 64 位): 1 个符号位+11 个指数区+52 个尾数区。下面以一个 float 类型实例简要说明一下浮点型数据的存储过程：以10.127F 为例：转换为二进制  1010.0100000100000110001001001101110100101111000110101 指数化时二进制浮动了 3 个二进制位，这个 3（二进制的 11）在存储到指数区时需要增加 0111111 进行偏移处理。即 127+3 得到的二进制为 10000010。最终保留的为0 10000010 01000100000100000110001
	[IEEE-754 浮点转换器](https://www.h-schmidt.net/FloatConverter/IEEE754.html)

4. _不同字面值的常量后缀与前缀_
	所谓字面值即通过文字表面就能知道其代表的数据是什么，反之就是变量. 整型数据字面值的格式为：`进制前缀+字面值+类型后缀`
	1. 整型常量
		- **八进制**：以 `0` 开头 示例：`075`（十进制 61）
		- **十进制**：无前缀 示例：`42`（整型）
		- **十六进制**：以 `0x` 或 `0X` 开头 示例：`0x1A`（十进制 26）
		- **无符号整数**：后缀 `u` 或 `U` 示例：`42u`
		- **长整型**：后缀 `l` 或 `L` 示例：`42l`
		- **长长整型**：后缀 `ll` 或 `LL` 示例：`42ll`
	2. 浮点常量
		- **双精度浮点型**：无后缀 示例：`3.14`
		- **单精度浮点型**：后缀 `f` 或 `F` 示例：`3.14f`
		- **长双精度浮点型**：后缀 `l` 或 `L` 示例：`3.14l`
	3. 字符常量
		- **字符型**：用单引号表示 示例：`'a'`
		- **宽字符型**：前缀 `L` 示例：`L'a'`
	4. 字符串常量
		- **普通字符串**：用双引号表示 示例：`"Hello"`
		- **宽字符串**：前缀 `L` 示例：`L"Hello"`
		- **UTF-16 字符串**：前缀 `u` 示例：`u"Hello"`
		- **UTF-32 字符串**：前缀 `U` 示例：`U"Hello"`
	5. 布尔常量
		- **布尔值**：`true` 和 `false`（无前缀或后缀）
	6. 二进制常量（C++14 及以上）
		- **二进制**：前缀 `0b` 或 `0B` 示例：`0b1010`（十进制 10）

# 03.字符在屏幕上显示的原理
![['attachments/03-1.png]]
1. _字符型的本质、字节数与存储原理？_
	字符的本质就是一个整数编码号对应一个"显示影像". char类型通常为1字节. 字符型变量的本质就是一个整数(编码号)。因此字符型和整型从存储上原理是相同的。

2. _字符型常量的表示方式？_
	单引号表示: 直接用单引号包围一个字符，例如：`'A'`、`'b'`、`'1'`
	转义序列: 使用反斜杠 `\` 进行转义，表示特殊字符，例如`'\0'`：空字符
	八进制表示: `char ch=0101; `或 `ch = '\101` "\101\102\103\104\105\n"
	六进制表示: 使用 `\x` 后跟两位十六进制数字，例如：`\x41` 表示字符 `'A'`。

3. _举例说明：转义字符的作用？_
	有些字符比较特殊；例如和代码内置符号相同的字符如单引号’、双引号”，反斜杠\等；它们在代码中有特殊的作用，如果设置它的字面值就不可以像字母字符或数字字符那样。常见的转义字符有`\r` `\n` `\b` `\t` `\'` `\"` `\\` 分别表示回车 换行 退格 缩格等 

4. _根据字符编码表规律产生的常用算法？_
	部分字符的编码号具有规律性；如数字字符、字母字符等它们的编号都是连续的。因此可以用这些规律实现如下算法：`char ch`
	1. 是否为数字`ch >='0' && ch <= '9'`
	2. 是否为大写字母`ch >= 'A' && ch <= 'Z'`
	3. 大写转小写`ch -=32; `或者`ch -= ('A'-'a')`
	4. 数字字符转数字 `ch -= '0'`

# 04.溢出现象
![['attachments/04-1.png]]
1. _-1的二进制为什么全1？_
	 根据整型存储原理 -1 首先为负数 符号位为1 源码为`10000000 00000000 00000000 00000001` 负数取反码得`11111111 11111111 11111111 111111110` 再加一得补码 即为全1

2. _什么是整型的溢出现象？_
	由于不同的整型占据的内存空间大小是固定的，也就是说不同的整数存在数据范围的边界问题。例如：1 个字节情况下有符号的数字的范围是-128~127，无符号的数字范围则是 0~255。在没有负数情况下正整数范围翻倍了。而当数据已经是该数据类型范围内的最大值再继续增加反而变成了最小值 或是最小值，如果继续减小反而变成了最大值的现象称为溢出现象

3. _为什么有符号整型最大值+1反而最小值？_
	*数据加减是在补码的形式下进行的* 有符号最大值的最左位为符号位 因为是正数所以为0 而其余位为1 源码即为补码 再加一产生的进位一直传递到符号位 将符号位从0变1 变成了负数 而余下位计算后只有最右位为0 因为是补码 即为最小值的存储

# 05.自动类型转换规律
![['attachments/05-1.png]]
1. _基本数据类型转换包括哪两种方式？_
	规律 1：当有整型与浮点型同时运算时：*整型向浮点型转换*(无关字节数的大小)
	规律 2：当==存储原理相同==时：*字节少的向字节多的转换*
	规律 3：char 或 short 变量参加的算术表达式，计算结果最小为 int 类型

	*0* char类型计算时提升为int int/2取下整为0

4. _`unsigned char a=-1; a/2`的结果？_
	unsigned char 范围$[0,255]$  赋值为-1时转换为255 除二得127

# 06.短路问题
![['attachments/06-1.png]]
1. _逻辑与&&的运算特点？_
	`&&`是逻辑与运算 表达式*两边都为真时*整个表达式才为真

2. _逻辑或||的运算特点？_
	`||`是逻辑或运算 表达式*一边为真时*表达式就为真
	`&&`比`||`高一个优先级运算

3. _短路问题指什么？_
	对于`&&`表达式 只有两边为真才为真 而当左边为为假时 右边表达式不会被运行
	同理 对于`||`表达式 若左边表达式已为真时 右边表达式也不会被运行

# 07.指针变量类型的作用
![['attachments/07-1.png]]
1. _指针变量的空间大小与什么有关？_
	与操作系统架构有关 若为x86即32位操作系统 指令长度为32位即4字节 指针也就是4字节 若为x64操作系统 指令长度为64位 即8字节

2. _指针变量保留的是什么？_
	保留的是变量的内存地址 类型信息(影响如何解引用)

3. _内存地址编号的特征？_
	唯一性: 即不会重复地址编号
	连续性: 并从小编号地址到大编号
	虚拟性: 在现代操作系统中，内存地址通常是虚拟地址，映射到物理内存，由操作系统管理

4. _指针变量类型的两大作用是什么？_
	解引用: 指针类型决定了如何访问其指向的数据。通过解引用操作符（`*`），可以获取指针指向的值。
	内存步长: 指针类型影响内存地址的增量。不同类型的指针在进行地址运算时，步长不同（例如，`int*` 每次增加 4 字节，`char*` 每次增加 1 字节），确保正确访问相应类型的数据。

# 10.数组指针
![['attachments/10-1.png]]
1. _指针数组是什么？_
	指针数组是存储指针的数组

2. _数组指针是什么？_
	数组指针是对指针可以指向更大内存空间的扩展类型 int \[4\]代表的是4 个int 的空间，可以理解为一种扩展的数据类型 而数组指针就是指向这种扩展类型的指针 定义为`int (* p)[4];` 同理可推出二维数组指针 `int (* p2)[3][2]`

3. _数组指针与基本类型指针的区别？_
	指向数据类型分别是基本类型 与基本类型的数组 ; 使用方式 基本类型指针可以直接通过解引用获取或修改指针所指向的值：\*ptr = 10; 数组指针解引用后返回整个数组的引用，不能直接用 * 获取单个元素，需要通过索引访问：(\*ptr)\[0\] = 10; 不同维度的数组名+1 时加的是当前数组最高维度的空间大小

4. _数组指针如何访问数组成员空间？_
	解引用后返回整个数组的引用，通过索引访问：(\*ptr)\[0\] = 10;

# 11.一维数组名_特性
![['attachments/11-1.png]]
1. _数组的特征包括哪些？_
	三个特性：长度固定、连续存储，有序编号每个成员，编号最小为 0，最大为长度减 1
	存储类型相同

2. _数组名的特性包括什么？_
	数组名是指针常量
	数组名本质上是数组首元素地址
	数组名+整数 得到的是数组内某成员的地址
	数组名代表第 0 个成员的地址

3. _数组名+1与&数组名+1的区别？_
	数组名+1 代表从首元素开始偏移一个存储类型的大小即第二个元素地址
	&数组名 +1 代表从首元素开始偏移整个数组大小空间

4. _`[]`运算符的计算过程是什么？_
	优先级和( )一样，最高优先级。其使用格式为：参照地址\[偏移量\]
	等价于 \*(参照地址+偏移量)
	arr\[N\] 从第 0 个成员地址(arr)开始偏移指向下标 N 成员的地址 然后按照数据类型获取存储内容

# 13.大小端存储
![['attachments/13-1.png]]
1. _内存空间分配的顺序是什么？_
	1. *静态存储区*
		内容：全局变量和静态变量。
		分配时机：程序编译时分配，生命周期贯穿整个程序运行。
		存储位置：.data 段（已初始化）和 .bss 段（未初始化）。
	2. *栈 (Stack)*
		内容：局部变量、函数参数、返回地址。
		分配顺序：采用后进先出（LIFO）方式，内存地址从高向低增长。
		特点：自动管理，函数结束后自动释放。
	3. *堆 (Heap)*
		内容：动态分配的内存（使用 malloc、new 等）。
		分配顺序：通常从低地址向高地址增长，取决于内存管理器。
		释放顺序：需要手动释放（使用 free 或 delete），否则可能导致内存泄漏。
	4. *代码区 (Text)*
		内容：存储程序的机器指令。
		特点：通常为只读，以防止程序意外修改其指令。
	**静态存储区** → **栈** → **堆** → **代码区**

2. _什么是小端存储及应用？_
	内存中低地址存储低位数值 而高地址存储高位数值
	一些处理器架构（如 x86 和 x86-64）使用小端存储 
	一些文件格式（如 BMP 图像文件）使用小端存储来表示多字节数据

3. _什么是大端存储及应用？_
	内存中低地址存储高位数值 而高地址存储低位数值
	网络协议（如 TCP/IP）通常使用大端存储，这被称为网络字节顺序，以确保在不同机器间传输数据时的统一性
	一些处理器（如 PowerPC 和 SPARC）使用大端存储

4. _代码举例：验证是否是小端存储？_
```cpp
bool isLittleEndian() {
    unsigned int x = 1;  // 1 的二进制表示为 00000001
    char* p = reinterpret_cast<char*>(&x);
    return p[0] == 1;    // 检查最低字节
}
```

# 14.函数在源代码中的三种状态
![['attachments/14-1.png]]
1. _函数的三种状态包括哪些？_
	前置声明：即在调用函数功能前需要提前“告知”有此功能。
	定义实现：即函数的功能具体如何实现？用流程结构描述具体实现的过程。我们把这个过程也称为“封装”——函数封装流程结构，流程结构必须写在函数里封装起来才不会触犯语法错误。
	调用执行：函数的功能实现后是“死的”，只有被调用才能“激活”执行。

2. _定义函数都包括什么？_
	函数名 参数 返回值 函数体{}包括的代码块 函数修饰符

3. _为什么需要前置声明？_
	1. 避免循环依赖: 在某些情况下，两个类可能相互引用，导致编译器无法确定它们的完整定义。通过前置声明，可以避免这种循环依赖。
	2. 提高编译速度: 如果只需要使用指针或引用，可以使用前置声明而不是包含完整的头文件，从而减少不必要的依赖，缩短编译时间。
	3. 简化依赖管理: 使用前置声明可以减少头文件之间的依赖关系，使代码结构更清晰，便于维护。
	4. 提高封装性: 前置声明有助于隐藏实现细节，只暴露接口，使得类的实现与使用分离，提高了封装性。

4. _自定义函数时：三种状态的最佳顺序？_
	声明 声明的语法是只有函数的头部而没有代码的实现过程，所以这个特点比较适合功能的特征（参数与返回类型）描述与设计思维描述的环节。很多语言也把这个语法称为接口。
	调用 这样的目的是从应用场景角度验证函数规划的参数条件于返回结果是否满足应用的需要。如参数个数，顺序，类型等是否合理。
	定义实现 经过应用场景调用下的验证，我们基本对这个函数的设计目的及应用已经非常清楚了，这时开发就会更加的有的放矢

# 15.堆区与栈区
![['attachments/15-1.png]]
1. _内存区域有哪些？_
	- 代码区：当我们的程序被执行时，它会有一个加载准备的过程。其中函数及内部的流程结构代码指令会被放到代码区中，等待着被调用执行。
	- 常数区：字符串常量、const 全局变量在程序启动加载时会放置在常数区，被放置在此区域的数据不可被修改，只能读取。
	- 全局区/静态区： 全局变量和代码中的静态变量会在程序启动执行时被加载到此区域。此区域的变量空间只有程序结束关闭后才会被释放。
	- 栈区： 当函数被调用时，其内部的形参、函数内的其它局部变量会被创建在栈区。当函数被调用结束后，配合函数的局部变量就会被操作系统自动释放回收。
	- 堆区： 堆区是由程序员自主管理的内存空间，可以通过 malloc 等函数在堆区内存中申请需要的任意大小的内存空间。但当此内存空间不打算继续使用时，务必使用 free 函数释放掉这些空间，否则在程序关闭以前，这些内存空间是不会被其它程序所使用的，会造成很大的空间浪费甚至宕机。直到程序被关闭后没有手动释放的空间才会被操作系统回收。

2. _什么样的变量在栈区？_
	函数内部的形参、函数内的其它局部变量会被创建在栈区

3. _堆区与栈区的特性是什么？_
	栈区的特性: 向下生长
	- 自动管理：局部变量在函数调用时分配，在函数返回时自动释放。
	- 存储速度快：由于栈区的分配和释放遵循后进先出（LIFO）原则，因此访问速度较快。
	- 大小限制：栈区的大小通常较小，依赖于系统的栈大小设置，容易导致栈溢出（stack overflow）。
	- 作用域：局部变量的生命周期和作用域仅限于函数内部。
	堆区的特性: 向上生长
	- 手动管理：内存的分配和释放由程序员控制，使用 new 和 delete 关键字。
	- 存储速度较慢：堆区的内存分配和释放相对较慢，因为需要查找合适的块并可能进行碎片整理。
	- 大小灵活：堆区的大小可以根据需要动态分配，通常受到系统内存限制。
	- 作用域广泛：在堆区分配的对象可以在程序的多个地方使用，直到显式释放内存。

4. _堆区不释放的后果会怎样？_
	- 内存泄漏：分配的内存无法被访问或使用，导致可用内存逐渐减少。
	- 资源耗尽：如果长时间运行的程序不断分配堆内存而不释放，最终可能耗尽系统内存，导致程序崩溃或无法分配新的内存。
	- 性能下降：内存泄漏可能导致系统变得缓慢，因为操作系统需要花费更多时间进行内存管理和寻找可用内存。
	- 不稳定性：程序可能出现不可预期的行为，甚至崩溃，特别是在内存耗尽时。
	- 调试难度增加：内存泄漏可能难以追踪，增加了调试和维护的复杂性。

# 16.函数执行原理
![['attachments/16-1.png]]
1. _函数执行的基本过程？_
	使用函数名所代表的代码区地址找到函数代码，加上`( )`传入实参执行这段代码
	- 函数调用：当程序执行到函数调用语句时，控制权转移到该函数。
	- 参数传递：如果函数有参数，调用时会将实参传递给形参。参数可以通过值传递或引用传递。
	- 分配栈空间：为该函数在栈区分配空间，存储局部变量、参数和返回地址。
	- 执行函数体：按照函数内部的代码顺序执行，进行计算或其他操作。
	- 返回值处理：如果有返回值，函数会将结果存储在指定的返回位置。
	- 释放栈空间：函数执行完毕后，栈空间被释放，控制权返回到调用函数的地方。
	- 继续执行：调用函数之后的代码继续执行，使用函数返回的值（如果有的话）。

2. _局部变量包括哪些？_
	函数内部的形参、函数内定义的变量

3. _函数名的特性及与函数所在代码区的关系？_
	函数的名字就是其所在代码区的内存地址
	- 标识符：函数名是一个标识符，用于唯一标识该函数。在同一作用域内，函数名必须唯一。
	- 类型：函数名的类型由其返回值类型和参数列表决定，这称为函数的“签名”。
	- 可重载性：函数可以根据参数类型和数量进行重载，即同名但参数不同的多个函数可以共存。
	- 作用域：函数名的作用域通常限于定义该函数的文件和命名空间，特别是在使用 static 关键字时，*其作用域仅限于定义它的文件*。
	与函数所在代码区的关系: 
	- 存储位置：函数名在编译时映射到存储在代码区中的函数体。代码区是程序可执行代码的存储区域
	- 调用时解析：当函数被调用时，编译器根据函数名和参数列表在代码区查找对应的函数地址，并将控制权转移到该地址。
	- 链接：在多文件项目中，函数名在链接阶段被解析，以确保调用的函数是在代码区中定义的。

4. _函数指针能执行函数的原理？_
	存储函数所在代码区地址的变量 使用函数指针调用函数时，通过解引用指针并传入相应的参数 通过跳转到存储在指针中的地址来实现。程序控制流程转移到该地址处，从而执行函数体

# 17.枚举类型
![['attachments/17-1.png]]
1. _举例：什么情况需要定义枚举类型？_
	主要用于某数据类型的数据值是有限的且有意义的少量可能的值 例如，表示一个任务的状态, 表示用户角色, 表示方向颜色 或者一组*错误码* 一些配置选项

2. _定义枚举类型的格式？_
```cpp
		enum EnumName {
	    Constant1,  // 默认值为 0
	    Constant2,  // 默认值为 1
	    Constant3,  // 默认值为 2
	    // ...
	    ConstantN   // 默认值为 N-1
		};
```
3. _枚举类型变量的值可以是整数吗？_
	默认是从0开始的整数 可自定义为整数

4. _枚举类型在源代码中的意义？_
	- 增强可读性：枚举提供了有意义的名称代替数字常量，使代码更易于理解。例如，使用 Color::RED 比使用 0 更直观。
	- 减少错误：使用枚举可以避免使用错误的常量值，编译器会检查传递给函数的枚举类型是否有效，从而减少类型错误。
	- 组织相关常量：枚举将相关常量组合在一起，有助于代码的组织和管理，使得相关值更易于查找和维护。
	- 提高可维护性：当需要修改常量值时，只需在枚举定义中进行更改，避免了在代码中到处查找和替换常量的麻烦。
	- 支持类型安全：在使用 enum class 时，枚举类型是强类型的，避免了不同枚举之间的隐式转换，提高了类型安全性。
	- 便于调试：枚举类型在调试时更容易识别和显示，因为它们使用了有意义的名称而不是数字，使调试信息更具可读性。

# 19.`const`
![['attachments/19-1.png]]
1. _`const`关键字是什么？_
	用于声明常量，使得被修饰的变量在其生命周期内不可修改。它可以用于基本数据类型、结构体、类以及指针等

2. _`const`修饰变量的注意事项？_
	不可修改：一旦用 const 声明变量，就不能再对其赋值。`const int x = 10;  x = 20; // 错误：不能修改常量`
	作用域：const 变量的作用域与普通变量相同，超出作用域后将不再有效。
	初始化：const 变量必须在声明时初始化，因为其值不可更改。
	与指针结合：在指针使用中，const 关键字可以修饰指针本身或指向的数据，具体用法需注意。

3. _`const`修饰指针变量的三种方式？_
	- 指向常量的指针: `const int* ptr;`指针 ptr 指向常量 int，不能通过 ptr 修改其指向的值
	- 常量指针: `int* const ptr = &value;` ptr 是常量指针，指向的地址固定，不能修改 ptr 的地址，但可以修改指向的数据
	- 常量指针指向常量: `const int* const ptr = &value;` ptr 是常量指针，既不能修改地址，也不能修改指向的数据

# 20.全局变量 局部变量
![['attachments/20-1.png]]
1. _全局变量与局部变量定义位置的区别？_
	*全局变量*通常指在函数体外部创建的变量。程序被启动执行时，它们会被创建在全局区。
	*局部变量*指函数体内的定义的变量，包括形式参数在内都是局部变量。它们是伴随函数调用而被创建于栈区，函数调用结束后从栈区被回收的临时性变量。
	全局变量与局部变量的区别在于生命周期与作用域的不同

2. _全局变量的生命周期与作用域是什么？_
	- 在程序启动时就被创建在全局区，并且默认初始值置为 0。只有程序被关闭后，其占用的内存空间才被释放掉 
	- 全局变量可以被项目内任何的函数访问

3. _局部变量的生命周期与作用域是什么？_
	- 而局部变量是其所在函数被执行时才被创建，函数执行结束后被回收。当函数再被执行时局部变量再重新创建
	- 局部变量的访问只能在函数体内部，函数体外部是不能通过局部变量名字访问函数内的变量
	同时 在一个函数 被执行时，恰巧其函数内定义的局部变量名与全局变量名重名时，按照临近原则，全局变量被屏蔽，只有最近的局部变量才能被访问函数体内部，函数体外部是不能通过局部变量名字访问函数内的变量

# 21.`static`
![['attachments/21-1.png]]
1. _`static`变量与非`static`变量所在内存区的区别？_
	- static 变量：存储在全局区（或静态区），在程序整个运行期间保持存在。只初始化一次，后续调用仍然保持上次的值。
	- 非 static 变量：存储在栈区（局部变量）或全局区（全局变量）。局部变量在函数调用时创建，函数结束后销毁，值在每次调用时重新初始化。

2. _C源代码的范围包括哪些？_
	- **代码区**：存储程序的机器指令。
	- **常量区**：存储程序中定义的常量数据。
	- **全局区**：存储全局变量和 `static` 变量。
	- **堆区**：动态分配内存的区域，使用 `malloc`、`calloc` 等函数分配。
	- **栈区**：存储局部变量和函数调用时的上下文信息。

3. _`static`变量的生命周期与作用域是什么？_
	- 生命周期：static 变量的生命周期是整个程序运行期间。它们在程序开始时分配内存，并在程序结束时释放。
	- 作用域：static 变量的作用域通常是定义它的块（如函数或文件）。如果在函数内定义，则只能在该函数内访问；如果在文件内定义，则只能在该文件内访问（文件作用域），但在整个程序中保持静态特性。

# 22.`extern`
![['attachments/22-1.png]]
1. _`extern`是什么意思？_
	`extern` 是一个存储类说明符，用于声明一个变量或函数在其他文件中定义。它告诉编译器该变量或函数的定义在别的地方，避免重复定义。

2. _`extern`的使用场景？_
	- **跨文件共享变量**：当多个源文件需要访问同一个变量时，可以在一个文件中定义变量，在其他文件中使用 `extern` 声明该变量。
	- **函数声明**：在一个文件中定义函数，而在其他文件中声明该函数以供使用
3. _使用`extern`的注意事项？_
	- **必须匹配类型**：使用 `extern` 声明的变量或函数必须与其定义时的类型匹配。
	- **初始化问题**：`extern` 声明的变量不能被初始化，因为它只是一个引用，不占用存储空间。`    extern int globalVar = 10;` 错误：不能初始化
	- **链接性**：确保在链接阶段，所有使用 `extern` 声明的变量或函数都有相应的定义，否则会导致链接错误。
	- **作用域**：`extern` 对于变量和函数的作用域是全局的，但变量的定义位置决定了它的可见性。

# 23.宏定义
![['attachments/23-1.png]]
1. _`#define`与`#include`在预处理时的不同作用？_
	- `#define` ：用于定义宏，创建常量或函数-like 宏。在预处理阶段，编译器会将所有出现的宏名称替换为其定义的内容。主要用于简化代码，增强可读性，或者条件编译。
	- `#include` ：用于包含头文件。在预处理阶段，编译器会将指定的头文件内容插入到当前文件中。主要用于代码重用和模块化，允许将函数、类及其他声明组织到多个文件中。

2. _参数宏的用法与注意事项？_
```cpp
#define SQUARE(x) ((x) * (x)) // 定义一个参数宏
int result = SQUARE(5); // result = 25
```
	- 括号：在宏定义中使用括号，以避免运算顺序错误。
	- 副作用：如果传递的参数有副作用（如自增），可能导致意外结果。

2. _举例：宏的嵌套定义是什么？_
	宏的嵌套定义指的是在一个宏中调用另一个宏。
```cpp
#define DOUBLE(x) ((x) + (x)) 
#define SQUARE(x) ((x) * (x)) 
#define DOUBLE_SQUARE(x) (DOUBLE(SQUARE(x))) // 嵌套宏
```

2. _宏定义类型与`typedef`定义类型的区别？_
	- 宏定义：使用 `#define` 定义常量或替换代码片段，不进行类型检查。在预处理阶段进行文本替换，可能会引入错误。
	- `typedef` ：用于定义类型别名，提供类型检查。在编译阶段进行，增强代码的可读性并保持类型安全。

# 24.字符串数组与字符串

1. _字符数组与字符串的区别？_
	字符数组是存储连续字符的内存空间。字符数组不一定能构成字符串
	字符串是以'\0'为标志的字符数组

2. _字符串常量的创建过程？_

	- `char* str="abc";` ：创建一个指向字符串常量的指针，常量存储在只读内存中，内容不可修改。如果尝试修改 str 指向的内容，将导致未定义行为。

# 25.`struct` & `union`
![['attachments/25-1.png]]
1. _扩展类型（或称复合类型）包括哪些？_
	- 结构体 (struct)：用于组合不同类型的数据。
	- 联合体 (union)：用于在同一内存位置存储不同类型的数据，但只能存储其中一个。
	- 枚举 (enum)：用于定义一组命名的整型常量。
	- 数组：用于存储相同类型的多个元素。

2. _`struct`与`union`的区别？_
	- 存储方式：struct：每个成员都有自己的内存空间，大小为所有成员大小之和。union：所有成员共享同一内存空间，大小为最大成员的大小。
	- 使用场景：struct：适合需要同时存储多个数据成员的情况。union：适合在不同时间存储不同类型的数据，节省内存。

3. _结构体对齐补齐指什么以及意义？_
	- 对齐补齐：在内存中，编译器根据数据类型的大小和架构要求，将结构体的各个成员按特定的边界对齐。例如，一个 int 可能要求在 4 字节对齐，而 char 可能要求在 1 字节对齐。
	- 意义：提高访问效率：对齐能使 CPU 更快地访问数据，减少因不对齐导致的性能损失。避免潜在的硬件错误：某些架构可能不支持未对齐的内存访问。

4. _`union`使用时的注意事项？_
	- 只能使用一个成员：在任何时候只能使用 union 中的一个成员，修改一个成员会影响其他成员的值。
	- 正确使用类型：访问 union 中的成员时，需确保访问的是最后被写入的成员，否则可能导致未定义行为。
	- 初始化：union 只能初始化一个成员，使用时需注意初始化的成员。
	- 大小和对齐：union 的大小由最大成员决定，注意对齐可能导致的内存浪费。

# 26.链式存储与顺序存储
![['attachments/26-1.png]]
1. _什么是线性表数据结构？_
	线性表是一种基本的数据结构，其中的数据元素按线性顺序排列。每个元素都有一个唯一的前驱和后继，除了第一个元素没有前驱和最后一个元素没有后继。线性表可以用来表示一系列相互关系的元素，如数组、链表等。

2. _什么是顺序存储及优缺点？_
	顺序存储是通过数组来实现线性表的数据结构。所有元素在内存中连续存储。
	- 优点：
		- 随机访问：可以通过索引直接访问任意元素，时间复杂度为 O(1)。
		- 空间利用率高：没有额外的指针开销，存储效率高。
	- 缺点：
		- 插入和删除：在数组中插入或删除元素需要移动大量元素，时间复杂度为 O(n)。
		- 固定大小：数组大小固定，无法动态扩展，可能导致空间浪费或溢出。

3. _什么是链式存储及优缺点？_
	链式存储是通过链表来实现线性表的数据结构。每个元素（节点）包含数据部分和指向下一个节点的指针。
	- 优点：
		- 动态大小：可以根据需要动态分配内存，灵活性高。
		- 高效插入和删除：在已知位置插入或删除元素时，只需改变指针，时间复杂度为 O(1)。
	- 缺点：
		- 随机访问：无法直接通过索引访问元素，必须从头遍历，时间复杂度为 O(n)。
		- 额外开销：每个节点需要存储指针，增加了内存开销。

# 27.文件处理模型
![['attachments/27-1.png]]
1. _内存存储与外存存储的差异是什么？_
	内存存储：
		速度：访问速度快，适合频繁读写操作。
		持久性：数据在断电后会消失，不具备持久性。
		类型：通常是随机存取存储器（RAM），用于存储正在运行的程序和数据。
	外存存储：
		速度：访问速度较慢，适合大容量数据存储。
		持久性：数据在断电后依然保留，具备持久性。
		类型：包括硬盘、固态驱动器（SSD）、光盘等，用于长期存储数据和文件

2. _文件存储类别包括哪两种；及区别？_
	文本文件：
		存储可读的字符数据，使用特定的编码格式（如 ASCII、UTF-8）。
		适合人类阅读和编辑，数据以行和列的形式组织。
		处理简单，可以直接用文本编辑器打开。
	二进制文件：
		存储以二进制格式表示的数据，不能直接用文本编辑器阅读。
		包含数据的原始格式，适合存储图像、音频、视频等复杂数据。
		处理复杂，需要特定的程序解析和操作。

3. _`fopen`函数的执行过程模型是什么？_
	请求文件打开：根据传入的文件名和模式（如读取、写入等）请求操作系统打开指定文件。
	检查文件状态：操作系统检查文件是否存在、权限是否允许、是否已被其他进程占用等。
	分配资源：如果文件打开成功，操作系统为该文件分配内存和资源（如文件描述符）。
	返回文件指针：fopen 返回一个指向 FILE 结构的指针，供后续的文件操作使用。
	错误处理：如果打开失败，返回 NULL，并设置错误码，供调用者检查。

# 28.文件复制原理
![['attachments/28-1.png]]
1. _如何创建目标文件？_
	在C语言中，可以使用`fopen`函数来创建目标文件。通过指定模式为`"wb"`（写入二进制）或`"w"`（写入文本），可以创建一个新文件或覆盖现有文件。

2. _`buffer`数组的作用？_
	`buffer`数组用于暂时存储从源文件读取的数据。它在文件复制过程中充当数据的缓存，允许程序块读取和写入数据，而不是逐字节处理。

3. _`fread`函数的返回值是什么？_
	`fread`函数的返回值是成功读取的元素数量。它可以用来判断读取操作是否成功，以及是否到达文件末尾。

4. _文件复制的执行过程？_
	- 使用`fopen`打开源文件以读取模式，打开目标文件以写入模式。
	- 使用`fread`从源文件读取数据到`buffer`中。
	- 使用`fwrite`将`buffer`中的数据写入目标文件。
	- 重复步骤2和3，直到读取到文件末尾（`fread`返回的元素数量为0）。
	- 使用`fclose`关闭源文件和目标文件。

# 29.C语言组件化
![['attachments/29-1.png]]
1. _组件化的前提是什么？_
	组件化的前提是良好的模块划分和接口设计。每个组件应功能独立，具备清晰的接口，以便于重用、替换和维护。此外，组件之间的耦合度应尽量低，以增强系统的灵活性和可扩展性。

2. _静态库的优缺点？_
	- **优点：**
    - **性能**：静态库在编译时链接到可执行文件，运行时不需要额外的加载时间。
    - **独立性**：最终生成的可执行文件包含所有必要的代码，无需依赖外部库。
	- **缺点：**
    - **文件大小**：可执行文件较大，因为所有代码都被包含在内。
    - **更新不便**：库的更新需要重新编译所有依赖该库的可执行文件。

3. _动态链接库的优缺点？_
	- **优点：**
    - **文件大小**：可执行文件较小，因为只包含必要的代码，其他部分由动态链接库提供。
    - **更新方便**：可以独立更新动态库，而无需重新编译所有依赖它的可执行文件。
	- **缺点：**
    - **性能**：运行时加载动态库可能导致启动时间增加。
    - **依赖性**：需要确保目标系统上存在正确版本的动态库，可能会导致兼容性问题。
