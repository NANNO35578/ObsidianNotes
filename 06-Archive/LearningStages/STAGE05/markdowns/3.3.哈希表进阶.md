# 3.3 哈希表进阶

## 一、装载因子（Load Factor）

哈希表中存储的元素数量与槽位总数的比率：

$$\alpha = \frac{\text{元素数量}}{\text{槽位数量}}$$

### 作用

1. **性能指标**：装载因子越高，冲突越多，查找/插入/删除的平均时间越长
2. **动态调整**：当装载因子超过阈值（通常 0.75）时，触发**重新哈希（rehashing）**，扩容并重新组织元素

### 常见阈值

- 通常 0.5 ~ 0.75 为合理范围
- Java `HashMap` 默认阈值 0.75
- C++ `unordered_map` 默认 `max_load_factor = 1.0`

---

## 二、哈希冲突解决方法对比

### 1. 链地址法（Separate Chaining）

每个槽位存储一个链表，哈希值相同的元素链接在一起。

- 优点：简单易实现，动态扩展；删除操作简单
- 缺点：额外指针空间；最坏情况查找 $O(n)$

### 2. 开放定址法（Open Addressing）

冲突时探测其他空槽位。

- **线性探测**：顺序检查后续槽位
- **二次探测**：$+1^2, -1^2, +2^2, -2^2, \ldots$
- **双重哈希**：用第二个哈希函数计算步长

- 优点：无额外空间，缓存友好
- 缺点：可能产生"聚集"现象；删除需特殊标记（不能直接删，否则断链）

### 3. 再哈希法

冲突时用不同的哈希函数重新计算。

### 4. Cuckoo Hashing（布谷鸟哈希）

每个元素有两个可能位置，冲突时将已有元素"踢"到备用位置，继续尝试。

- 查找和插入通常 $O(1)$
- 实现复杂，可能频繁重哈希

---

## 三、线性探测 vs 拉链法

| 特性 | 拉链法 | 线性探测 |
|------|--------|----------|
| 冲突处理 | 链表存储多个元素 | 寻找下一个空槽 |
| 额外空间 | 需指针空间 | 无额外开销 |
| 高装载因子 | 性能下降不明显 | 性能急剧下降（聚集） |
| 删除操作 | 简单，直接删节点 | 复杂，需标记墓碑 |
| 缓存友好 | 差（链表指针跳跃） | 好（连续内存） |
| 最坏查找 | $O(n)$ | $O(n)$ |

### 选择建议

- **线性探测**：数据量小、装载因子低、需要缓存友好
- **拉链法**：数据量大、高冲突、频繁插入删除

---

## 四、扩容与重哈希

当装载因子超过阈值时：
1. 申请更大的数组（通常 2 倍）
2. 遍历旧数组，对每个元素重新计算哈希值，放入新数组
3. 释放旧数组

> 重哈希的时间复杂度为 $O(n)$，但均摊到每次插入为 $O(1)$。

---

## 五、哈希函数设计原则

1. **确定性**：相同输入必须产生相同输出
2. **均匀性**：输出应均匀分布在整个值域
3. **高效性**：计算速度快
4. **雪崩效应**：输入微小变化导致输出巨大变化（加密哈希）

### 常见哈希函数

- 整数：除留余数法 `key % p`
- 字符串：BKDRHash、APHash、DJBHash
- 通用：`std::hash`（C++）、`hashCode()`（Java）
