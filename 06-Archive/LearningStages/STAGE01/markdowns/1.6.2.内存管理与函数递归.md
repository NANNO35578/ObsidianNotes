# 内存管理与函数递归

## 程序内存四区

以 C/C++ 为例，程序运行时内存主要分为四个区域：

### 代码区

- 存放 CPU 执行的机器指令（编译后的二进制代码）
- **共享的**：频繁执行的程序只需保留一份代码
- **只读的**：防止程序意外修改指令

### 全局区（静态区 / 数据区）

存放全局变量、静态变量和常量。可细分为：

| 子区 | 内容 |
|---|---|
| data 区 | 已初始化的全局变量、静态变量、常量 |
| bss 区 | 未初始化的全局变量、静态变量，程序执行前自动初始化为 0 或 NULL |
| 常量区 | 字符串常量、`const` 修饰的全局变量 |

### 栈区（stack）

- 由编译器**自动分配和释放**，存放函数参数值、局部变量等
- 先进后出（LIFO）的内存结构
- 分配方向：由**高地址向低地址**增长
- 空间有限，Windows 默认栈大小约 1MB，过大的局部数组会栈溢出

### 堆区（heap）

- 用于**动态内存分配**，容量远大于栈区
- 由程序员手动分配和释放（`malloc`/`free`、`new`/`delete`）；若不释放，程序结束时由操作系统回收
- 增长方向：由**低地址向高地址**增长
- 频繁分配释放会产生内存碎片

> 每个程序都有独立的四个内存区域。了解各区域特性对编程和调试至关重要。

## 函数递归

### 递归的概念

函数直接或间接调用自身，称为递归。递归将复杂问题分解为规模更小的同类子问题。

递归的两个必要条件：
1. **基线条件（base case）**：递归终止的条件，不再调用自身
2. **递归条件（recursive case）**：将问题缩小，调用自身

缺少基线条件会导致无限递归，最终栈溢出崩溃。

### 递归与栈

每次函数调用（包括递归调用）都会在栈区分配一块栈帧，保存局部变量、参数和返回地址。递归深度过大时栈帧累积，可能耗尽栈空间。

### 经典示例：阶乘

```c
int factorial(int n) {
    if (n <= 1) return 1;          // 基线条件
    return n * factorial(n - 1);   // 递归条件
}
```

执行 `factorial(3)` 的调用链：
```
factorial(3) → 3 * factorial(2)
             → 3 * (2 * factorial(1))
             → 3 * (2 * 1)
             → 6
```

### 经典示例：斐波那契数列

```c
int fib(int n) {
    if (n <= 1) return n;               // 基线条件
    return fib(n - 1) + fib(n - 2);     // 递归条件
}
```

> 朴素递归斐波那契存在大量重复计算，时间复杂度 O(2^n)，实际应用中应改用迭代或记忆化。

### 递归的优缺点

| 优点 | 缺点 |
|---|---|
| 代码简洁，符合数学定义 | 函数调用开销大 |
| 天然适合树、图等结构 | 深度过大导致栈溢出 |
| 易于理解分治思想 | 重复子问题效率低 |

## 动态内存管理

### malloc / free

```c
#include <stdlib.h>

int* p = (int*)malloc(sizeof(int) * 10);  // 分配 10 个 int 的堆空间
if (p != NULL) {
    p[0] = 42;
    free(p);    // 释放堆内存
    p = NULL;   // 释放后置空，避免悬空指针
}
```

- `malloc(size_t size)`：分配指定字节数，返回 `void*`，失败返回 NULL
- `free(void* ptr)`：释放 `malloc`/`calloc`/`realloc` 分配的内存
- `calloc(n, size)`：分配并初始化为 0
- `realloc(ptr, newSize)`：调整已分配内存的大小

> `free` 后指针变为悬空指针，必须置 NULL。同一块内存不可重复释放。
