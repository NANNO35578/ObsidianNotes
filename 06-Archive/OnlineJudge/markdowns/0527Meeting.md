# 1.UDP 怎么样可以实现可靠的传输
 1. 应用层重传机制  **确认（ACK）**：接收方在成功接收到数据后发送确认消息，发送方在未收到确认时重传数据。
 2. 序列号  **数据包序列化**：为每个数据包分配一个序列号，接收方可以根据序列号检测丢包和顺序问题。
 3. 超时重传  **超时机制**：设置超时阈值，如果在特定时间内未收到确认，则重传数据包。
 4. 数据完整性检查  **校验和**：使用校验和来检查数据包在传输过程中的完整性，确保数据未损坏。
 5. 流量控制  **控制发送速率**：根据网络状况调整发送速率，避免网络拥塞。

想要使用UDP还要保证数据的可靠传输，就只能通过应用层来做文章。实现的方式可以参考TCP。

在应用层实现可靠传输关键点有两个，从应用层角度考虑分别是：

1. 提供超时重传机制，能避免数据报丢失的问题。
2. 提供确认序列号，保证数据拼接时候的正确排序。 
- 请求端：首先在UDP数据报定义一个首部，首部包含确认序列号和时间戳，时间戳是用来计算RTT(数据报传输的往返时间)，计算出合适的RTO(重传的超时时间)。然后以等-停的方式发送数据报，即收到对端的确认之后才发送下一个的数据报。当时间超时，本端重传数据报，同时RTO扩大为原来的两倍，重新开始计时。 
- 响应端：接受到一个数据报之后取下该数据报首部的时间戳和确认序列号，并添加本端的确认数据报首部之后发送给对端。根据此序列号对已收到的数据报进行排序并丢弃重复的数据报。

# 2.TCP滑动窗口机制
##### TCP流量控制-滑动窗口
- _窗口概念_:TCP是每发送一个数据 都要进行一次确认应答 当上一个数据包收到了应答了 再发送下一个 _缺点_:效率比较低
- 有了窗口 就可以指定窗口大小 窗口大小就是指无需等待确认应答 而可以继续发送数据的最大值

> _窗口大小由哪一方决定?_
> 三次握手的时候 会交换窗口大小 通常窗口的大小是由接收方的窗口大小来决定的。发送方发送的数据大小不能超过接收方的窗口大小 否则接收方就无法正常接收到数据。

# 3.什么是网关，举例说明
网关（Gateway）是连接两个不同网络的设备或软件，通常用于不同协议之间的通信。
> 网间连接器 协议转换器. 
> 网间连接器 就是连接两个子网之间的 _设备或软件_ 如路由器具有网关功能 都是具有路由功能的IP地址 就是说网关必须要有路由功能 默认的主机号都是0,这样的才是网关。

它的主要功能包括：
##### 1. 协议转换
- 网关能够在不同的网络协议之间进行转换，使得不同网络能够相互通信。
##### 2. 数据包转发
- 网关可以接收来自一个网络的数据包，并将其转发到另一个网络。
##### 3. 网络安全
- 网关可以实施安全策略，如防火墙功能，来保护内部网络。
##### 4. 互联网接入
- 在家庭或企业环境中，网关通常是连接内部网络与互联网的设备，常见的如路由器。
##### 5. 应用层网关
- 一些网关工作在应用层，处理特定应用程序的通信，如邮件网关、Web网关等。

网关在网络中起着重要的桥梁作用，确保不同网络和协议之间的顺畅通信。连接和管理不同协议与流量的关键作用


#### 软件网关
1. **邮件网关**：处理邮件传输，如 Microsoft Exchange。
2. **API网关**：管理和路由API请求，如 AWS API Gateway。
3. **Web网关**：用于Web流量管理和过滤，如 Squid Proxy。
4. **VPN网关**：提供安全的远程访问，如 OpenVPN。

#### 硬件网关
1. **路由器**：连接家庭或企业网络与互联网，如 Cisco 路由器。
2. **防火墙**：提供安全防护并进行流量过滤，如 Palo Alto Networks 防火墙。
3. **IoT网关**：连接物联网设备与云服务，如 Raspberry Pi 作为网关。
4. **交换机**：某些智能交换机具备网关功能，允许跨网络通信。
