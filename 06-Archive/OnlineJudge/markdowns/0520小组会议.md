# `const`和`constexpr`
在C++中，`const`和`constexpr`都是用于定义常量的关键字，但它们有不同的用途和特性。

### 1. `const`
- **定义**: `const`用于声明常量，表示该变量的值不能被修改。
- **类型**: 可以用在任何类型的变量上。
- **运行时**: `const`变量的值可以在运行时确定。
- **示例**: `const int x = 10;  // x在运行时被初始化，值不可修改`
### 2. `constexpr`
- **定义**: `constexpr`用于声明常量表达式，表示该值可以在编译时求值。  
- **要求**: 必须是可在编译时计算的表达式。
- **性能**: 通常用于提高性能，因为它允许编译器在编译时进行优化。
- **示例**:
    ```cpp
    constexpr int square(int x) {
        return x * x;  // 函数可以在编译时求值
    }
    constexpr int y = square(5);  // y在编译时被计算为25
    ```
### 3. 主要区别
- **求值时间**: `const`可以在运行时确定，`constexpr`在编译时确定。
- **适用范围**: `constexpr`限制更严格，要求表达式必须是常量表达式。
- **使用场景**: `const`用于不需要在编译时求值的常量，`constexpr`用于需要在编译时求值的常量表达式。
### 4. 例子对比
```cpp
const int a = 10; // 运行时常量
constexpr int b = 20; // 编译时常量

constexpr int add(int x, int y) {
    return x + y; // 编译时求值
}

const int c = add(1, 2); // c在运行时被计算
constexpr int d = add(3, 4); // d在编译时被计算
```

# 介绍一下C++中观察者模式
观察者模式（Observer Pattern）是一种常见的设计模式，在C++中广泛应用于事件驱动的编程和GUI框架中。它定义了一种一对多的依赖关系，使得当一个对象的状态发生变化时，所有依赖于它的对象都能自动得到通知并更新。

### 主要角色
1. **主题（Subject）**: 维护观察者的列表，并提供注册和注销观察者的方法。
2. **观察者（Observer）**: 定义一个接口，用于在主题状态发生变化时更新自身。
3. **具体主题（ConcreteSubject）**: 实现主题接口，管理状态并通知观察者。
4. **具体观察者（ConcreteObserver）**: 实现观察者接口，响应主题的状态变化。
### 工作流程
1. 观察者注册到主题。
2. 主题状态变化时，调用观察者的更新方法。
3. 观察者根据主题的变化进行相应的处理。
##### 示例代码

```cpp
#include <iostream>
#include <vector>
#include <memory>

// 观察者接口
class Observer {
public:
    virtual void update(int state) = 0;
};

// 主题接口
class Subject {
public:
    virtual void attach(std::shared_ptr<Observer> observer) = 0;
    virtual void detach(std::shared_ptr<Observer> observer) = 0;
    virtual void notify() = 0;
};

// 具体主题
class ConcreteSubject : public Subject {
private:
    std::vector<std::shared_ptr<Observer>> observers;
    int state;

public:
    void attach(std::shared_ptr<Observer> observer) override {
        observers.push_back(observer);
    }

    void detach(std::shared_ptr<Observer> observer) override {
        observers.erase(
            std::remove(observers.begin(), observers.end(), observer), observers.end());
    }

    void setState(int newState) {
        state = newState;
        notify();
    }

    int getState() const {
        return state;
    }

    void notify() override {
        for (auto& observer : observers) {
            observer->update(state);
        }
    }
};

// 具体观察者
class ConcreteObserver : public Observer {
private:
    std::string name;

public:
    ConcreteObserver(const std::string& name) : name(name) {}

    void update(int state) override {
        std::cout << "Observer " << name << " updated with state: " << state << "\n";
    }
};

// 主函数
int main() {
    auto subject = std::make_shared<ConcreteSubject>();

    auto observer1 = std::make_shared<ConcreteObserver>("Observer 1");
    auto observer2 = std::make_shared<ConcreteObserver>("Observer 2");

    subject->attach(observer1);
    subject->attach(observer2);

    subject->setState(10); // 通知所有观察者

    return 0;
}
```

> 观察者模式提供了一种灵活的方式来建立对象之间的关系，有助于实现低耦合的设计。它在事件管理、GUI应用程序和多线程环境中具有广泛的应用。

# 什么是折叠引用
折叠引用（folding references）是C++11及以后版本中引入的一种特性，主要用于简化模板编程中的引用类型处理。它允许在模板参数中自动处理和简化多个引用的组合。
##### 1. 基本概念
在C++中，引用可以是左值引用、右值引用或常量引用等。当我们使用模板时，如果将多个引用类型结合在一起，会产生复杂的类型。例如，使用`std::tuple`或模板参数包时，可能会出现嵌套的引用。
##### 2. 折叠规则
折叠引用的规则如下：
- **左值引用和左值引用**: 结果为左值引用。
- **右值引用和右值引用**: 结果为右值引用。
- **左值引用和右值引用**: 结果为左值引用。
##### 3. 示例
```cpp
#include <iostream>
#include <type_traits>

template<typename T>
void printType(T&& arg) {
    std::cout << std::is_lvalue_reference<decltype(arg)>::value << "\n"; // 输出是否为左值引用
}

int main() {
    int x = 10;
    printType(x);             // 输出 1 (左值引用)
    printType(5);             // 输出 0 (右值引用)
    printType(std::move(x));  // 输出 0 (右值引用)
}
```
##### 4. 应用场景
折叠引用在模板编程中非常有用，尤其是在处理转发时（如使用`std::forward`）。它简化了类型推导，使得模板更加灵活和易于使用。

# C++中四个map
在C++中，常用的四种 `map` 相关的数据结构分别是：
1. **`std::map`**
2. **`std::unordered_map`**
3. **`std::multimap`**
4. **`std::unordered_multimap`**
### 1. `std::map`
- **特性**: 有序容器，内部使用红黑树实现。
- **存储**: 键值对以键的升序排列。
- **查找复杂度**: O(log n)。
- **允许重复键**: 不允许。
### 2. `std::unordered_map`
- **特性**: 无序容器，内部使用哈希表实现。
- **存储**: 键值对没有特定排列。
- **查找复杂度**: 平均 O(1)，最坏情况 O(n)。
- **允许重复键**: 不允许。
### 3. `std::multimap`
- **特性**: 有序容器，内部使用红黑树实现。
- **存储**: 键值对以键的升序排列。
- **查找复杂度**: O(log n)。
- **允许重复键**: 允许。
### 4. `std::unordered_multimap`
- **特性**: 无序容器，内部使用哈希表实现。
- **存储**: 键值对没有特定排列。
- **查找复杂度**: 平均 O(1)，最坏情况 O(n)。
- **允许重复键**: 允许。

# STL核心思想
C++ STL（标准模板库）的核心思想可以总结为以下几个方面：

### 1. **泛型编程**
- **定义**: STL 提供了一种通用的方法来操作数据结构和算法，通过模板实现。
- **优势**: 允许编写与类型无关的代码，提高了代码的重用性和灵活性。
### 2. **算法与数据结构分离**
- **定义**: STL 将算法和数据结构分开设计。
- **优势**: 用户可以独立选择数据结构和算法，并通过一致的接口进行组合，增强了灵活性。
### 3. **容器**
- **定义**: STL 提供多种容器（如 `vector`, `list`, `map` 等）来存储和管理数据。
- **类型**: 容器分为序列容器和关联容器，适应不同的使用场景。
### 4. **迭代器**
- **定义**: 迭代器是用于遍历容器的对象，提供统一的访问接口。
- **类型**: 迭代器有不同类型（如输入迭代器、输出迭代器、随机访问迭代器），支持不同的操作。
### 5. **算法**
- **定义**: STL 提供丰富的算法（如排序、查找、变换等），可以在容器上直接使用。
- **优势**: 通过算法与容器的结合，用户可以高效地处理数据。
### 6. **适配器**
- **定义**: 适配器用于修改容器或迭代器的接口，以适应不同的需求。
- **类型**: 包括容器适配器（如 `stack`, `queue`）和迭代器适配器（如 `reverse_iterator`）。
### 7. **性能与效率**
- **设计**: STL 的设计考虑了性能，许多算法和容器都经过优化，适合高效处理大量数据。

# C++ STL六大核心组件

### 1. **容器（Containers）**
- **定义**: 用于存储和管理数据的对象。
- **类型**:
    - **序列容器**: `vector`, `deque`, `list`
    - **关联容器**: `set`, `map`, `multiset`, `multimap`
    - **无序容器**: `unordered_set`, `unordered_map`, `unordered_multiset`, `unordered_multimap`
### 2. **算法（Algorithms）**
- **定义**: 处理数据的函数，提供各种操作，如排序、查找、变换等。
- **示例**: `sort`, `find`, `accumulate`, `copy`
### 3. **迭代器（Iterators）**
- **定义**: 用于遍历容器的对象，提供统一的访问方式。
- **类型**:
    - **输入迭代器**: 只读
    - **输出迭代器**: 只写
    - **前向迭代器**: 一次读取
    - **双向迭代器**: 前后读取
    - **随机访问迭代器**: 支持任意位置访问
### 4. **适配器（Adapters）**
- **定义**: 修改容器或迭代器的接口，以适应不同的需求。
- **类型**:
    - **容器适配器**: `stack`, `queue`, `priority_queue`
    - **迭代器适配器**: `reverse_iterator`, `insert_iterator`
### 5. **函数对象（Functors）**
- **定义**: 可以像函数一样调用的对象，通常是重载了 `operator()` 的类。
- **用途**: 用于自定义排序或其他操作。
### 6. **分配器（Allocators）**
- **定义**: 负责管理内存分配和释放的对象。
- **作用**: 提供内存管理机制，允许自定义内存分配策略。
