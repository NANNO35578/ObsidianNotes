# 如何解决TCP粘包问题
- **定长协议**： ==固定包大小== 每个消息的长度是固定的，接收方知道每个包的大小。
	- 缺点 : 可能浪费时间拆包
- **分隔符协议**： 在每个消息后添加特定的分隔符（如`\n`或`\0`），接收方根据分隔符判断消息的结束。
	- 缺点 : 数据可能会与标志重复 起始标志还可能会导致无法确定何处结束 (考虑数据类型是否固定)
- **消息头**：==先发数据长度 再发数据==  在每个消息前添加一个固定长度的消息头，包含消息的长度信息。接收方首先读取消息头，知道接下来要读取多少字节。
- **短连接**: 建立连接时发送数据然后断开 适用于用户操作间隔时间长

- **使用应用层协议**：
    - 使用现有的应用层协议（如HTTP、WebSocket等），这些协议已经解决了粘包和拆包问题。

# TCP与UDP能否使用同一端口

- TCP和UDP是不同的传输层协议，操作系统会根据协议类型将数据包路由到正确的应用程序。
- 如DNS通过UDP提供快速查询，同时在需要保证可靠性或处理大数据量时使用TCP。这种设计使得DNS既能高效处理大量请求，又能在必要时提供可靠性。
