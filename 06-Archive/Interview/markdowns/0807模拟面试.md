
> [!abstract] 为什么用`nginx`, 对`nginx`了解多少?
> - 异步框架的网页服务器, 可用作反向代理,负载均衡,和HTTP缓存.
> - 免费开源, 异步事件驱动处理请求, 在Linux上使用epoll事件模型, 在BSD等操作系统上使用类似epoll就绪模型的kqueue
> - 模块化事件驱动架构, 整体采用模块化设计, 有丰富模块库和第三方库, 配置灵活


> [!note] 为什么使用rtmp，而不其他的流媒体协议？
> - rtmp（实时流媒体传输协议）具有广泛的兼容性，很多流媒体服务器都为rtmp提供了很好的支持
> - 且rtmp的配置相对简单，既可以用作点播也能用于直播，其他的流媒体协议比如rtsp（实时视频流传输），一般是用作摄像头，安防系统，和视频会议
> - 底层采用UDP，允许大量丢包. 
> 
> - 同时在后续实现功能过程中，也有一些更适合视频点播的协议
> - 比如hls协议通过拆分视频成ts小块，通过m3u8索引找到具体播放位置，方便跳转，且可以通过转码实现自适应码率，在客户端网络质量不好时也能匹配合适的播放源



> [!abstract] 客户端播放视频出现卡顿, 怎么排查问题
> 如果用户反馈视频播放卡顿，我会从以下几个方面着手排查和优化：
>
> 1. **确认卡顿类型**：是首次加载慢，还是播放过程中缓冲
> 2. **检查客户端网络状况**：排除带宽不足或丢包情况. 抓包分析（Wireshark）或测速, 使用 HLS 的 `EXT-X-TARGETDURATION` 了解片段长度，计算缓冲情况
> 3. **查看 HLS 服务（nginx）是否能快速响应 `.ts` 文件请求**，以及转码后的视频是否完整输出. nginx配置是否合理,如是否设置缓存
> 4. **确认 ffmpeg 是否实时转码造成延迟**，考虑改为预转码+多码率支持
> 5. **优化播放器策略**，例如增加缓冲大小、预加载片段数等
> 6. **部署 CDN** 和 nginx 调优，提高访问效率
>
> 最终目标是**降低首帧时间、减少缓冲次数、提高用户体验**

##### 死锁四个必要条件
- 互斥: 一份资源只能由一个线程持有
- 不可剥夺: 线程持有的资源不可被其他线程剥夺
- 循环等待: 两个线程各自持有自己的资源, 并且等待对方释放资源
- 持有并等待: 线程持有资源时, 一直等待
`[!!example:打破死锁]` : 打破以上一个条件即可, 同时需要考虑线程安全问题

# [`kqueue`](https://zh.wikipedia.org/wiki/Kqueue) vs [`epoll`](https://zh.wikipedia.org/wiki/Epoll "Epoll") vs [`IOCP`](https://zh.wikipedia.org/wiki/IOCP "建议看英文") 

建议看英文Wikipedia:  [`kqueue`](https://en.wikipedia.org/wiki/Kqueue) vs [`epoll`](https://en.wikipedia.org/wiki/Epoll "Epoll") vs [`IOCP`](https://en.wikipedia.org/wiki/IOCP) 

##### 我们知道在Linux下`epoll`是一个高效的IO多路复用同步非阻塞的机制, 在Windows下有没有类似的机制? 了解IOPC吗
- epoll 与 IOCP 最明显的区别在于: epoll是就绪模型, IOCP是完成模型
- *就绪模型*意思是, 当某个文件fd有数据可读写时, 系统内核通知程序可以进行读写操作, 然后再去做下面的操作. 是“我问系统现在能不能做，然后我自己去做”
- *完成模型*意思是, 某个文件数据读写已经完成了, 可以直接执行下面的操作了. 是“我告诉系统我要做什么，然后系统做完了告诉我”

`[!!example:用投简历比喻]` 内推时, IOCP就是我们跟就业老师说想投XX公司内推, 当有内推码后, 就业老师就帮我们投了, 然后我们就开始面试了. <br>而epoll就相当于我们跟就业老师说想投XX公司内推, 有内推码后, 就业老师把内推码告诉我们, 我们自己去投递, 然后再去面试.

---
##### 线程安全问题
- 相比下, epoll的就绪线程安全问题是我们自己保证的: 当事件就绪时, 我们分为接受连接任务和事件业务, 在`if`分支中, 分别构建不同的任务投入任务队列, 然后由线程池加锁保证的并发情况下加锁不会出现多个线程处理同一任务. 
- 流程为: `事件就绪-> epoll_wait返回-> 构造任务-> 投入线程池-> 线程池线程上锁读取任务-> 执行任务-> ......`

然而, IOCP的事件就绪后只会有一个线程操作, 一般不会出现数据竞争等线程安全问题. 
- 首先分析一下IOCP流程: `创建线程-> 线程阻塞等待IOCP事件-> 初始化IOCP事件-> 投递异步任务(读取客户端数据)-> 任务完成-> 线程处理任务-> 任务完成(回显数据)-> 继续投递异步事件-> .....`
- 具体原因是, 每次投递的异步操作使用独立的上下文, 什么意思呢? 就是每次投递的是单个socket与其绑定的完成异步操作的数据. 其次, IOCP 本质是事件队列, 因为事件是**单线程消费的**, 而线程由系统唤醒

`[!!|bug|debit:投递任务用到的非阻塞函数|230,126,128]` [`WSARecv`](https://learn.microsoft.com/en-us/windows/win32/api/winsock2/nf-winsock2-wsarecv)

- 强在哪儿? 支持监听的种类多

	2. 信号捕获
	3. 进程退出通知
	4. 文件修改
	5. 定时器事件

程安全问题
- 相比下, epoll的就绪线程安全问题是我们自己保证的: 当事件就绪时, 我们分为接受连接任务和事件业务, 在`if`分支中, 分别构建不同的任务投入任务队列, 然后由线程池加锁保证的并发情况下加锁不会出现多个线程处理同一任务. 
- 流程为: `事件就绪-> epoll_wait返回-> 构造任务-> 投入线程池-> 线程池线程上锁读取任务-> 执行任务-> ......`

然而, IOCP的事件就绪后只会有一个线程操作, 一般不会出现数据竞争等线程安全问题. 
- 首先分析一下IOCP流程: `创建线程-> 线程阻塞等待IOCP事件-> 初始化IOCP事件-> 投递异步任务(读取客户端数据)-> 任务完成-> 线程处理任务-> 任务完成(回显数据)-> 继续投递异步事件-> .....`
- 具体原因是, 每次投递的异步操作使用独立的上下文, 什么意思呢? 就是每次投递的是单个socket与其绑定的完成异步操作的数据. 其次, IOCP 本质是事件队列, 因为事件是**单线程消费的**, 而线程由系统唤醒

`[!!|bug|debit:投递任务用到的非阻塞函数|230,126,128]` [`WSARecv`](https://learn.microsoft.com/en-us/windows/win32/api/winsock2/nf-winsock2-wsarecv)
 



```c title:"IOCP样例"
#define _WINSOCK_DEPRECATED_NO_WARNINGS
#include <winsock2.h>
#include <windows.h>
#include <stdio.h>

#pragma comment(lib, "Ws2_32.lib")

#define PORT 12345
#define WORKER_THREADS 4
#define BUFFER_SIZE 1024



typedef struct {
    OVERLAPPED overlapped; // 用于异步 I/O
    SOCKET sock;           // 与客户端通信的 socket
    WSABUF wbuf;           // Winsock 缓冲区结构体
    char buf[BUFFER_SIZE]; // 实际数据缓冲
    enum { OP_RECV, OP_SEND } op_type;
} PER_IO;

// 工作线程函数
DWORD WINAPI Worker(LPVOID arg) {
    HANDLE iocp = (HANDLE)arg;
    DWORD bytes;
    ULONG_PTR key;
    OVERLAPPED *olp;

    // 使用 `GetQueuedCompletionStatus` 阻塞等待 IOCP 事件
    while (GetQueuedCompletionStatus(iocp, &bytes, &key, &olp, INFINITE)) {
        PER_IO *pio = CONTAINING_RECORD(olp, PER_IO, overlapped);

        if (bytes == 0) {
            // 客户端关闭连接
            printf("Client disconnected\n");
            closesocket(pio->sock);
            free(pio);
            continue;
        }

        if (pio->op_type == OP_RECV) {
            // 接收到数据，准备回显
            pio->wbuf.len = bytes;
            pio->wbuf.buf = pio->buf;
            pio->op_type = OP_SEND;

            DWORD sent;
            int ret = WSASend(pio->sock, &pio->wbuf, 1, &sent, 0, &pio->overlapped, NULL);
            if (ret == SOCKET_ERROR && WSAGetLastError() != WSA_IO_PENDING) {
                fprintf(stderr, "WSASend failed: %d\n", WSAGetLastError());
                closesocket(pio->sock);
                free(pio);
            }
        } else if (pio->op_type == OP_SEND) {
            // 回显完成，继续接收
            ZeroMemory(&pio->overlapped, sizeof(OVERLAPPED));
            pio->wbuf.buf = pio->buf;
            pio->wbuf.len = BUFFER_SIZE;
            pio->op_type = OP_RECV;
            DWORD flags = 0;
            int ret = WSARecv(pio->sock, &pio->wbuf, 1, NULL, &flags, &pio->overlapped, NULL);
            if (ret == SOCKET_ERROR && WSAGetLastError() != WSA_IO_PENDING) {
                fprintf(stderr, "WSARecv failed: %d\n", WSAGetLastError());
                closesocket(pio->sock);
                free(pio);
            }
        }
    }

    return 0;
}

int main() {
    WSADATA wsa;
    WSAStartup(MAKEWORD(2, 2), &wsa);

    SOCKET listen_sock = socket(AF_INET, SOCK_STREAM, 0);
    if (listen_sock == INVALID_SOCKET) {
        fprintf(stderr, "socket failed: %d\n", WSAGetLastError());
        return 1;
    }

    struct sockaddr_in addr = {
        .sin_family = AF_INET,
        .sin_port = htons(PORT),
        .sin_addr.s_addr = INADDR_ANY
    };

    if (bind(listen_sock, (struct sockaddr*)&addr, sizeof(addr)) == SOCKET_ERROR) {
        fprintf(stderr, "bind failed: %d\n", WSAGetLastError());
        return 1;
    }

    listen(listen_sock, SOMAXCONN);
    printf("Echo server listening on port %d\n", PORT);

    // 第一步创建一个 IOCP；
    HANDLE iocp = CreateIoCompletionPort(INVALID_HANDLE_VALUE, NULL, 0, 0);
    CreateIoCompletionPort((HANDLE)listen_sock, iocp, 0, 0);

    // 创建 4 个工作线程，每个线程阻塞等待 IOCP 上的完成事件
    for (int i = 0; i < WORKER_THREADS; i++) {
        CreateThread(NULL, 0, Worker, iocp, 0, NULL);
    }

    while (1) {
        SOCKET client = accept(listen_sock, NULL, NULL); // 每当接收到一个连接时：
        if (client == INVALID_SOCKET) {
            fprintf(stderr, "accept failed: %d\n", WSAGetLastError());
            continue;
        }

        printf("Client connected: %d\n", (int)client);

        CreateIoCompletionPort((HANDLE)client, iocp, 0, 0); // 将客户端 socket 注册到 IOCP；

        // 为该 socket 分配一个 `PER_IO` 对象；
        PER_IO *pio = (PER_IO*)calloc(1, sizeof(PER_IO)); 
        pio->sock = client;
        pio->wbuf.buf = pio->buf;
        pio->wbuf.len = BUFFER_SIZE;
        pio->op_type = OP_RECV;

        DWORD flags = 0;
        int ret = WSARecv(client, &pio->wbuf, 1, NULL, &flags, &pio->overlapped, NULL); // 发起异步接收操作
        if (ret == SOCKET_ERROR && WSAGetLastError() != WSA_IO_PENDING) {
            fprintf(stderr, "WSARecv failed immediately: %d\n", WSAGetLastError());
            closesocket(client);
            free(pio);
        }
    }

    closesocket(listen_sock);
    WSACleanup();
    return 0;
}
```

##### `[!!example: ]` 3. IOCP

- 创建完成端口：`HANDLE iocp = CreateIoCompletionPort(INVALID_HANDLE_VALUE, NULL, 0, 0);`
- 关联句柄：`CreateIoCompletionPort(fileHandle, iocp, (ULONG_PTR)key, 0);`
- 发起异步 I/O：例如 `ReadFile`／`WSARecv`，传入一个 `OVERLAPPED` 结构
- 等待并获取完成：`GetQueuedCompletionStatus(iocp, &transferred, &key, &overlapped, INFINITE);`



```c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/event.h>
#include <sys/time.h>
#include <fcntl.h>
#include <netinet/in.h>

int main() {
    int listen_fd = socket(AF_INET, SOCK_STREAM, 0);
    // bind & listen 略
    fcntl(listen_fd, F_SETFL, O_NONBLOCK);

    int kq = kqueue();
    struct kevent change;
    EV_SET(&change, listen_fd, EVFILT_READ, EV_ADD, 0, 0, NULL);
    kevent(kq, &change, 1, NULL, 0, NULL);

    struct kevent events[16];
    while (1) {
        int n = kevent(kq, NULL, 0, events, 16, NULL);
        for (int i = 0; i < n; i++) {
            if (events[i].ident == (unsigned)listen_fd) {
                int conn = accept(listen_fd, NULL, NULL);
                fcntl(conn, F_SETFL, O_NONBLOCK);
                EV_SET(&change, conn, EVFILT_READ, EV_ADD, 0, 0, NULL);
                kevent(kq, &change, 1, NULL, 0, NULL);
            } else {
                int fd = events[i].ident;
                char buf[1024];
                int r = read(fd, buf, sizeof(buf));
                if (r <= 0) {
                    close(fd);
                } else {
                    // echo 回显
                    write(fd, buf, r);
                }
            }
        }
    }
    return 0;
}
```

这段 C 代码展示了一个使用 **IOCP (I/O Completion Port)** 实现的 **基于 Windows 的高性能 TCP Echo 服务器**。它通过重叠 I/O（Overlapped I/O）来实现**异步网络通信**，可以处理大量客户端连接而不需要每个连接都占用一个线程。

---

## ✅ 代码功能概述

* 使用 `IOCP`（I/O Completion Port）机制来处理多客户端通信。
* 主线程负责：

  * 初始化 Winsock；
  * 创建监听 socket；
  * 接受客户端连接并投递异步接收请求；
* 工作线程：

  * 等待 IOCP 上的事件；
  * 读取收到的数据；
  * 使用 `WSASend` 发回数据（即 Echo）。

---

## 📌 数据结构说明

```c
typedef struct {
    OVERLAPPED overlapped; // 用于异步 I/O
    SOCKET sock;           // 与客户端通信的 socket
    WSABUF wbuf;           // Winsock 缓冲区结构体
    char buf[1024];        // 实际数据缓冲
} PER_IO;
```

这是一个用于保存每次 I/O 操作（接收或发送）所需的上下文信息的结构体。

---

## 🧩 关键流程详细说明

---

### 1️⃣ 初始化与监听

```c
WSAStartup(MAKEWORD(2,2), &wsa);
SOCKET listen_sock = socket(AF_INET, SOCK_STREAM, 0);
```

初始化 Winsock，创建一个 TCP socket。

> 绑定 (`bind`) 和监听 (`listen`) 代码省略，应在这里插入。

---

### 2️⃣ 创建 IOCP 并与监听 socket 关联

```c
HANDLE iocp = CreateIoCompletionPort(INVALID_HANDLE_VALUE, NULL, 0, 0);
CreateIoCompletionPort((HANDLE)listen_sock, iocp, 0, 0);
```

* 第一步创建了一个 IOCP；
* 第二步将监听 socket 与之绑定（实际上意义不大，主要是接受后还需要对 `client` socket 再绑定）。

---

### 3️⃣ 创建工作线程

```c
for (int i = 0; i < WORKER_THREADS; i++)
    CreateThread(NULL, 0, Worker, iocp, 0, NULL);
```

创建 4 个工作线程，每个线程阻塞等待 IOCP 上的完成事件。

---

### 4️⃣ 主线程负责接受客户端连接并发起异步接收

```c
while (1) {
    SOCKET client = accept(listen_sock, NULL, NULL);
    CreateIoCompletionPort((HANDLE)client, iocp, 0, 0);

    PER_IO *pio = calloc(1, sizeof(*pio));
    pio->sock = client;
    pio->wbuf.buf = pio->buf;
    pio->wbuf.len = sizeof(pio->buf);
    DWORD flags = 0;
    WSARecv(client, &pio->wbuf, 1, NULL, &flags, &pio->overlapped, NULL);
}
```

每当接收到一个连接时：

* 将客户端 socket 注册到 IOCP；
* 为该 socket 分配一个 `PER_IO` 对象；
* 发起异步接收操作 (`WSARecv`)。

---

### 5️⃣ 工作线程的执行逻辑

```c
while (GetQueuedCompletionStatus(iocp, &bytes, &key, &olp, INFINITE)) {
    PER_IO *pio = CONTAINING_RECORD(olp, PER_IO, overlapped);
    if (bytes == 0) {
        closesocket(pio->sock);
        free(pio);
        continue;
    }
    // echo
    pio->wbuf.len = bytes;
    pio->wbuf.buf = pio->buf;
    DWORD sent;
    WSASend(pio->sock, &pio->wbuf, 1, &sent, 0, &pio->overlapped, NULL);
}
```

### 📌 工作线程逻辑：

1. 使用 `GetQueuedCompletionStatus` 阻塞等待 IOCP 事件；
2. 若 `bytes == 0`，表示客户端断开连接；

   * 关闭 socket；
   * 释放资源；
   * `continue`。
3. 否则，处理收到的数据并通过 `WSASend` 发回（Echo）；

   * 使用同一个 `PER_IO` 结构进行发送。

---

## 🔁 注意事项

* **未重投 WSARecv**：工作线程发送完数据后，没有再次发起 `WSARecv`，意味着这个 Echo 是 **一次性** 的，发完即止。如果要实现持续通信，应该在 `WSASend` 完成后再次调用 `WSARecv`。
* **WSASend/WSARecv 都是异步的**，需要配套 IOCP 使用，使用重叠结构。
* **错误处理缺失**：比如 `WSARecv` 失败、`calloc` 失败等。
* **连接数量受限于 PER\_IO 结构数量与 IOCP 并发度**。

# WSARecv 会阻塞吗

----
----

不会阻塞。

在你给出的代码中：

```c
WSARecv(client, &pio->wbuf, 1, NULL, &flags, &pio->overlapped, NULL);
```

因为使用了\*\*`OVERLAPPED`结构体\*\*（`&pio->overlapped` 参数非 NULL），这是一次 **异步（overlapped）I/O** 调用，所以：

> ✅ **`WSARecv` 在主线程中是非阻塞的** —— 它会立即返回，I/O 操作在后台进行，完成后由 IOCP 通知工作线程。

---

### 🔍 更具体地解释：

* `WSARecv()` 有两种使用方式：

  1. **同步阻塞调用**：

     * 如果传入的 `OVERLAPPED` 参数为 `NULL`，那就是同步调用，会阻塞线程直到操作完成。
  2. **异步调用（你的情况）**：

     * 当传入了有效的 `OVERLAPPED` 指针，并且 socket 是以 `WSA_FLAG_OVERLAPPED` 创建的（默认是），那么 `WSARecv` 会 **立即返回**，I/O 在后台进行；
     * 完成后通过 **IOCP（`GetQueuedCompletionStatus`）** 来通知工作线程。

---

### 🚨 注意事项

* 异步调用下，`WSARecv()` 返回时可能：

  * **返回 0**，表示操作**同步完成**；
  * **返回 SOCKET\_ERROR 且 WSAGetLastError() == WSA\_IO\_PENDING**，表示操作**正在进行中** —— 这是正常的异步行为，不是错误。

所以通常判断方式是：

```c
int ret = WSARecv(...);
if (ret == SOCKET_ERROR) {
    int err = WSAGetLastError();
    if (err != WSA_IO_PENDING) {
        // 真正的错误，处理它
    }
    // 否则异步正在进行，正常
}
```

---

### ✅ 总结

你的调用方式中：

```c
WSARecv(client, ..., &pio->overlapped, NULL);
```

由于使用了 `OVERLAPPED`，**WSARecv 是非阻塞的**，即使在主线程中调用也不会阻塞线程，它只是发起了一个异步操作。I/O 完成后会由 IOCP 通知工作线程处理。

---

## ✅ 功能说明

* 支持多个客户端并发连接；
* 每个连接都支持多次发送和接收；
* 使用 IOCP 管理异步 I/O；
* 每个 `recv` 后 `echo`，再继续 `recv`；
* 正确管理内存与连接生命周期。

---

## ✅ 完整代码

```c
#define _WINSOCK_DEPRECATED_NO_WARNINGS
#include <winsock2.h>
#include <windows.h>
#include <stdio.h>

#pragma comment(lib, "Ws2_32.lib")

#define PORT 12345
#define WORKER_THREADS 4
#define BUFFER_SIZE 1024

typedef struct {
    OVERLAPPED overlapped;
    SOCKET sock;
    WSABUF wbuf;
    char buf[BUFFER_SIZE];
    enum { OP_RECV, OP_SEND } op_type;
} PER_IO;

// 工作线程函数
DWORD WINAPI Worker(LPVOID arg) {
    HANDLE iocp = (HANDLE)arg;
    DWORD bytes;
    ULONG_PTR key;
    OVERLAPPED *olp;

    while (GetQueuedCompletionStatus(iocp, &bytes, &key, &olp, INFINITE)) {
        PER_IO *pio = CONTAINING_RECORD(olp, PER_IO, overlapped);

        if (bytes == 0) {
            // 客户端关闭连接
            printf("Client disconnected\n");
            closesocket(pio->sock);
            free(pio);
            continue;
        }

        if (pio->op_type == OP_RECV) {
            // 接收到数据，准备回显
            pio->wbuf.len = bytes;
            pio->wbuf.buf = pio->buf;
            pio->op_type = OP_SEND;

            DWORD sent;
            int ret = WSASend(pio->sock, &pio->wbuf, 1, &sent, 0, &pio->overlapped, NULL);
            if (ret == SOCKET_ERROR && WSAGetLastError() != WSA_IO_PENDING) {
                fprintf(stderr, "WSASend failed: %d\n", WSAGetLastError());
                closesocket(pio->sock);
                free(pio);
            }
        } else if (pio->op_type == OP_SEND) {
            // 回显完成，继续接收
            ZeroMemory(&pio->overlapped, sizeof(OVERLAPPED));
            pio->wbuf.buf = pio->buf;
            pio->wbuf.len = BUFFER_SIZE;
            pio->op_type = OP_RECV;
            DWORD flags = 0;
            int ret = WSARecv(pio->sock, &pio->wbuf, 1, NULL, &flags, &pio->overlapped, NULL);
            if (ret == SOCKET_ERROR && WSAGetLastError() != WSA_IO_PENDING) {
                fprintf(stderr, "WSARecv failed: %d\n", WSAGetLastError());
                closesocket(pio->sock);
                free(pio);
            }
        }
    }

    return 0;
}

int main() {
    WSADATA wsa;
    WSAStartup(MAKEWORD(2, 2), &wsa);

    SOCKET listen_sock = socket(AF_INET, SOCK_STREAM, 0);
    if (listen_sock == INVALID_SOCKET) {
        fprintf(stderr, "socket failed: %d\n", WSAGetLastError());
        return 1;
    }

    struct sockaddr_in addr = {
        .sin_family = AF_INET,
        .sin_port = htons(PORT),
        .sin_addr.s_addr = INADDR_ANY
    };

    if (bind(listen_sock, (struct sockaddr*)&addr, sizeof(addr)) == SOCKET_ERROR) {
        fprintf(stderr, "bind failed: %d\n", WSAGetLastError());
        return 1;
    }

    listen(listen_sock, SOMAXCONN);
    printf("Echo server listening on port %d\n", PORT);

    HANDLE iocp = CreateIoCompletionPort(INVALID_HANDLE_VALUE, NULL, 0, 0);
    CreateIoCompletionPort((HANDLE)listen_sock, iocp, 0, 0);

    for (int i = 0; i < WORKER_THREADS; i++) {
        CreateThread(NULL, 0, Worker, iocp, 0, NULL);
    }

    while (1) {
        SOCKET client = accept(listen_sock, NULL, NULL);
        if (client == INVALID_SOCKET) {
            fprintf(stderr, "accept failed: %d\n", WSAGetLastError());
            continue;
        }

        printf("Client connected: %d\n", (int)client);

        CreateIoCompletionPort((HANDLE)client, iocp, 0, 0);

        PER_IO *pio = (PER_IO*)calloc(1, sizeof(PER_IO));
        pio->sock = client;
        pio->wbuf.buf = pio->buf;
        pio->wbuf.len = BUFFER_SIZE;
        pio->op_type = OP_RECV;

        DWORD flags = 0;
        int ret = WSARecv(client, &pio->wbuf, 1, NULL, &flags, &pio->overlapped, NULL);
        if (ret == SOCKET_ERROR && WSAGetLastError() != WSA_IO_PENDING) {
            fprintf(stderr, "WSARecv failed immediately: %d\n", WSAGetLastError());
            closesocket(client);
            free(pio);
        }
    }

    closesocket(listen_sock);
    WSACleanup();
    return 0;
}
```

这是一个非常关键的网络编程概念问题，**IOCP（I/O Completion Port）** 和 **epoll（就绪模型）** 的本质区别体现在它们分别代表两种 I/O 模型：

---

## 🔍 核心区别：**就绪模型** vs **完成模型**

| 模型       | 代表机制    | 代表平台    | 关键区别                    |
| -------- | ------- | ------- | ----------------------- |
| **就绪模型** | `epoll` | Linux   | 内核通知“某个fd已经准备好，可以做操作”   |
| **完成模型** | `IOCP`  | Windows | 内核通知“操作已经完成，数据已准备好/已发送” |

---

## 🧱 一、就绪模型（epoll）—— **I/O Ready**

### 🧠 思想：

> 内核只告诉你：**这个 fd 准备好了**，你自己再去执行 `read` 或 `write`。

### ✅ 特点：

* 调用 `epoll_wait` 后返回 "就绪" 的 fd；
* 应用程序再主动去 `read` 或 `write`；
* I/O 仍可能**阻塞**或返回 `EAGAIN`，所以通常配合非阻塞 I/O 使用；
* 多数是**边缘触发**或**水平触发**模式。

### 🧪 示例流程（Linux epoll）：

```
epoll_wait --> 你被告知 fd 可读
         |
         --> 你主动 read(fd, buf, size)
                   |
                   --> 真正把数据读进来
```

---

## 🧱 二、完成模型（IOCP）—— **I/O Completion**

### 🧠 思想：

> 你先告诉内核：“我要读/写”，然后内核 **后台完成工作**，最后通知你：“我做完了”。

### ✅ 特点：

* 应用程序**先投递异步请求**（如 `WSARecv`）；
* 内核后台执行该请求；
* 请求完成后通过 `GetQueuedCompletionStatus` 通知你；
* 完全由内核驱动完成，效率高。

### 🧪 示例流程（Windows IOCP）：

```
WSARecv(fd, buf, ...) --> 内核开始后台读取
                          |
       [稍后]
                          |
GetQueuedCompletionStatus --> 通知你读完了，有 N 字节数据
```

---

## 📌 举例类比（形象理解）

| 比喻    | epoll                        | IOCP                       |
| ----- | ---------------------------- | -------------------------- |
| 餐厅点菜  | 你去窗口排队，问服务员（fd）是否好了；好了就自己去端菜 | 你告诉服务员想吃什么，他忙完后端菜上桌告诉你“吃吧” |
| 图书馆取书 | 不停去书架看书有没有放上去（poll）          | 告诉图书馆员你要的书，她找到后叫你去拿（完成通知）  |
| 邮件系统  | 不停查邮箱（就绪）                    | 邮件来了通知你（完成）                |

---

## 📦 总结对比表

| 对比项     | epoll（就绪）      | IOCP（完成）                 |
| ------- | -------------- | ------------------------ |
| 模型      | 就绪通知           | 完成通知                     |
| 编程语言/平台 | Linux / Unix   | Windows                  |
| 通知内容    | 某个 fd 可读/可写    | 某个异步操作（read/write）已完成    |
| 操作风格    | 应用主动发起读取/写入    | 应用投递异步请求，内核异步完成并通知       |
| 性能      | 较高，需要配合非阻塞和线程池 | 极高，线程利用率高                |
| 编程复杂度   | 相对简单           | 相对复杂，需管理 OVERLAPPED、线程池等 |

---

## ✅ 补充说明

* IOCP 是操作系统级别的**事件驱动机制**，更接近硬件；
* epoll 依赖应用层逻辑主动执行操作，灵活但负担较大；
* Linux 并无真正的完成模型；要模拟类似 IOCP 的行为可用 **io\_uring**（Linux 新式接口）；
* Windows 上也有 `select` 和 `WSAPoll`，但性能远低于 IOCP。

---

## ✅ TL;DR

> IOCP 是“我告诉系统我要做什么，然后系统做完了告诉我”，这是**完成模型**；
>
> epoll 是“我问系统现在能不能做，然后我自己去做”，这是**就绪模型**。

# IOCP每个线程都在阻塞等待 IOCP 事件, 当事件来时, 不会出现数据竞争等线程安全问题吗?

非常好的问题！

### ✅ 简短回答：

**不会**出现数据竞争 —— **只要你每次投递的异步操作使用独立的上下文（如每个 `PER_IO`）结构体。**

这是 IOCP 的一个重要设计特性，它**天然避免了大多数线程安全问题**，**无需额外加锁**，从而实现高并发、高性能的网络服务。

---

## 🔍 详细解释

### 🧠 1. IOCP 本质是事件队列

* 每个工作线程通过 `GetQueuedCompletionStatus()` 阻塞等待；
* 内核会将**I/O 完成事件**放入 IOCP 队列中；
* 每个事件只能被**一个线程**取出处理！

👉 所以你不用担心 **多个线程同时处理同一个 I/O 完成事件**，因为事件是**单线程消费的**，从根源避免了线程冲突。

---

### 🧱 2. `PER_IO` 是每个 I/O 操作的“独立上下文”

你每次投递的异步操作：

```c
WSARecv(..., &pio->overlapped, NULL);
```

* 绑定了一个专属的 `PER_IO *pio`，其中包含缓冲区、OVERLAPPED、socket等；
* 等到事件完成时，系统通过 `OVERLAPPED *` 找回原始 `PER_IO`；
* 每个 I/O 操作都使用 **自己独立的 `PER_IO` 实例**，所以不同线程间处理的是不同的数据对象。

### ✅ 所以不会有共享冲突：

* 不同 socket 各用各的 `PER_IO`；
* 同一个 socket 的连续操作也用不同的 `PER_IO`；
* 处理完后及时释放结构，干干净净。

---

### 🔒 3. 哪些情况下需要考虑线程安全？

IOCP 本身线程安全，但**如果你的回调逻辑中访问了共享资源**（比如日志、数据库、缓存池等），就需要加锁。

**举例：**

```c
// 线程安全，不需要加锁
PER_IO *pio = CONTAINING_RECORD(olp, PER_IO, overlapped);
WSASend(pio->sock, &pio->wbuf, 1, ...);

// 线程不安全，访问共享全局 map
connection_map[pio->sock].last_active_time = GetTickCount(); // 需要加锁
```

---

### 🧪 补充：一个 I/O 操作的生命周期

```
主线程投递 WSARecv() --> 内核后台处理 --> 操作完成 --> IOCP 入队 --> 某线程取出 --> 处理完成（再投递下一次）
```

整个过程中：

* 主线程使用 `PER_IO1` 投递；
* 完成时，`PER_IO1` 交由一个工作线程处理；
* 主线程如果再次投递，应使用 `PER_IO2`；
* 不会有多个线程同时用 `PER_IO1`。

---

## ✅ 小结

| 问题           | IOCP 的处理机制              |
| ------------ | ----------------------- |
| 多线程会不会处理同一事件 | 不会，事件只能被一个线程从队列中取出      |
| 会不会访问同一数据结构  | 不会，每次投递都有独立的 `PER_IO`   |
| 会不会有锁竞争      | 不会，除非你显式访问了全局/共享资源      |
| 需要自己加锁吗      | **一般不需要**，除非你的逻辑中访问共享资源 |

---

## 🧠 一句话总结：

> IOCP 天生是为 **高并发、线程安全** 设计的完成端口模型，**事件分发天然互斥，不需要锁**，只要你管理好自己的异步上下文（`PER_IO`），就不会有数据竞争问题。
