## 分布式和负载均衡

#### 分布式

*分布式系统*: 将一个业务或系统拆分成多个相互协作的节点部署在不同服务器上, 通过网络协作完成整体业务功能.
- 水平拓展 scale-out: 通过增加节点提升性能
- 高可用HA: 某节点宕机, 其他节点可接管任务
- 资源共享: 不同节点分担不同业务
- 容错能力: 通过冗余和一致性算法保证稳定
常见场景:

##### [分布式存储 HDFS Ceph](https://zh.wikipedia.org/wiki/%E5%88%86%E5%B8%83%E5%BC%8F%E5%9D%97%E5%AD%98%E5%82%A8) 

##### [分布式计算 MapReduce,Spark](https://zh.wikipedia.org/wiki/%E5%88%86%E5%B8%83%E5%BC%8F%E8%AE%A1%E7%AE%97) 

##### [分布式数据库 MySQL分库分表,TiDB](https://zh.wikipedia.org/wiki/%E5%88%86%E5%B8%83%E5%BC%8F%E6%95%B0%E6%8D%AE%E5%BA%93)
**事务性质**

由于分布式数据库的结构特性，根据分布式系统的[CAP定理](https://zh.wikipedia.org/wiki/CAP%E5%AE%9A%E7%90%86 "CAP定理")，实现[ACID](https://zh.wikipedia.org/wiki/ACID "ACID")事务需要付出很大的成本来维护可用性，所以为了保障可用性而总结出一套弱化的事务特性：

- 基本可用（**B**asically **A**vailable）：系统能够基本运行、一直提供服务。
- 软状态（**S**oft-state）：系统不要求一直保持强一致状态。
- [最终一致性](https://zh.wikipedia.org/wiki/%E6%9C%80%E7%BB%88%E4%B8%80%E8%87%B4%E6%80%A7 "最终一致性")（**E**ventual consistency）：系统需要在某一时刻后达到一致性要求。

简称**BASE**，与ACID相对应（acid为“酸”的英文名称，base为“碱”的英文名称）


#### 负载均衡
- 将请求/任务合理分配到多个服务器节点, 提升吞吐量, 减少单节点压力, 提升可用性.
*负载均衡方式*:
1. DNS负载均衡: 通过DNS解析返回不同服务器IP. 实现简单, 但是DNS缓存更新慢,权重控制不灵活
2. 反向代理负载均衡: 请求先到代理服务器, 由代理转发给后端服务器. *后端服务器IP隐藏, 同时保证安全*. 常用Nginx, HAProxy
3. 硬件负载均衡: F5, Citrix专用设备, 高性能, 高消费
4. LVS内核级负载均衡: Linux Virtual Server,性能更高
5. 客户端负载均衡: 客户端根据算法选择服务端, RPC框架常见

*负载均衡算法*:
1. 轮询 Round Robin
2. 加权轮询 Weighed RR
3. 最少连接数 Leased Connections
4. 加权最少连接 Weighted LC
5. IP散列 IP Hash: 同一IP分配同一节点
6. 一致性哈希: *Consistent Hash*, 分布式缓存常用


|               | 正向代理（Forward Proxy） | 反向代理（Reverse Proxy）    |
| ------------- | ------------------- | ---------------------- |
| **客户端是否知道目标** | 否，客户端访问代理，代理再访问目标   | 是，客户端访问的就是代理（但不知道真实后端） |
| **作用对象**      | 服务端                 | 客户端                    |
| **常见用途**      | 翻墙、访问被屏蔽网站、缓存加速     | *负载均衡*、*安全防护*、*隐藏后端*结构 |
| **举例**        | Shadowsocks、Squid   | Nginx、HAProxy          |

##### Nginx 反向代理的负载均衡

Nginx 的 `upstream` 配置可实现负载均衡：

```nginx
upstream backend {
    server 192.168.1.101 weight=3;
    server 192.168.1.102;
    server 192.168.1.103 backup;
}

server {
    listen 80;
    location / {
        proxy_pass http://backend;
    }
}
```

- **weight**：权重，数值越大分配请求越多
- **backup**：备用服务器，主节点都挂了才会用
- 支持轮询、最少连接、IP 哈希等策略

#### LVS负载均衡 Linux Virtual Server
- LVS 在 Linux 内核中实现，性能高，适合高并发场景
*LVS 三种模式*:
1. *NAT 模式Network Address Translation*: 请求到达 LVS 后，修改目标 IP 为后端服务器 IP，响应再修改回客户端 IP. *简单，支持端口映射*. 但所有流量都经过 LVS，压力大
2. *DR 模式Direct Routing*:  LVS 只负责请求的转发，响应直接从 Real Server 返回客户端. *性能高，请求和响应分离*. 但需要 LVS 与 Real Server 在同一物理网络
3. *TUN 模式IP Tunneling*:  LVS 通过 IP 隧道将请求发给 Real Server，响应直接回客户端. *支持跨网络*. 需要服务器支持 IP 隧道协议


## 集群 Cluster
即计算机集群, 一组松散或紧密联系在一起的工作的计算机. 这些计算机协同工作, 在许多方面可视为单个系统, 为每个节点设置设置相同的任务, 由软件控制和调度.  可以理解为：**多台机器 -→ 像一台机器一样工作**
- 部署集群通常是为了提高单台计算机的性能和可用性，而集群也通常比速度或可用性相当的单台计算机的成本效益要高

| 对比项      | 集群                                   | 分布式                      |
| -------- | ------------------------------------ | ------------------------ |
| **核心目的** | 提升性能和可用性                             | 拆分业务、分摊计算与存储             |
| **节点特征** | 节点之间通常是**相同/相似功能**，互为备份或共同处理         | 节点可能功能完全不同，各司其职          |
| **依赖关系** | 多台机器协作处理**同一份任务/数据**                 | 多台机器处理**不同部分任务/数据**      |
| **举例**   | Redis 集群（多个节点共同存储一份数据）<br>MySQL 主从集群 | 微服务架构<br>HDFS（存储分布在不同节点） |

- **分布式**：把任务拆开，不同节点干不同的活
- **集群**：大家干同一类活，一起顶一个更大的锅

**1. 你了解单机架构与分布式架构的区别吗？**

  * 单机架构指所有功能运行在一台服务器上，开发部署简单，但扩展性和容灾能力差, 当服务器宕机时, 就不能提供服务. 而分布式架构是将业务拆分到多台机器协同工作，具备高可用、可扩展性和容灾能力, 即使部分机器宕机, 仍有一部分能够提供服务. 

**2. 什么是服务器架构中的动静分离？**
- 将静态资源（图片、CSS、JS、视频等）从动态请求中剥离，交由 CDN 或文件服务器提供，减少应用服务器压力，提高加载速度


**4. 什么是集群？它和分布式有什么区别？** 
  * 集群：多台相同功能的服务器协同工作，外部看起来像一个整体（如 Nginx 集群）。
  * 分布式：不同节点可能有不同功能（如订单系统、库存系统），强调业务拆分。
  * 区别：集群是功能冗余，分布式是功能拆分，二者可以结合使用。

**5. 为什么要引入缓存系统（如 Redis）？**

  * 减少数据库压力，降低响应延迟。
  * Redis 基于内存存储，读写速度远高于磁盘数据库。
  * 常用数据结构：字符串、哈希、列表、集合、有序集合。
  * 常见问题：缓存穿透、击穿、雪崩（解决方法：布隆过滤器、互斥锁、过期时间随机化等）。

6. 什么是消息队列（MQ）？它是如何做到对流量进行削峰填谷的？

* **答案**：一种异步通信机制，通过“生产者-消费者”模型将任务存储在队列中，实现**削峰填谷**（应对流量波动）、**解耦**（降低模块依赖）和**异步处理**（提高响应速度）. 如何削峰填谷: 电商下单时，扣库存为核心操作，发送通知为辅助操作，将辅助操作丢入消息队列, 等待流量低谷期可异步处理

## **二、中级难度（系统设计与性能优化）**

> 考察候选人能否结合场景给出架构优化方案

**7. 在分布式系统中如何做请求分发？**
  * 七层（HTTP）负载均衡：Nginx、HAProxy（基于应用层信息分发）。
  * 四层（TCP/UDP）负载均衡：LVS、F5（基于 IP + 端口转发）。
  * 策略：轮询、加权轮询、最少连接、一致性哈希等。

**8. 多节点缓存数据会带来什么问题？如何解决？**
  * 问题：缓存数据重复，占用内存多，更新一致性难保证。
  * 解决：使用分布式缓存（Redis Cluster），通过一致性哈希分片，让数据只存一份。

**9. 削峰填谷为什么不能“一刀切”？**

  * 核心业务必须同步执行保证一致性（下单、扣库存），辅助业务（发邮件、记录日志）可以延迟处理。
  * 一刀切会导致核心业务延迟执行，影响用户体验。

**10. 什么是数据库读写分离？如何保证一致性？**

* **答案**：

  * 将写操作发送到主库，读操作发送到从库，缓解主库压力。
  * 一致性问题：主从延迟可能导致读到旧数据，解决方法：强制从主库读、延迟双写检测、读写分离策略优化。

**11. 什么是分库分表？**

* **答案**：

  * 垂直分库：按业务模块拆分（订单库、用户库）。
  * 水平分表：按数据范围拆分（订单表按时间分片）。
  * 作用：减小单库/单表数据量，提高并发能力。
  * 难点：跨库查询、分布式事务。

**12. 当 Nginx 扛不住流量时还有哪些方案？**

  * 在 Nginx 前加 LVS 或硬件负载均衡器（如 F5、A10）。
  * 使用 DNS 轮询、CDN 做流量分发。
  * 拆分业务、增加缓存层、使用异步处理等。

## **三、高级难度（架构演进与服务治理）**

> 考察候选人对大型系统架构的全局掌控能力

**13. 单体拆分为多个子系统后会遇到什么问题？**

  * 服务间强耦合、调用链长、固定 IP 带来灵活性差。
  * 一个子系统宕机可能导致全局瘫痪（单点故障）。
  * 解决：服务注册中心（Eureka、Consul、Nacos），动态发现服务，熔断、限流、降级等保护措施。

**14. 什么是 SOA 架构？ESB 在其中的作用是什么？为什么 ESB 场景越来越少？**

* **答案**：

  * SOA（面向服务架构）：将业务封装成可复用、可组合的服务。
  * ESB（企业服务总线）：统一管理服务通信的中间件，类似“系统胶水”。
  * 场景减少原因：ESB 引入单点瓶颈，部署复杂，微服务和轻量化 API 网关（如 Spring Cloud Gateway、Kong）更灵活。

**15. LVS 是如何提升接入层性能的？与 Nginx 有何区别？**

* **答案**：

  * LVS：工作在四层（IP+端口转发），转发速度快，支持上百万并发连接，适合 TCP/UDP 流量。
  * Nginx：工作在七层（HTTP），可做请求内容判断，支持灵活路由。
  * 组合：LVS 在前负责大流量接入，Nginx 在后负责内容分发和缓存。


**17. 微服务和分布式有什么关系？**

* **答案**：

  * 微服务是一种分布式架构实现方式，将业务按功能拆分成小而独立的服务，每个服务独立部署、运行。
  * 分布式是更大范围的概念，微服务是其中一种实现模式。

- 将静态资源（图片、CSS、JS、视频等）从动态请求中剥离，交由 CDN 或文件服务器提供，减少应用服务器压力，提高加载速度

##### 3. 什么是集群？它和分布式有什么区别？   
  * 集群是指多台相同功能的服务器协同工作，外部看起来像一个整体（如 Nginx 集群）. 而分布式是不同节点可能有不同功能（如订单系统、库存系统），强调业务拆分. 同时集群是功能冗余，分布式是功能拆分，二者可以结合使用

##### 4. 为什么要引入缓存系统（如 Redis）？  
- 当服务器流量大, 有*热门数据*增删次数少, 读取次数多的时候. 就可以将数据放到缓存中. 主要目的减少数据库压力，降低响应延迟. Redis 基于内存存储，读写速度远高于磁盘数据库. 

##### 5. 什么是消息队列（MQ）？它是如何做到对流量进行削峰填谷的？
* 消息队列是一种异步通信机制，通过“生产者-消费者”模型将任务存储在队列中，实现  削峰填谷  （应对流量波动）、  解耦  （降低模块依赖）和  异步处理  （提高响应速度）. 如何削峰填谷: 将业务分解成核心功能和辅助功能, 例如电商下单时，扣库存为核心操作，发送通知为辅助操作，将辅助操作丢入消息队列, 等待流量低谷期可异步处理

  ##### 6. 什么是数据库读写分离？如何保证一致性？  

  * 将写操作发送到主库，读操作发送到从库，缓解主库压力。
  * 一致性问题：主从延迟可能导致读到旧数据，解决方法：强制从主库读、延迟双写检测、读写分离策略优化

  ##### 7. 什么是分库分表？  

  * 垂直分库：按业务模块拆分（订单库、用户库）
  * 水平分表：按数据范围拆分（订单表按时间分片）
  * 作用：减小单库/单表数据量，提高并发能力
  * 难点：跨库查询、分布式事务

  ##### 8. 当 Nginx 扛不住流量时还有哪些方案？  

  * 在 Nginx 前加 LVS 或硬件负载均衡器（如 F5、A10）
  * 使用 DNS 轮询、CDN 做流量分发
  * 拆分业务、增加缓存层、使用异步处理等

  ##### 9. 单体拆分为多个子系统后会遇到什么问题？  

  * 服务间强耦合、调用链长、固定 IP 带来灵活性差
  * 一个子系统宕机可能导致全局瘫痪（单点故障）
  * 解决：服务注册中心（Eureka、Consul、Nacos），动态发现服务，熔断、限流、降级等保护措施。

  ##### 10. LVS 是如何提升接入层性能的？与 Nginx 有何区别？  

  * LVS：工作在四层（IP+端口转发），转发速度快，支持上百万并发连接，适合 TCP/UDP 流量。
  * Nginx：工作在七层（HTTP），可做请求内容判断，支持灵活路由。
  * 组合：LVS 在前负责大流量接入，Nginx 在后负责内容分发和缓存。


  ##### 11. 微服务和分布式有什么关系？  

  * 微服务是一种分布式架构实现方式，将业务按功能拆分成小而独立的服务，每个服务独立部署、运行。
  * 分布式是更大范围的概念，微服务是其中一种实现模式。
