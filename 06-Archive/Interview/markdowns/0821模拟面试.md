# 12.为什么用OPUS?
- 12.1 了解其他的音频播放吗?

这个问题非常典型，面试官主要是想考察：

1. 你对 **音频编解码器的基本认知**；
2. 你为什么会做 **技术选型**（从 Speex 换到 Opus 的原因）；
3. 你有没有了解其他常见的音频方案。

---

### 回答思路

#### 1. 为什么实时语音通话使用 Opus

* **开源 & 标准化**：Opus 是 IETF 标准化的音频编解码器，得到广泛支持（WebRTC、VoIP、Discord 等）。
* **音质与压缩率**：在低比特率下（<20kbps）比 Speex、AMR-WB 更清晰；在高比特率时可以媲美 MP3/AAC。
* **自适应能力强**：支持 **6kbps – 510kbps** 宽范围，比特率可动态调整，适合网络状况变化的实时场景。
* **低延迟**：可以做到 < 20ms 编解码延迟，非常适合语音通话、在线游戏语音。
* **兼容语音 & 音乐**：不像 Speex 只针对语音，Opus 同时能处理语音和高保真音乐。

所以：**实时语音用 Opus，是因为它在延迟、音质、网络适应性上全面优于 Speex。**

---

#### 2. 从 Speex 过渡到 Opus 的原因

* Speex 主要是针对语音优化的老方案，现在已经进入维护模式；
* Opus 本质上是 Vorbis（音乐）和 SILK（语音）的结合体，既能做语音，又能做音乐播放，应用面更广；
* 社区、浏览器、WebRTC 都推荐和默认支持 Opus。

所以选择 Opus 是更长期、更现代的方案。

---

#### 3. 了解的其他音频编解码

* **G.711**：最早的电话语音标准，几乎无压缩，延迟低但带宽大。
* **G.729 / AMR-NB / AMR-WB**：移动通信常用的语音编码，适合低带宽语音。
* **AAC（Advanced Audio Coding）**：流媒体、视频平台常用，适合音乐和高质量音频，但延迟比 Opus 高。
* **MP3**：经典有损压缩格式，音乐播放为主，实时语音不适合。
* **FLAC**：无损压缩，适合存档/音乐，不适合实时。

---

### 示例回答（面试时可以说的版本）

> 实时语音通话我们选择了 Opus。主要原因是它是 IETF 标准化的开源编解码器，在低比特率下音质优于 Speex，并且能在网络条件不稳定时自适应调整比特率，保证实时性和清晰度。同时，它延迟非常低，可以做到 20ms 以内，非常适合语音通话。另外，Opus 不仅能处理语音，也能处理音乐，比 Speex 应用范围更广。我之前也用过 Speex，但它现在基本处于维护状态，社区和 WebRTC 官方都推荐使用 Opus，所以我们切换了。
> 除了 Opus，我也了解一些常见编解码器，比如 G.711、G.729、AMR 系列主要用于传统语音通信；AAC、MP3 更常用于音乐或流媒体；FLAC 用于无损存储。这些各有优劣，但在实时语音场景下，Opus 是目前最优的选择。

# 介绍一下封装继承多态?


这个问题属于 **C++ OOP 三大特性** 的经典考点。回答时最好 **结构清晰 + 举例**，不要只背概念。

---

## 1. 封装（Encapsulation）

* **定义**：把数据和操作数据的方法捆绑在一起，形成“对象”，并通过访问控制隐藏内部实现。
* **意义**：保证内部细节对外透明，外部只需使用接口。
* **例子**：

  ```cpp
  class Account {
  private:
      double balance;   // 数据隐藏
  public:
      void deposit(double amount) { balance += amount; }
      double getBalance() const { return balance; }
  };
  ```

  * 外部代码不能直接修改 `balance`，必须通过 `deposit()` 或 `getBalance()` 访问。

---

## 2. 继承（Inheritance）

* **定义**：子类在继承父类的基础上，复用父类的属性和方法，同时可以扩展或修改。
* **意义**：提高代码复用性，支持层次化建模。
* **例子**：

  ```cpp
  class Animal {
  public:
      void eat() { cout << "Eating\n"; }
  };

  class Dog : public Animal {
  public:
      void bark() { cout << "Barking\n"; }
  };
  ```

  * `Dog` 继承了 `Animal` 的 `eat()`，还扩展了 `bark()`。

---

## 3. 多态（Polymorphism）

* **定义**：同一接口，不同实现；即“一个接口，多种形态”。
* **意义**：提高扩展性和灵活性，使得父类指针/引用可以调用子类方法。
* **例子**：

  ```cpp
  class Animal {
  public:
      virtual void speak() { cout << "Some sound\n"; }
  };

  class Dog : public Animal {
  public:
      void speak() override { cout << "Woof\n"; }
  };

  class Cat : public Animal {
  public:
      void speak() override { cout << "Meow\n"; }
  };

  // 使用
  Animal* a = new Dog();
  a->speak();  // 输出 "Woof"
  a = new Cat();
  a->speak();  // 输出 "Meow"
  ```

  * `speak()` 是统一接口，但不同子类有不同实现。

---

## 4. 面试时的简洁回答

> 封装是把数据和方法包装在类里，并通过访问控制隐藏细节，保证对象的独立性；
> 继承是子类复用父类代码，并能扩展或修改功能，提高代码复用性；
> 多态是相同接口在不同对象上的不同实现，常用虚函数实现，可以让父类指针调用子类方法，提高扩展性。

---

# 多态实现原理?
静态多态: 操作符重载, 模板重载
这个追问就进入了 C++ 底层，面试官要看你是不是只会“会用”，还是对 **实现机制** 也有理解。回答时要点清晰，既要讲原理，又要能说到工程意义。

---

## 多态实现原理（C++）

### 1. 静态多态（编译期）

* **实现方式**：函数重载、模板。
* **原理**：在编译时通过 **名字修饰（name mangling）** 和模板实例化，编译器就能确定调用哪个函数。
* **特点**：编译期决定，效率高，没有额外开销。

### 2. 动态多态（运行期） → 面试重点

* **实现方式**：虚函数（`virtual`）。
* **关键机制**：**虚函数表（vtable） + 虚函数指针（vptr）**。

  * 当一个类声明了虚函数时，编译器会为该类生成一张 **虚函数表**（存放函数地址的数组）。
  * 每个对象会有一个隐藏的 **vptr 指针**，指向该对象所属类的虚函数表。
  * 当调用虚函数时，实际运行的是 `vptr` 查表得到的函数地址，因此可以根据对象的实际类型来调用对应实现。

---

### 3. 举例说明

```cpp
class Animal {
public:
    virtual void speak() { cout << "Some sound\n"; }
};

class Dog : public Animal {
public:
    void speak() override { cout << "Woof\n"; }
};
```

* `Animal` 有一个 `speak` 的虚函数表，存放 `Animal::speak` 地址。
* `Dog` 也有一个虚函数表，但 `speak` 的条目被替换为 `Dog::speak` 地址。
* 当我们写：

  ```cpp
  Animal* a = new Dog();
  a->speak();
  ```

  实际执行过程是：

  * 通过 `a` 的 `vptr` 找到 `Dog` 的 vtable；
  * 从表里取出 `Dog::speak` 地址；
  * 跳转执行 `Dog::speak`。

---

### 4. 运行开销

* **空间开销**：每个类有一张虚函数表（全局共享），每个对象多一个 `vptr` 指针。
* **时间开销**：每次虚函数调用，多一次“间接寻址”（查 vtable）。
* 相比普通函数调用稍慢，但通常可接受。

---

## 面试时的示范回答

> C++ 的多态分为编译期和运行期。编译期多态通过函数重载和模板实现，编译时就确定了调用关系。
> 运行期多态是通过虚函数实现的，编译器会为含有虚函数的类生成虚函数表，每个对象内部有一个虚表指针 `vptr`，指向对应类的虚函数表。当通过父类指针或引用调用虚函数时，实际是通过 `vptr` 查表得到真正的函数地址，从而根据对象的实际类型来执行不同的方法。
> 所以多态的本质是 **通过虚表实现的间接调用**。

# 介绍一下lamuda表达式
- 分5块 还有个mutable

- lamuda表达式何时会失效
这个问题挺有意思，面试官问“lambda 表达式何时会失效”，其实是考察你对 **C++ lambda 的捕获和生命周期** 有没有深入理解。

---

## 1. 可能的含义

C++ 里的 **lambda 表达式失效**，主要体现在 **捕获的变量生命周期问题**。

### （1）按引用捕获（`&`）的失效

```cpp
auto f = [&]() { return x; };
```

* 如果 `x` 是一个局部变量，而 lambda 在函数外被调用，那么 `x` 已经销毁，lambda 捕获的引用悬空 → **失效（未定义行为）**。

### （2）按值捕获（`=`）但变量已销毁

```cpp
auto f = [=]() { return ptr->data; };
```

* 如果捕获的是指针（按值），但指向的对象被销毁，lambda 内部依旧可能访问野指针。

### （3）返回 lambda，但捕获的对象生命周期不对

```cpp
auto make_lambda() {
    int a = 42;
    return [&]() { return a; };  // 错误：返回的 lambda 持有对局部变量 a 的引用
}
```

* 这种情况，返回的 lambda 会失效，因为 `a` 离开作用域就没了。

### （4）mutable lambda 的拷贝问题

```cpp
int x = 0;
auto f = [=]() mutable { return ++x; }; 
```

* 每次拷贝 `f` 时，它的捕获副本独立，如果你以为能“共享状态”，就会“逻辑上失效”。

### （5）线程问题

* 如果 lambda 捕获了局部变量的引用，然后在线程中异步执行，原函数早就返回了 → 捕获的引用无效。

---

## 2. 面试时可以这样答

> Lambda 表达式本身不会失效，但它捕获的变量可能会导致失效。最常见的情况是：
>
> 1. **按引用捕获局部变量**，但在 lambda 被调用时变量已销毁，引用悬空。
> 2. **按值捕获指针**，指向的对象被释放，lambda 内部访问悬空指针。
> 3. **返回 lambda** 时捕获了局部变量引用，会导致返回后的 lambda 无效。
> 4. 在多线程场景中，lambda 捕获的引用若超出作用域，也可能失效。
>
> 所以，本质上 lambda 的有效性取决于 **捕获变量的生命周期**。

---

# 介绍一下右值引用, 对右值引用理解.
- 对右值取别名
##### - 取别名作用


移动赋值,构造
完美转发(万能引用)

好的，这个问题也是 C++ 面试高频题。回答的时候要从 **概念 → 作用 → 原理/使用场景** 三步走，既清晰又能显得你理解深入。

---

## 1. 概念

右值引用（`T&&`）是 C++11 引入的新特性，用来绑定到 **右值（临时对象、字面量等不能取地址的值）**。

* 普通左值引用（`T&`）只能绑定左值。
* 右值引用（`T&&`）可以直接绑定右值。

例子：

```cpp
int x = 10;
int& lref = x;    // 左值引用
int&& rref = 5;   // 右值引用，绑定到字面量 5
```

---

## 2. 作用

右值引用的引入主要是为了解决 **性能优化** 和 **资源管理** 问题。

### （1）支持移动语义

以前拷贝大对象（如 `std::vector`）时，总要深拷贝，效率低。
右值引用可以用来“窃取”临时对象的资源，避免额外拷贝。

```cpp
std::vector<int> v1 = {1,2,3,4};
std::vector<int> v2 = std::move(v1); // v2 直接接管 v1 的资源
```

### （2）完美转发

在模板编程中，右值引用配合 **`std::forward`**，可以保持参数的值类别（左值/右值），避免不必要的拷贝。

```cpp
template<typename T>
void wrapper(T&& arg) {
    func(std::forward<T>(arg)); // 完美转发
}
```

---

## 3. 底层理解

* 左值引用（`T&`） → 只能绑定左值。
* 右值引用（`T&&`） → 只能绑定右值（临时对象）。
* **引用折叠规则**：在模板中 `T&&` 可能变成左值引用或右值引用：

  * 如果传入左值 → 推导为 `T&`
  * 如果传入右值 → 推导为 `T&&`

这就是 **万能引用/转发引用** 的原理。

---

## 4. 面试时的回答模板

你可以这样说：

> 右值引用是 C++11 引入的新型引用，语法是 `T&&`，它主要用来绑定临时对象（右值）。
> 它的最大意义在于支持 **移动语义** 和 **完美转发**：
>
> * 移动语义能避免不必要的深拷贝，提升性能，比如 `std::vector` 的移动构造。
> * 在模板中通过右值引用和 `std::forward`，可以保持参数的左值/右值属性，实现高效的泛型编程。
>
> 从实现原理看，右值引用实际上就是一种能延长临时对象生命周期、并允许“窃取”资源的引用，它和左值引用一起完善了 C++ 的值类别系统。

---

# `auto` `decltype` 介绍一下

好问题 👍 这俩都是 **类型推导相关的关键字**，但作用和规则完全不同，面试官爱拿来考“细节理解”。我帮你分成四块讲：

---

## 1. `auto`

`auto` 是 **自动类型推导**，根据初始化表达式推导变量的类型。

### 例子：

```cpp
int x = 10;
auto a = x;        // a -> int
auto& b = x;       // b -> int&
auto c = &x;       // c -> int*
auto d = {1,2,3};  // d -> std::initializer_list<int>
```

### 规则：

* `auto` 会 **丢弃顶层引用**，但会保留底层引用/指针。
* `auto` 会忽略 `const` 顶层属性，但保留底层。

例子：

```cpp
const int n = 42;
auto x = n;      // x -> int  (顶层const被忽略)
const auto y = n; // y -> const int
auto& z = n;     // z -> const int&   (保留底层const)
```

---

## 2. `decltype`

`decltype` 用于 **获取表达式的类型**，不会实际求值。
语法：

```cpp
decltype(expr) var;
```

### 推导规则（C++11标准的核心四条）：

1. 如果 `expr` 是一个 **没有括号的标识符表达式**（变量名等） → 推导为该变量的声明类型（含 const、引用）。

   ```cpp
   int a = 0;
   decltype(a) x;   // int
   const int b = 0;
   decltype(b) y;   // const int
   ```

2. 如果 `expr` 是个 **函数调用** → 推导为函数返回值类型。

   ```cpp
   double foo();
   decltype(foo()) val;  // double
   ```

3. 如果 `expr` 是一个 **左值表达式** → 推导为 `T&`。

   ```cpp
   int a = 0;
   decltype((a)) ref = a; // int&   注意双括号！
   ```

4. 如果 `expr` 是一个 **右值表达式** → 推导为 `T`。

   ```cpp
   decltype(1+2) sum = 0; // int
   ```

---

## 3. 区别

| 特性         | `auto`                   | `decltype`                                |
| ---------- | ------------------------ | ----------------------------------------- |
| 用途         | 自动推导变量类型（需初始化）           | 提取表达式的类型（不计算表达式）                          |
| 是否求值       | 需要初始化，表达式会执行             | 仅获取类型，不执行表达式                              |
| const/引用保留 | 丢弃顶层 const 和引用           | 完全保留声明类型                                  |
| 灵活性        | 简单，常用于局部变量推导             | 更精确，可结合 `decltype(expr)` 定义复杂类型           |
| 典型应用       | `auto it = vec.begin();` | `decltype(vec.begin()) it = vec.begin();` |

---

## 4. 结合使用

在泛型编程中常见：

```cpp
template <typename T, typename U>
auto add(T t, U u) -> decltype(t+u) {
    return t+u;
}
```

这里 `auto` 表示函数返回值占位，`decltype` 确定真实类型。

C++14 后甚至可以直接写：

```cpp
template <typename T, typename U>
auto add(T t, U u) {
    return t+u;  // 编译器自动推导返回类型
}
```

---

✅ **面试回答模板**：

> `auto` 用于变量声明时的类型自动推导，规则是会丢弃顶层 const 和引用，常用于简化代码。
> `decltype` 则是获取表达式的精确类型，不会执行表达式，能完整保留 const 和引用修饰。
> 区别在于：`auto` 需要初始化表达式，而 `decltype` 只做类型分析，常用于模板和泛型编程里定义函数返回值。
> 二者经常结合使用，比如 `auto f(T t, U u) -> decltype(t+u)`。

# 四种类型转换

- / 为什么C++不沿用C中的强制类型转换, 而提出这四种类型转换? 
- C++ 在设计时强调类型安全, 但C中类型转换可谓无所不能, 若继续沿用, 会破坏C++的类型系统, 同时留下安全隐患
- 此外, 四种类型转换有不同使用场景和功能, 相较于C的强制类型转换更强大

##### `{cpp}static_cast<"类型">("待转换量")` 静态转换
- 编译时确定相关内容的转换. 用于基本类型转换, 以及类之间的安全转换,例如子类对象地址转换为父类指针
- 而不相关类型不能转换, 例如`int*`与`int`

##### `{cpp}dynamic_cast<"类型">("待转换量")`
- 只适用于有继承关系的两个类
- 继承向上转换效果等同于`static_cast`, 向下转换会检验即是安全的. 
- 若父类指针指向子类对象, 而转出类型就是该子类类型, 可以正常转换
- 若父类指针指向的不是转出类型的子类对象, 返回结果为空
- 同时, 向下转换, 父类必须包含虚函数, `static_cast`无这个要求

> [!example] `static_cast` `与dynamic_cast` 区别总结
> - `static_cast` 支持相关数据类型转化 `dynamic_cast`不支持
> - 对于继承关系中的转换,`static_cast`可以向上和向下转换, dynamic_cast可以交叉转换
> - `dynamic_cast`向上转换与`static_cast`一致, 向下转换, 父类要有虚函数, 并且存在检验机制.

##### `{cpp}const_cast<"类型">("待转换量")`
- 去常转换
- `const int -> int`
- `volatile int -> int`
- volatile : 防止修饰变量编译优化, 避免修饰变量缓存和内存不一致(每次到其地址读取,先写后读)
##### `{cpp}reinterpret_cast<"类型">("待转换量")`
- 重解释类型转换
- C++ 强制类型转换符
- 相当于`(type)` ~~无所不能~~ 
- 有安全隐患

# QT事件循环机制
- 子线程能否控制UI组件吗, 为什么
- : 多线程操作出现并发, 互斥加锁会影响主事件循环
这个问题考察的是你对 **Qt底层运行机制** 的理解。面试官想确认你是否知道 Qt 程序为什么“能响应用户点击、窗口刷新、网络事件”，以及它和一般的循环 `while(true)` 有什么区别。

---

## **回答思路**

### 1. Qt 事件循环的本质

* Qt 应用程序启动时，调用 `QApplication::exec()`（或 `QCoreApplication::exec()`）。
* 这会进入 **事件循环（event loop）**，本质是一个消息循环（message loop），不断：

  1. 从操作系统的事件队列里取出事件（如鼠标、键盘、定时器、socket I/O）。
  2. 将事件封装成 `QEvent`。
  3. 投递给目标 `QObject`，调用 `event()` 或更具体的 `mousePressEvent()`、`keyPressEvent()` 等虚函数。

类似 Windows 的 `GetMessage/DispatchMessage` 或 Linux 的 `select/poll/epoll` 驱动的循环机制。

---

### 2. 信号与槽与事件循环的关系

* **信号和槽的回调，实际上是事件循环调度的结果**。
  当你 `emit signal` 时，Qt 会生成一个事件，交给事件循环去分发。
  如果是 **跨线程信号**，事件循环会把事件放入目标线程的消息队列，然后在目标线程的事件循环里处理。

---

### 3. 特点

* **单线程 UI 原则**：Qt 的 GUI 必须运行在主线程（事件循环所在），否则会出错。
* **异步处理**：很多 Qt 功能（定时器 `QTimer`、网络 `QTcpSocket`、`QNetworkAccessManager`）都依赖事件循环异步调度。
* **可嵌套**：可以在对话框里再开启一个局部事件循环（比如 `QDialog::exec()` 会启动自己的循环）。

---

### 4. 常见问题/面试加分点

* 如果一个槽函数里执行了耗时操作（例如死循环或阻塞 I/O），就会卡死事件循环 → 界面假死。
  解决方法：放到子线程（`QThread`）或使用异步操作。
* `QCoreApplication::processEvents()` 可以手动让事件循环处理积压事件（比如在长耗时计算时保持 UI 响应）。

---

## **简洁示例回答**

> Qt 的事件循环是通过 `QApplication::exec()` 启动的，本质上是一个消息循环，它不断从操作系统取消息，封装为 `QEvent` 并分发到相应对象。信号与槽的调用也依赖事件循环来调度。Qt 的 UI 必须运行在主线程，事件循环保证了界面的响应和异步机制。如果事件循环被阻塞，界面就会卡死，所以耗时操作一般放在子线程里处理。

# 介绍一下C语言面向过程编程, C++面向对象编程, 说说区别

> C 语言是一种典型的面向过程编程语言，核心是通过函数把问题拆解成步骤，数据和操作是分开的。比如银行账户的例子，会用结构体保存数据，用函数去修改它
> 
> C++ 则是面向对象的，它把数据和操作封装在类里，通过对象进行建模，并且支持继承和多态，适合处理复杂系统和扩展需求
> 
> 简单来说：C 更关注“怎么做”，C++ 更关注“对象是谁、能做什么”


# 介绍一下封装继承多态?

`Animal Dog Cat Speak`

> 封装是把数据和方法包装在类里，并通过访问控制隐藏细节，保证对象的独立性；  
> 继承是子类复用父类代码，并能扩展或修改功能，提高代码复用性；  
> 多态是相同接口在不同对象上的不同实现，常用虚函数实现，可以让父类指针调用子类方法，提高扩展性。

# 多态实现原理?

> C++ 的多态分为编译期和运行期。
> *编译期多态*通过函数/函数重载和模板实现，编译时就确定了调用关系。
> *运行期多态*是通过虚函数实现的，编译器会为含有虚函数的类生成虚函数表，每个对象内部有一个虚表指针 `vptr`，指向对应类的虚函数表。当通过父类指针或引用调用虚函数时，实际是通过 `vptr` 查表得到真正的函数地址，从而根据对象的实际类型来执行不同的方法。
> 
> 所以多态的本质是 **通过虚表实现的间接调用**

# lamuda表达式何时会失效
Lambda 表达式本身不会失效，但它捕获的变量可能会导致失效。最常见的情况是：

1. **按引用捕获局部变量**，但在 lambda 被调用时变量已销毁，引用悬空
2. **按值捕获指针**，指向的对象被释放，lambda 内部访问悬空指针
3. **返回 lambda** 时捕获了局部变量引用，会导致返回后的 lambda 无效
4. 在多线程场景中，lambda 捕获的引用若超出作用域，也可能失效

所以，本质上 lambda 的有效性取决于 **捕获变量的生命周期**。



# 介绍一下右值引用, 对右值引用理解.

右值引用是 C++11 引入的新型引用，语法是 `T&&`，它主要用来绑定临时对象（右值）。  
它的最大意义在于支持 **移动语义** 和 **完美转发**：

- 移动语义能避免不必要的深拷贝，提升性能，比如 `std::vector` 的移动构造
- 在模板中通过右值引用和 `std::forward`，可以保持参数的左值/右值属性，实现高效的泛型编程

从实现原理看，右值引用实际上就是一种能延长临时对象生命周期、并允许“窃取”资源的引用，它和左值引用一起完善了 C++ 的值类别系统。



# `auto` `decltype` 介绍一下

> `auto` 用于变量声明时的类型自动推导，规则是会丢弃顶层 const 和引用，常用于简化代码。  
> `decltype` 则是获取表达式的精确类型，不会执行表达式，能完整保留 const 和引用修饰。  
> 	1. **没有括号的标识符表达式**（变量名等）-> 推导为该变量的声明类型
> 	2. **函数调用**-> 推导为函数返回值类型
> 	3. **左值表达式**-> 推导为 `T&`
> 	4. `expr` 是一个 **右值表达式**-> 推导为 `T`
> 区别在于：`auto` 需要初始化表达式，而 `decltype` 只做类型分析，常用于模板和泛型编程里定义函数返回值。  
> 二者经常结合使用，比如 `{cpp}auto f(T t, U u) -> decltype(t+u)`

# `{cpp}constexpr`和`{c}const`区别

 `[!!sprout:constexpr]` : 修饰真正的常量, 编译期会计算出来, 整个运行过程不会被改变, 可修饰函数, 返回值会尽可能在编译期被计算当作一个常量, 若不能计算出来, 就是一个普通函数. 可赋值`const`常量

> [!example] `{cpp}constexpr` 与`{c}const` 的区别
> *const* :
>    - 主要用于指明变量的值在初始化后就不应该被改变
>    - `const` 变量的值可以在运行时确定,也可以在编译时确定
>    - `const` 变量的初始化可以是任意复杂的表达式<br>
>  
> *constexpr* : 是 C++11 新引入的关键字, 用于声明表达式(函数)为编译时常量, 保证了变量或函数在编译时就已经确定了值,使得它们可以用在需要编译时常量表达式的场景中, 例如数组的大小
>    - `constexpr` 变量或函数必须在编译时就能确定其值或结果
>    - `constexpr` 可以用于函数和构造函数,可以创建在编译时就能计算出结果的函数和对象
>    - `constexpr` 变量或函数的初始化表达式必须足够简单,以便编译器能够在编译时求值

# QT第五个参数


> [!abstract] 信号槽第五个参数
> - `Qt::AutoConnection` : *默认使用* 若sender与reciver在同一线程, 使用`Qt::DirectConnection`, 若在不同线程, 使用`Qt::QueuedConnection`
> - `Qt::DirectConnection` : 直接连接, 相当于在发送信号处直接调用槽函数,增加函数栈,槽函数执行完返回发送信号处继续运行. 在sender线程
> - `Qt::QueuedConnection` : 队列执行, 同一个信号发送多次, 槽函数排队进入主事件循环, 逐个执行. 在reciver线程
> - `Qt::BlockingQueuedConnection` : 阻塞队列执行, sender与reciver在不同线程,sender会阻塞,直到槽函数执行完成返回. 若在同一个线程, 会产生死锁
> - `Qt::UniqueConnection` : 与其他连接方式并用, 多次绑定会失效. 若信号绑定多个槽函数,槽函数按绑定顺序排队执行


# 信号槽底层


> [!abstract] 信号槽底层如何实现
> Qt 的信号与槽机制通过 **元对象系统** 实现。每个 `QObject` 子类会生成一个 **QMetaObject**，记录类的信号和槽。当信号发射时，Qt 会查找与该信号连接的槽，并通过事件队列调用它们
> - **信号** 是在对象内部发射的，并不会直接调用槽
> - **槽** 是通过 `QObject::connect()` 连接的，当信号发射时，槽会被调用
> - Qt 支持多种连接方式（如直接连接、队列连接）来保证信号与槽在不同线程和环境中的正确执行
> 底层使用 **函数指针** 和 **事件队列** 来实现连接和调用，确保信号与槽之间的解耦和异步处理



# QT事件循环机制

> Qt 的事件循环是通过 `QApplication::exec()` 启动的，本质上是一个消息循环，它不断从操作系统取消息，封装为 `QEvent` 并分发到相应对象。信号与槽的调用也依赖事件循环来调度。Qt 的 UI 必须运行在主线程，事件循环保证了界面的响应和异步机制。如果事件循环被阻塞，界面就会卡死，所以耗时操作一般放在子线程里处理

| 传输层 (Transport)    | 提供端到端通信<br>保证数据传输可靠性或效率      | TCP、UDP                            |       |
| 网络层 (Network)      | 负责*寻址和路由*<br>数据从源头到目的地的路径选择  | IP、ICMP、IGMP、ARP、IPSec、OSPF、BGP    | IP数据报 |
| 数据链路层 (Data Link)  | 建立和管理物理链路上的逻辑连接<br>帧的传输和差错检测 | MAC、PPP、以太网协议、ARP、Switch(交换机)      | 数据帧   |
| 物理层 (Physical)     | 传输比特流，定义电气、机械规范              | RJ45、光纤、网线、集线器、Repeater            | 01比特流 |


# 项目为什么不用UDP

- UDP需要自行在应用层保证可靠
- 开发时间来不及, 准备有空优化
- 最开始学习的就是TCP, 相对来说更熟悉
- 同时*传输文件*, 使用TCP保证有序可靠等, 数据完整性保证

> 我们的项目需要保证数据传输的完整性和可靠性，比如消息不能丢失、不能乱序。TCP自带连接管理、丢包重传、顺序控制等机制，可以直接满足这些需求。而UDP虽然延迟低，但需要我们额外实现可靠性机制，成本更高。所以综合考虑，我们选择了TCP
