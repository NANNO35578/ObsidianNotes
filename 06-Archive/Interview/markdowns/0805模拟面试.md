# `[!!abstract:auto 和decltype]`

| 特性                | `auto`              | `decltype`   |
| ----------------- | ------------------- | ------------ |
| 基于表达式推导           | 变量初始化               | 任意表达式、函数返回值等 |
| 是否保留 `const` / 引用 | 否  去掉顶层 `const` 和引用  | 是            |
| 支持赋值表达式推导         | 否                   | 是  推导为左值引用    |
| 支持解引用推导           | 否                   | 是  推导为对应类型引用  |


### `[!!abstract:]` 构造 `{cpp}std::shared_ptr<A>`时 <br>`{cpp}std::shared_ptr<A> p_share= std::make_share<A>();` 赋值构造和 <br>用`{cpp}std::shared_ptr<A> p_share(new A);`的区别

| 特性         | `std::make_shared<A>()`  | `std::shared_ptr<A>(new A)`                     |
| ---------- | ------------------------ | ----------------------------------------------- |
| **内存分配次数** | 一次分配：对象和控制块  引用计数 一起分配    | 两次分配：先分配对象，再分配控制块                               |
| **性能**     | 更高效  减少一次堆分配              | 相对低效                                            |
| **异常安全性**  | 完全异常安全：在构造过程中若抛异常，内存不会泄漏 | 可能出现异常安全隐患  需要确保 `new A` 成功后才进入 `shared_ptr` 构造  |
| **自定义删除器** | 不支持直接指定删除器               | 支持 `std::shared_ptr<A>(new A,  deleter)`         |
| **对象布局**   | 对象和控制块在一块连续内存  cache 友好   | 控制块和对象分离                                        |
| **使用场景**   | 常用、推荐使用                  | 需要自定义删除器或配合 `std::shared_ptr` 管理已有裸指针时          |

# `[!!abstract:进程间通信方式]`
- 进程间通信  IPC 方式，原理、API、特点、优缺点和典型用途

| 方式          | 核心特点            | 双向/单向 | 需要同步    | 性能    | 典型场景            |
| ----------- | --------------- | ----- | ------- | ----- | --------------- |
| 匿名管道        | 简单、一对父子         | 单向    | 否       | 高     | Shell 管道、父子同步   |
| 命名管道        | 文件系统可见          | 单向    | 否       | 较高    | 简易客户端/服务        |
| SysV IPC    | 共享内存／消息／信号量     | 双向／消息 | 共享内存需同步 | 极高／中等 | 大数据共享／异步消息      |
| POSIX IPC   | 名称空间更友好         | 同上    | 同上      | 同上    | 实时系统、Modern API |
| UNIX Socket | 全双工、权限控制        | 双向    | 内置  流    | 高     | 本地服务通信、FD 传递    |
| INET Socket | 可跨网络            | 双向    | 内置  流    | 较高    | 分布式服务           |
| Signals     | 轻量异步通知          | 信号    | n/a     | 低     | 终止控制、简单事件       |
| eventfd/... | 与 epoll/IOCP 结合 | 事件驱动  | n/a     | 高     | 高性能事件通知         |
| mmap+文件     | 持久化共享           | 双向    | 需同步     | 高     | 文件缓存、数据库        |

##### 1. 匿名管道  Unnamed Pipe 

- **原理** 由内核维护的一对环形管道缓冲区：一个用于写入，一个用于读取. 只能用于具有亲缘关系的进程  父子进程或 fork 出来的兄弟进程 .
- **API** `int pipe(int fds[2]);`  
  - `fds[0]`：读端，`fds[1]`：写端  
  - 默认阻塞读、写. 写端关闭后，读端读到 EOF。
- **特点**  
  - 单向通信；若需双向，可创建两对 pipe. 
  - 简单、高效，开销小. 
  - 无名，仅在创建者及其子进程间可见. 
- **典型场景** shell 管道 `|`、父子进程简单同步/数据传递. 

---

##### 2. 命名管道  FIFO 

- **原理** 在文件系统中创建一个特殊文件  FIFO ，进程可通过该路径打开并读写，实现无亲缘关系进程间通信. 
- **API**  
  - 创建：`mkfifo(const char *pathname,  mode_t mode);`  
  - 打开：`open(path,  O_RDONLY|O_NONBLOCK)` / `open(path, O_WRONLY)`  
- **特点**  
  - 半双工：一次只能一个方向读写.   
  - 同时支持多个读者/写者.   
  - 可与普通文件权限、目录结构集成. 
- **典型场景** 简易的服务进程/客户端通信，日志收集. 

---

##### 3. System V IPC

###### 3.1 System V 共享内存  shm 

- **原理** 多个进程将同一段物理内存映射到自己的虚拟地址空间，共享读写. 
- **API**  
  ```c
  int shmget(key_t key,  size_t size, int shmflg);
  void *shmat(int shmid,  const void *addr, int shmflg);
  int shmdt(const void *addr);
  int shmctl(int shmid,  IPC_RMID, NULL);
  ```
- **特点**  
  - 最快的 IPC  零拷贝 .   
  - 需要额外的同步机制  如信号量 保证并发安全.   
  - 通过 `key` 标识，可持久存在于内核，失控风险需清理  `IPC_RMID` . 
- **典型场景** 视频处理、高速缓存、大规模数据共享. 

###### 3.2 System V 消息队列  msg 

- **原理** 内核维护一个按类型排序的消息链表. 每条消息带用户定义的 `mtype`，可按类型有选择地收取.
- **API**  
  ```c
  int msgget(key_t key,  int msgflg);
  int msgsnd(int msqid,  const void *msgp, size_t size, int msgflg);
  ssize_t msgrcv(int msqid,  void *msgp, size_t size, long mtype, int msgflg);
  int msgctl(int msqid,  IPC_RMID, NULL);
  ```
- **特点**  
  - 面向消息，天然同步；可选择接收指定类型.   
  - 内核分配队列长度、消息条数有限制.   
- **典型场景** 多生产者—多消费者架构中的异步命令/日志收集. 

###### 3.3 System V 信号量  sem 

- **原理** 内核管理一组计数器，供进程间同步或互斥. 
- **API**  
  ```c
  int semget(key_t key,  int nsems, int semflg);
  int semop(int semid,  struct sembuf *sops, size_t nsops);
  int semctl(int semid,  int semnum, IPC_RMID, union semun);
  ```
- **特点**  
  - 可构造 mutex  初值 1 或计数信号量.   
  - 原子操作，可批量执行多次 P/V.   
- **典型场景** 与 System V 共享内存配合，做并发控制. 

---

##### 4. POSIX IPC

###### 4.1 POSIX 共享内存  shm 

- **API**  
  ```c
  int shm_open(const char *name,  int oflag, mode_t mode);
  ftruncate(fd,  size);
  void *mmap(...);
  shm_unlink(name);
  ```
- **特点**  
  - 名称空间在 `/dev/shm`  临时文件系统 下.   
  - 不用 `key`，更符合文件模型.   
- **典型场景** 同 System V 共享内存. 

###### 4.2 POSIX 消息队列  mqueue 

- **API**  
  ```c
  mqd_t mq_open(const char *name,  int oflag, ...);
  mq_send(mqd_t,  const char *msg, size_t len, unsigned prio);
  mq_receive(mqd_t,  char *msg, size_t len, unsigned *prio);
  mq_close(mqd_t);
  mq_unlink(name);
  ```
- **特点**  
  - 支持消息优先级.   
  - 可通过异步通知  SIGEV_SIGNAL、SIGEV_THREAD 接收新消息事件.   
- **典型场景** 实时系统中异步事件分发. 

###### 4.3 POSIX 信号量  sem 

- **API**  
  ```c
  sem_t *sem_open(const char *name,  int oflag, ...);
  sem_init(sem_t *sem,  int pshared, unsigned value);
  sem_wait(sem_t *sem);
  sem_post(sem_t *sem);
  sem_close(sem_t *sem);
  sem_unlink(name);
  ```
- **特点**  
  - 命名  跨进程 或匿名  `pshared=1` 放在共享内存中 .   
  - 接口更友好、类型安全. 
- **典型场景** POSIX 共享内存并发同步. 

---

##### 5. 套接字  Sockets 

###### 5.1 UNIX Domain Socket

- **原理** 内核在文件系统中创建一个 socket 文件  `AF_UNIX` ，支持字节流  `SOCK_STREAM` 或数据报  `SOCK_DGRAM` 通信. 
- **API** 标准 BSD socket 接口：`socket()`,  `bind()`, `listen()`, `accept()`, `connect()`, `send/recv`. 
- **特点**  
  - 双向、全双工.   
  - 权限继承文件权限，可传递文件描述符  `SCM_RIGHTS` .   
  - 本地通信延迟低  绕过网络栈 . 
- **典型场景** Docker daemon、X11、systemd 等本地服务进程通信. 

###### 5.2 网络套接字  INET Socket 

- **原理** TCP/UDP over IP，通过 loopback  127.0.0.1 也可用于同机进程通信. 
- **API** 同上. 
- **特点**  
  - 可扩展到不同主机；跨网络.   
  - 相比 UNIX Domain 多了一层网络栈开销. 
- **典型场景**    微服务、分布式通信. 

---

##### 6. 信号  Signals 

- **原理** 内核向目标进程/线程发送异步通知. 信号只有编号和可选的整数/指针  `sigqueue` 作为载荷。
- **API** `kill()`,  `signal()/sigaction()`, `sigqueue()`, `sigwaitinfo()`. 
- **特点**  
  - 低带宽，适合简单事件通知  如 “终止”、“用户自定义事件” .   
  - 异步、安全性、可靠性都有限制，需要配合信号屏蔽和 `sigaction` 使用. 
- **典型场景** 进程终止控制、定制简单通知. 

---

##### 7. 其它 Linux 专用机制

- **eventfd**  
  - 轻量级计数事件；可用于用户态互斥/计数器，或与 `epoll`/`signal_fd` 集成.   
  - `int eventfd(unsigned initval,  int flags);`
- **signalfd**  
  - 将信号转成文件描述符读事件，方便 `poll/epoll` 统一处理.   
  - `int signalfd(int fd,  const sigset_t *mask, int flags);`
- **timerfd**  
  - 定时器通知抽象成文件描述符，方便与 I/O 复用一起使用.   
  - `int timerfd_create(int clockid,  int flags);`
- **inotify**  
  - 文件系统变化事件通知.   
  - `int inotify_init();`,  `inotify_add_watch()`

---

##### 8. 内存映射文件  mmap + 文件 

- **原理** 多进程同时 `open` 同一文件并 `mmap`，共享该文件映射区. 
- **特点**  
  - 类似共享内存，但数据持久化到文件.   
  - 使用时同样需额外同步  信号量、futex 等 . 
- **典型场景** 大文件映射、持久化缓存、数据库缓冲区.

# 什么是RTMP, 什么是HLS, 工作原理

##### [RTMP](https://zh.wikipedia.org/wiki/RTMP) 实时消息协议

- 用于客户端音视频数据交互
- 推流: 客户端向服务器不断推送音视频流数据. 项目中, 客户端并没有向服务器推流, 因为音视频文件已存储在服务器, 由服务器自己进行推流.
- 分发: 服务器将收到的音视频数据流分发到下游播放器比如OBS, VLC. 项目中我们自己实现了播放器

*原理*:
1. 基于TCP 长连接
2. 数据流分片传输, 客户端实时接收, 播放

参考: 
- https://zhuanlan.zhihu.com/p/191542130 
- https://www.cnblogs.com/IServise/articles/18388197 
- https://zhuanlan.zhihu.com/p/468248646 

##### [`HLS(HTTP Live Streaming)`](https://zh.wikipedia.org/wiki/HTTP_Live_Streaming) HTTP实时流媒体

基于HTTP的流媒体直播, 点播协议. 
- 将视频文件切分为小的TS,片段(2~10)
- 客户端请求m3u8. 播放列表文件(索引) 根据进度逐一请求播放
能够自适应比特率,根据网络选择不同质量

参考: 
- https://www.cloudflare.com/zh-cn/learning/video/what-is-http-live-streaming/ 
- https://zhuanlan.zhihu.com/p/358216055 
- https://www.cnblogs.com/linux985/p/17043072.html 

对比下, RMTP适用于实时性较强的直播, 低延迟, 快速互动的场景
HLS基于HTTP, 兼容性强, 自适应能力强
