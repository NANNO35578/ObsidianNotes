

> [!error] 为什么类和结构体的花括号后面要加分号, 而函数不用?
> 因为类和结构体属于*声明语句*, 而函数加上大括号后就是定义语句了. 
> 同样道理, 只声明函数而在其他地方定义函数, 依旧需要加分号.
> ![[functionNeedSemicolon.png]]

````markdown title:"根本原因"

这个问题其实是 **语法规则（grammar rules）** 导致的，不是因为编译器“宽容”。我帮你分开讲：

---
## 1. **函数定义**
函数定义的语法在 C++ 里是这样的（简化版 BNF）：
```cpp
function-definition:
    decl-specifier-seq declarator function-body
```
- `function-body` → `{ ... }`
- 这个规则本身就完整了，不需要任何 **结束符号**。
- 所以函数定义写成：

```cpp
void foo() {
    // body
}
```

编译器在读到 `}` 就知道 **函数定义结束** 了。
如果你写了个分号：
```cpp
void foo() {
    // body
};   // ✅ 语法允许，但是这个分号其实是一个“空语句”
```

这不是函数定义必须的分号，而是编译器把它当作 **一个空语句**，所以能过编译，但没意义。

---
## 2. **类/结构体定义**

类和结构体的语法是这样的（简化版 BNF）：
```cpp
class-specifier:
    class-key identifier { member-specification } ;

struct-specifier:
    struct-key identifier { member-specification } ;
```

注意最后是 **必须有一个分号 `;`**。
这是因为类/结构体 **定义本身** 是一个 _声明语句（declaration statement）_，C++ 所有声明语句都必须以分号结束：

```cpp
struct A {
    int x;
};   // ← 必须有分号，表示“声明语句结束”
```

编译器才能继续往下读，否则不知道是不是还有别的声明。

---

## 3. **直观理解**

- **函数定义**：本身就是一个完整的“语句单元”，花括号 `{}` 自带边界，不需要额外分号。
- **类/结构体定义**：是 **声明**，C++ 规定声明语句都要以 `;` 结束，所以要写分号。

---

## 4. **类/结构体后面的分号到底是“干什么的”？**

它严格来说不是“结构体的一部分”，而是“声明的结束符”。  
你可以理解为：

```cpp
struct A { int x; } ;  // 前面是定义体，后面那个 ; 是结束标志
```

这也解释了为什么你可以写：

```cpp
struct A {
    int x;
} a, b;   // 定义了 A 类型的变量 a 和 b
```

这里 `a, b` 其实是跟在 **声明语句** 后面的“变量声明部分”，所以必须要有那个 `;` 才算完整。

---

👉 总结一句：

- **函数定义**：`{}` 就是结束，不需要 `;`。
- **类/结构体定义**：属于声明语句，C++ 规定声明语句必须以 `;` 结尾。

---

要不要我帮你找个 **标准 C++ 语法文法（BNF 规则）对照**，让你能直接看到函数定义和类定义在语言标准里的不同？
````

# 隐式类型转换
- 转换通常在编译时发生，允许在不同类型之间进行运算而无需显式地进行转换
1. **算术运算**：当涉及不同类型的操作数时，比如`int`和`float`，编译器会自动将`int`转换为`float`，以便进行运算。
  ```cpp
 int a = 5;
 float b = 2.5;
 float result = a + b; // a会被隐式转换为float
  ```

2. **赋值操作**：在赋值时，如果右侧的值类型可以转换为左侧变量的类型，编译器会进行隐式转换。
 ```cpp
 double x = 10; // int 10 隐式转换为 double
```

3. **函数参数传递**：当传递参数给函数时，如果参数的类型与函数定义中的类型不匹配，编译器会尝试进行隐式转换。
  ```cpp
 void func(float f) { /* ... */ }
 func(10); // int 10 隐式转换为 float
 ```
 
##### 造成后果
- **精度丢失**：隐式类型转换可能导致数据精度丢失。例如，将`float`转换为`int`时，小数部分将被截断
- **不安全的转换**：某些情况下，隐式转换可能导致逻辑错误，尤其是在复杂表达式中
- **使用`static_cast`**：在需要明确转换时，可以使用`static_cast`进行显式类型转换，以提高代码的可读性和安全性


## *截断* 
- **截断**是指在将数据从一种类型转换为另一种类型时，丢弃不需要的部分
- 常见的情况包括将浮点数转换为整数时，小数部分会被移除

1. **浮点数到整数的转换**：当一个浮点数（如`float`或`double`）转换为整数类型时，小数部分会被截断，仅保留整数部分
```cpp
   double x = 3.7;
   int    y = x; // y 将是 3，0.7 被截断

   int  num   = 300;  
   char chNum = num; // chNum为44 char最大127, 300%127=44
```

2. **字符串到数字的转换**：在某些情况下，将字符串解析为数字时，可能会忽略无效部分
  ```cpp
  std::string str = "123abc";
  int num = std::stoi(str); // num 将是 123，"abc" 被截断
  ```

# 调用约定 [Calling convention](https://en.wikipedia.org/wiki/Calling_convention) [x86](https://en.wikipedia.org/wiki/X86_calling_conventions#thiscall)
约定参数怎么传递,谁来管理出栈,编译后名字的修饰方式
- 默认 : `__cdecl` 另有`__stdcall` `__fastcall`
- 如`scanf` `printf`等变长参数函数,不知道参数大小,只能由调用者回收
- Win32的API绝大部分是__stdcall调用约定 WINAPI只是__stdcall别名

| 调用约定         | 管理出栈方 | 参数传递                                             | 名称修饰                                                               | C++名字修饰                |
| ------------ | ----- | ------------------------------------------------ | ------------------------------------------------------------------ | ---------------------- |
| `__cdecl`    | 函数调用方 | 从右至左的顺序压参数入栈                                     | 下划线+函数名(c编译)                                                       | ?+函数名@@YA+参数表@Z(c++编译) |
| `__stdcall`  | 函数本身  | 从右至左的顺序压参数入栈                                     | 下划线+函数名+@+参数的字节数,如函数`int func(int a,double b)`的修饰名是`_func@12`(c编译) | ?+函数名@@YG+参数表@Z(c++编译) |
| `__fastcall` | 函数本身  | 头两个DWORD(共4字节)类型者占更少字节的参数被放入寄器,其他剩下的数按从右到左的顺序压入栈 | @+函数名+@+参数的字节数(c编译)                                                | ?+函数名@@Yl+参数表@Z(c++编译) |

# 内存分布**四区五段** [Program memory](https://en.wikipedia.org/wiki/Data_segment#Program_memory)
- *四区*: 以`区`来看有 堆区、栈区、全局区、常量区。  
  这四个区代表了程序运行时内存的不同部分，每个区域负责不同的任务和数据存储方式。

- *五段*: 四区展开为更具体的五个部分。  
  - `stack` 栈区 [Call Stack](https://en.wikipedia.org/wiki/Call_stack):  
    栈区用于存储局部变量、函数调用时的返回地址、参数以及函数调用的上下文信息。栈是由操作系统自动管理的，它使用“后进先出（LIFO）”的方式来分配和回收内存。栈的大小是有限的，一旦超过限制，就会发生“栈溢出”。

  - `heap` 堆区 [Manual Memory Management](https://en.wikipedia.org/wiki/Manual_memory_management):  
    堆区用于动态分配内存。程序员可以通过 `malloc()`、`free()`等函数手动分配和释放堆内存。堆内存的分配和回收是程序员负责的，相比栈，它的生命周期更长，直到显式地释放。堆的内存管理比栈更复杂，容易出现内存泄漏。

  - `.bss` [Block starting symbol](https://en.wikipedia.org/wiki/.bss):  
    `.bss` 段存储未初始化的全局变量和静态变量。尽管这些变量在程序启动时不会占用具体的内存空间，但操作系统会为它们分配内存，并在程序加载时将其初始化为零。`.bss` 段的主要作用是节省程序的存储空间，因为操作系统会在程序加载时为这些变量分配内存并初始化为零，而不需要在可执行文件中存储这些数据。

  - `.data` 数据段 [Data segment](https://en.wikipedia.org/wiki/Data_segment):  
    `.data` 段存储程序中已初始化的全局变量和静态变量。与 `.bss` 不同，`.data` 中的数据在程序加载时已经有了确定的值。此段数据通常在编译时就会被嵌入到程序文件中，并会在程序运行时被加载到内存中。

  - `.text` 代码段 [Code segment](https://en.wikipedia.org/wiki/Code_segment):  
    `.text` 段是程序的代码段，存储程序的可执行代码。它通常是只读的，以防止程序意外地修改自身代码。程序的机器指令都保存在这里，操作系统会在程序加载时将其映射到内存中。

### C启动过程 [C startup](https://www.bravegnu.org/gnu-eprog/c-startup.html)
  在程序开始执行之前，操作系统和运行时环境需要完成一些初始化工作。例如，它们会先初始化 `.bss` 和 `.data` 段，设置栈和堆的大小，创建必要的文件描述符，处理命令行参数等。这些初始化操作通常在程序的入口函数（如 `main()`）执行之前进行。这些过程是由C语言的启动代码（通常由编译器和操作系统提供）来完成的。

## 堆和栈区别

1. 申请方式不同: 栈区空间由系统自动分配，而堆区空间根据需要由程序员自己申请。栈区空间在其所在作用域结束后由系统自动回收，而堆区空间由程序员自己释放，若程序员没有释放，则在程序结束后由操作系统回收，在程序结束前会造成内存泄漏
2. 申请后系统响应: 只要栈剩余空间大于所申请空间，系统就会为程序提供内存，否则会有异常提示或栈溢出。对于堆内存，操作系统会有一个记录空闲内存地址的链表. 系统收到程序的申请时, 会遍历该链表, 寻找第一个空间大于所申请的空间的堆, 然后将该节点从空闲链表中删除并将节点空间分配给程序员~~若是找到一堆节点的大小不XXXX大于申请的大小,系统会自动将多余的那部分重新放入空闲链表中(可能会导致堆申请效率问题)~~
3. 申请的效率问题: 栈, 申请速度快, 但无法人为控制. 堆, 一般速度较慢, 会产生内存碎片
4. 申请大小限制: Windows下栈区是向低地址扩展的数据结构,是一块连续的内存区域, 即栈顶地址和栈的最大容量是系统预定的. 栈的大小是一个编译时即就确定好的常数. 一旦申请空间太大, 超出栈的剩余空间,将导致栈溢出. 堆是向高地址扩展的, 是不连续的内存区域, 堆大小受限于系统有效的虚拟内存. 堆获得的空间比较灵活, 也比较大
5. 堆和栈中心存储内容: 栈, 在函数调用时,第一个进栈的是函数调用的下一条指令的地址, 然后是函数参数(默认`__cdecl`调用约定从右向左), 然后是函数的中心局部变量, 当函数调用结束后, 局部变量,参数依次出栈,最后栈顶指针指向最开始的地址. 堆, 一般是在堆头部用一个字节存放堆大小, 堆中心具体内容由程序员安排
6. 存取率比较: `char str1[] = "aaa";` 与`char *str2 = "aaaa";`. str1是数组,运行时赋值,放入栈中, str2是编译时确定指向常量区,**放在堆中??** 之后存取, 栈比堆快

## 哈夫曼编码 [Huffman Coding](https://en.wikipedia.org/wiki/Huffman_coding)
<dl>
<dt>一种用于数据压缩的最优编码方法, 根据哈夫曼树编码, 哈夫曼树又称最优二叉树.</dt>
<dd>是一种带权路径长度最短的二叉树</dd>
<dd>树的带权路径长度, 就是树中所有节点的权值乘该节点到根节点的路径长度(层数)</dd>
</dl>
- 记节点高度$d(i)$ 权值$w_i$ ,则哈夫曼树加权路径长度为
$$ WPL = \sum_{i} w_i \cdot d(i) $$


构建一个**前缀码**来最小化编码的总长度, 假设消息为`A_DEAD_DAD_​CEDED_A_BAD_​BABE_A_BEADED_​ABACA_BED`

1. 首先，统计每个字符在消息中出现的次数
```
A: 9    _: 7    D: 4    B: 4    E: 6    C: 2
```

2. 根据字符的频率构建一个*最小堆（优先队列）*
最初的堆中，每个元素是一个包含字符及其频率的节点：
```
(A, 9), (_, 7), (D, 4), (B, 4), (E, 6), (C, 2)
```

3. 每次从堆中取出频率最小的两个节点，创建一个新的节点，它们的频率是两个节点频率之和。将新的节点插入堆中
	 1. 从堆中取出 `C`（频率 2）和 `B`（频率 4），创建一个新的节点 `(CB, 6)`，并将其插入堆中。
	` (E, 6), (CB, 6), (_, 7), (A, 9), (D, 4)`
    2. 以此类推. 最后，取出 `E_`（频率 13）和 `(A DCB, 19)`（频率 19），创建最终的根节点 `(E_ A DCB, 32)`

4. 经过合并，生成最终的哈夫曼树，结构如下：
```
                (E_ A DCB, 32)
               /              \
          (E_, 13)          (A DCB, 19)
          /    \            /         \
      (E, 6)   (_)       (A, 9)     (DCB, 10)
                         /    \       /     \
                    (D, 4)  (CB, 6) (C, 2)  (B, 4)
```

5. 根据哈夫曼树的结构，从根节点到每个叶子节点的路径决定了每个字符的哈夫曼编码。通常，左分支标记为 `0`，右分支标记为 `1`. 最终的哈夫曼编码如下：
```
A: 01    _: 00    D: 111    B: 110    E: 10    C: 1110
```

6. 对原始消息进行编码. 消息 `"A_DEAD_DAD_​CEDED_A_BAD_​BABE_A_BEADED_​ABACA_BED"` 使用哈夫曼编码后，将变成一串二进制数字：
```
A_DEAD_DAD_​CEDED_A_BAD_​BABE_A_BEADED_​ABACA_BED
= 01 00 111 10 00 111 111 10 10 1110 00 10 111 01 111 111 01 110 01 110 1110 01 110 10 111 01 110 1110 01 111 110 01 111 110
```

##### 为什么说 C 语言是强类型语言？
- 计算机编程语言种类繁多，这些编程语言根据不同的特性角度可以分为不同的种类
- 根据“变量在定义时，是否需要显式地指明数据类型”，可以分为强类型语言与弱类型语言
- C 语言,C++,JAVA 这些语言对于变量的类型“极其敏感”。不同数据类型定义的变量会拥有不同的存储原理与空间大小，如果变量在被赋值或读取值时，类型与值不匹配会产生编译错误
- 与之相反的称为弱类型语言，如 JavaScript（JS）、Python、PHP等。弱类型语言在定义变量时不需要显式的指明类型。编译器（或解释器）会根据最新赋值给变量的数据值*自动推导类型*。一个变量的类型值可自由切换

##### `register`, `volatile`, `auto` 关键字(C89/C90)
- `register` 用于优化性能，建议使用寄存器
- `volatile` 用于防止编译器优化，确保变量的值始终从内存中读取
- `auto` 主要用于声明局部变量，通常不需要显式使用

`register`
- **作用**：提示编译器将变量存储在 CPU 寄存器中，以提高访问速度。
- **使用场景**：通常用于频繁访问的局部变量。
- **注意**：编译器并不一定会遵循这个建议，且不能对 `register` 类型的变量取地址。
```c
void func() {
    register int count; // 提示编译器存储在寄存器中
}
```

`volatile`
- **作用**：告诉编译器，该变量可能会在程序的其他部分被改变，因此每次访问时都要从内存中读取，而不是使用寄存器中的值。
- **使用场景**：常用于多线程编程、处理硬件寄存器或信号处理程序中。
```c
volatile int flag; // 可能被外部因素改变
```

`auto`
- **作用**：用于声明局部变量，表示其存储类型为自动变量（默认类型）。在 C89/C90 中，`auto` 实际上很少使用，因为局部变量默认就是自动存储类型。
- **使用场景**：主要用于增强代码的可读性，但在实际编程中几乎不必使用。
```c
auto int num = 10; // 自动变量声明
```

##### C99的5个关键字

`inline`
- **作用**：建议编译器在调用函数时内联展开，以减少函数调用的开销。
- **使用场景**：用于小型函数，提升性能。
```c
inline int square(int x) { return x * x; }
```

`restrict`
- **作用**：用于指针，表示该指针是唯一的访问某一内存区域的方式，允许编译器进行更优化的操作。
- **使用场景**：在处理数组和指针时，提升性能。
```c
void copy(int *restrict dest, const int *restrict src, size_t n);
```

`_Bool`
- **作用**：表示布尔类型，值为 `true`（1）或 `false`（0）。
- **使用场景**：提高代码可读性，使用布尔逻辑。
```c
#include <stdbool.h>
bool flag = true;
```

`_Complex` 
- **作用**：表示复数类型，支持复数运算。
- **使用场景**：在数学、信号处理等领域。
```c
double _Complex z = 1.0 + 2.0 * I;
```

`_Imaginary` 可用作变量名 
- **作用**：表示虚数类型，用于复数的虚部。
- **使用场景**：与复数一起使用，表示虚数部分。
```c
#include <complex.h>
double imaginary_part = 2.0 * I; // 虚数部分
```

##### C11的7个关键字 多线程编程和类型安全

`_Alignas`
- **作用**：用于指定变量或类型的对齐要求。
- **使用场景**：控制结构体或变量的内存对齐。
```c
_Alignas(16) int x; // x 的对齐要求为 16 字节
```

`_Alignof`
- **作用**：用于获取类型的对齐要求。
- **使用场景**：在动态内存分配时获取所需的对齐值。
```c
size_t alignment = _Alignof(double); // 获取 double 类型的对齐要求
```

`_Atomic`
- **作用**：表示原子类型，支持无锁并发编程。
- **使用场景**：实现多线程安全操作。
```c
#include <stdatomic.h>
_Atomic int counter; // 声明一个原子整数
```

`_Noreturn`
- **作用**：用于标记不会返回的函数。
- **使用场景**：在编写异常处理或终止程序的函数时使用。
```c
#include <stdlib.h>
_Noreturn void my_exit() {
    exit(1);
}
```

`_Static_assert`
- **作用**：用于在编译时进行断言检查。
- **使用场景**：确保某些条件在编译时为真。
```c
_Static_assert(sizeof(int) == 4, "int must be 4 bytes");
```

`_Thread_local`
- **作用**：用于声明线程本地存储的变量。
- **使用场景**：在多线程程序中保留每个线程的独立变量。
```c
_Thread_local int thread_local_var;
```

`_Generic`
- **作用**：用于实现泛型选择，根据类型选择不同的表达式。
- **使用场景**：简化多种类型的函数实现。
```c
#define max(a, b) _Generic((a), \
    int: max_int, \
    float: max_float \
)(a, b)
```

1. _从源代码到exe需要经过哪几个时期？_	
	- 预处理期-> 编译期-> 汇编期-> 连接期-> 执行期	

2. _不同时期里：谁？在做什么事情？_
	- 预处理期: _预处理器_ 将处理所有`#`开头的指令 即宏，指令和头文件，生成 `.i`文件
	- 编译期: _编译器_ 将 `.i`文件编译成汇编语言 主要进行词法分析、语法分析、优化等操作
	- 汇编期: _汇编器_ 将 汇编语言转换成目标文件`.obj`/`.o`
	- 连接期: _链接器_ 将目标文件链接成可执行文件`.exe`
	- 执行期: _操作系统_ 加载可执行文件运行程序

3. _基本数据类型的存储原理包括哪些？_
	1. **整型存储**: 以int为例 占32位 最左侧为符号位(0为正1为负) 余下位存储该int的二进制值 该32位码称为*源码* 对源码处理得到*反码* 若为正数不做操作(源码与反码相同) 若为负数则保留符号位余下位按位取反得到反码 然后对反码操作得到*补码* 同样正数不做操作 负数则在反码基础上加一 最终得到计算机实际存储的反码 因此可以得到int类型表达范围为$[-2^{31}, 2^{31}-1]$(-1为全1)
	2. **浮点存储**: 内存空间按——*符号位+指数区+尾数区*的形式进行存储分配。其中：float 的内存空间(4 个字节 32 位): 1 个符号位+8 个指数区+23 个尾数区。double 的内存空间(8 个字节 64 位): 1 个符号位+11 个指数区+52 个尾数区。下面以一个 float 类型实例简要说明一下浮点型数据的存储过程：以10.127F 为例：转换为二进制  1010.0100000100000110001001001101110100101111000110101 指数化时二进制浮动了 3 个二进制位，这个 3（二进制的 11）在存储到指数区时需要增加 0111111 进行偏移处理。即 127+3 得到的二进制为 10000010。最终保留的为0 10000010 01000100000100000110001
	[IEEE-754 浮点转换器](https://www.h-schmidt.net/FloatConverter/IEEE754.html)

4. _`[]`运算符的计算过程是什么？_
	优先级和( )一样，最高优先级。其使用格式为：参照地址\[偏移量\]
	等价于 \*(参照地址+偏移量)
	arr\[N\] 从第 0 个成员地址(arr)开始偏移指向下标 N 成员的地址 然后按照数据类型获取存储内容

5. _什么是小端存储及应用？_
	内存中低地址存储低位数值 而高地址存储高位数值
	一些处理器架构（如 x86 和 x86-64）使用小端存储 
	一些文件格式（如 BMP 图像文件）使用小端存储来表示多字节数据

6. _什么是大端存储及应用？_
	内存中低地址存储高位数值 而高地址存储低位数值
	网络协议（如 TCP/IP）通常使用大端存储，这被称为网络字节顺序，以确保在不同机器间传输数据时的统一性
	一些处理器（如 PowerPC 和 SPARC）使用大端存储

7. _堆区与栈区的特性是什么？_
	栈区的特性: *向下生长*
	- 自动管理：局部变量在函数调用时分配，在函数返回时自动释放。
	- 存储速度快：由于栈区的分配和释放遵循后进先出（LIFO）原则，因此访问速度较快。
	- 大小限制：栈区的大小通常较小，依赖于系统的栈大小设置，容易导致栈溢出（stack overflow）。
	- 作用域：局部变量的生命周期和作用域仅限于函数内部。
	堆区的特性: *向上生长*
	- 手动管理：内存的分配和释放由程序员控制，使用 new 和 delete 关键字。
	- 存储速度较慢：堆区的内存分配和释放相对较慢，因为需要查找合适的块并可能进行碎片整理。
	- 大小灵活：堆区的大小可以根据需要动态分配，通常受到系统内存限制。
	- 作用域广泛：在堆区分配的对象可以在程序的多个地方使用，直到显式释放内存。

## **内存分布**
1. _内存空间分配的顺序是什么？_ 
	四区五堆: 数据段, 代码段, `.bss`, 堆, 栈
	1. *静态存储区*
		内容：全局变量和静态变量。
		分配时机：程序编译时分配，生命周期贯穿整个程序运行。
		存储位置：.data 段（已初始化）和 .bss 段（未初始化）。
	2. *栈 (Stack)*
		内容：局部变量、函数参数、返回地址。
		分配顺序：采用后进先出（LIFO）方式，内存地址从高向低增长。
		特点：自动管理，函数结束后自动释放。
	3. *堆 (Heap)*
		内容：动态分配的内存（使用 malloc、new 等）。
		分配顺序：通常从低地址向高地址增长，取决于内存管理器。
		释放顺序：需要手动释放（使用 free 或 delete），否则可能导致内存泄漏。
	4. *代码区 (Text)*
		内容：存储程序的机器指令。
		特点：通常为只读，以防止程序意外修改其指令。
	**静态存储区** → **栈** → **堆** → **代码区**

## 关键字
#### `extern`
1. _`extern`是什么意思？_
	`extern` 是一个存储类说明符，用于声明一个变量或函数在其他文件中定义。它告诉编译器该变量或函数的定义在别的地方，避免重复定义。

2. _`extern`的使用场景？_
	- **跨文件共享变量**：当多个源文件需要访问同一个变量时，可以在一个文件中定义变量，在其他文件中使用 `extern` 声明该变量。
	- **函数声明**：在一个文件中定义函数，而在其他文件中声明该函数以供使用
3. _使用`extern`的注意事项？_
	- **必须匹配类型**：使用 `extern` 声明的变量或函数必须与其定义时的类型匹配。
	- **初始化问题**：`extern` 声明的变量不能被初始化，因为它只是一个引用，不占用存储空间。`extern int globalVar = 10;` 错误：不能初始化
	- **链接性**：确保在链接阶段，所有使用 `extern` 声明的变量或函数都有相应的定义，否则会导致链接错误。
	- **作用域**：`extern` 对于变量和函数的作用域是全局的，但变量的定义位置决定了它的可见性

---
#### `static`
1. _`static`变量与非`static`变量所在内存区的区别？_
	- static 变量：存储在全局区（或静态区），在程序整个运行期间保持存在。只初始化一次，后续调用仍然保持上次的值。
	- 非 static 变量：存储在栈区（局部变量）或全局区（全局变量）。局部变量在函数调用时创建，函数结束后销毁，值在每次调用时重新初始化。

2. _C源代码的范围包括哪些？_
	- **代码区**：存储程序的机器指令。
	- **常量区**：存储程序中定义的常量数据。
	- **全局区**：存储全局变量和 `static` 变量。
	- **堆区**：动态分配内存的区域，使用 `malloc`、`calloc` 等函数分配。
	- **栈区**：存储局部变量和函数调用时的上下文信息。

3. _`static`变量的生命周期与作用域是什么？_
	- 生命周期：static 变量的生命周期是整个程序运行期间。它们在程序开始时分配内存，并在程序结束时释放。
	- 作用域：static 变量的作用域通常是定义它的块（如函数或文件）。如果在函数内定义，则只能在该函数内访问；如果在文件内定义，则只能在该文件内访问（文件作用域），但在整个程序中保持静态特性

#### `const`
1. _`const`关键字是什么？_
	用于声明常量，使得被修饰的变量在其生命周期内不可修改。它可以用于基本数据类型、结构体、类以及指针等

2. _`const`修饰变量的注意事项？_
	不可修改：一旦用 const 声明变量，就不能再对其赋值。`const int x = 10;  x = 20; // 错误：不能修改常量`
	作用域：const 变量的作用域与普通变量相同，超出作用域后将不再有效。
	初始化：const 变量必须在声明时初始化，因为其值不可更改。
	与指针结合：在指针使用中，const 关键字可以修饰指针本身或指向的数据，具体用法需注意。

3. _`const`修饰指针变量的三种方式？_
	- 指向常量的指针: `const int* ptr;`指针 ptr 指向常量 int，不能通过 ptr 修改其指向的值
	- 常量指针: `int* const ptr = &value;` ptr 是常量指针，指向的地址固定，不能修改 ptr 的地址，但可以修改指向的数据
	- 常量指针指向常量: `const int* const ptr = &value;` ptr 是常量指针，既不能修改地址，也不能修改指向的数据

#### `typedef`
1. _`typedef`的基本用法？_
	全称 `type define` 即类型定义 用于定义类型别名 `typedef existing_type new_type_name;`

2. _`typedef`定义数组指针与函数指针的方式？_
	- 定义数组指针: 数组指针是指向数组的指针，可以使用 typedef 来简化定义。
	```cpp
typedef int (*ArrayPtr)[10]; // 定义一个指向大小为 10 的整型数组的指针
	```
	- 定义函数指针: 函数指针是指向函数的指针，可以使用 typedef 来定义函数指针类型。
```cpp
typedef void (*FuncPtr)(int); // 定义一个指向返回类型为 void，参数为 int 的函数的指针
```

3. _`typedef`的嵌套定义指什么？_
	在定义类型别名时，使用一个或多个 `typedef` 来定义更复杂的类型，同时允许将这些类型组合在一起。这种方式通常用于简化复杂的类型，例如结构体、指针和函数指针的组合。
```cpp
	typedef int Array[10];         // 定义一个大小为 10 的整型数组类型
	typedef Array* ArrayPtr;       // 定义指向整型数组的指针类型
```

#### `enum`
1. _举例：什么情况需要定义枚举类型？_
	主要用于某数据类型的数据值是有限的且有意义的少量可能的值 例如，表示一个任务的状态, 表示用户角色, 表示方向颜色 或者一组*错误码* 一些配置选项

2. _定义枚举类型的格式？_
```cpp
		enum EnumName {
	    Constant1,  // 默认值为 0
	    Constant2,  // 默认值为 1
	    Constant3,  // 默认值为 2
	    // ...
	    ConstantN   // 默认值为 N-1
		};
```
3. _枚举类型变量的值可以是整数吗？_
	默认是从0开始的整数 可自定义为整数

4. _枚举类型在源代码中的意义？_
	- 增强可读性：枚举提供了有意义的名称代替数字常量，使代码更易于理解。例如，使用 Color::RED 比使用 0 更直观。
	- 减少错误：使用枚举可以避免使用错误的常量值，编译器会检查传递给函数的枚举类型是否有效，从而减少类型错误。
	- 组织相关常量：枚举将相关常量组合在一起，有助于代码的组织和管理，使得相关值更易于查找和维护。
	- 提高可维护性：当需要修改常量值时，只需在枚举定义中进行更改，避免了在代码中到处查找和替换常量的麻烦。
	- 支持类型安全：在使用 enum class 时，枚举类型是强类型的，避免了不同枚举之间的隐式转换，提高了类型安全性。
	- 便于调试：枚举类型在调试时更容易识别和显示，因为它们使用了有意义的名称而不是数字，使调试信息更具可读性。

#### `union`
1. _扩展类型（或称复合类型）包括哪些？_
	- 结构体 (struct)：用于组合不同类型的数据。
	- 联合体 (union)：用于在同一内存位置存储不同类型的数据，但只能存储其中一个。
	- 枚举 (enum)：用于定义一组命名的整型常量。
	- 数组：用于存储相同类型的多个元素。

2. _`struct`与`union`的区别？_
	- 存储方式：struct：每个成员都有自己的内存空间，大小为所有成员大小之和。union：所有成员共享同一内存空间，大小为最大成员的大小。
	- 使用场景：struct：适合需要同时存储多个数据成员的情况。union：适合在不同时间存储不同类型的数据，节省内存。

3. _结构体对齐补齐指什么以及意义？_
	- 对齐补齐：在内存中，编译器根据数据类型的大小和架构要求，将结构体的各个成员按特定的边界对齐。例如，一个 int 可能要求在 4 字节对齐，而 char 可能要求在 1 字节对齐。
	- 意义：提高访问效率：对齐能使 CPU 更快地访问数据，减少因不对齐导致的性能损失。避免潜在的硬件错误：某些架构可能不支持未对齐的内存访问。

4. _`union`使用时的注意事项？_
	- 只能使用一个成员：在任何时候只能使用 union 中的一个成员，修改一个成员会影响其他成员的值。
	- 正确使用类型：访问 union 中的成员时，需确保访问的是最后被写入的成员，否则可能导致未定义行为。
	- 初始化：union 只能初始化一个成员，使用时需注意初始化的成员。
	- 大小和对齐：union 的大小由最大成员决定，注意对齐可能导致的内存浪费。

#### `#define`
1. _`#define`与`#include`在预处理时的不同作用？_
	- `#define` ：用于定义宏，创建常量或函数-like 宏。在预处理阶段，编译器会将所有出现的宏名称替换为其定义的内容。主要用于简化代码，增强可读性，或者条件编译。
	- `#include` ：用于包含头文件。在预处理阶段，编译器会将指定的头文件内容插入到当前文件中。主要用于代码重用和模块化，允许将函数、类及其他声明组织到多个文件中。

2. _参数宏的用法与注意事项？_
	```cpp
#define SQUARE(x) ((x) * (x)) // 定义一个参数宏
int result = SQUARE(5); // result = 25
	```
	- 括号：在宏定义中使用括号，以避免运算顺序错误。
	- 副作用：如果传递的参数有副作用（如自增），可能导致意外结果。

3. _举例：宏的嵌套定义是什么？_
	宏的嵌套定义指的是在一个宏中调用另一个宏。
```cpp
#define DOUBLE(x) ((x) + (x)) 
#define SQUARE(x) ((x) * (x)) 
#define DOUBLE_SQUARE(x) (DOUBLE(SQUARE(x))) // 嵌套宏
```

2. _宏定义类型与`typedef`定义类型的区别？_
	- 宏定义：使用 `#define` 定义常量或替换代码片段，不进行类型检查。在预处理阶段进行文本替换，可能会引入错误。
	- `typedef` ：用于定义类型别名，提供类型检查。在编译阶段进行，增强代码的可读性并保持类型安全。

## `__attribute__` 

在C/C++中，`__attribute__`是一个GNU扩展，用于给变量、函数或类型添加特定的属性或指示。这些属性可以影响编译器的行为，以优化代码、增强性能或提供特定的功能。
##### 常见属性
1. **`__attribute__((noreturn))`** 指示函数不会返回，例如 `exit()` 或 `abort()`
```c
void my_exit() __attribute__((noreturn));
```

2. **`__attribute__((deprecated))`** 标记一个函数或变量为不推荐使用，编译时会发出警告
```c
void old_function() __attribute__((deprecated));
```

3. **`__attribute__((unused))`** 指示编译器某个变量或函数可能未被使用，避免未使用的变量警告。
```c
int unused_var __attribute__((unused));
```

4. **`__attribute__((aligned(n)))`** 指定变量的内存对齐方式
```c
struct my_struct {
    char a;
    int b __attribute__((aligned(16)));
};
```

5. **`__attribute__((section("section_name")))`**  
    将函数或变量放置在指定的段中
```c
void my_function() __attribute__((section(".my_section")));
```
