# 发送接收缓冲区

UDP和TCP协议的数据都是这样发送和接收的

> 1. 操作系统会给每个进程分配4G的 _虚拟_ 内存空间,0-2G是内核空间,2-4G是用户空间
> 	_虚拟_ : 大小虚拟(应用程序以为有) 实际按需分配
> 	      实际地址也是虚拟的
> 2. 进程创建socket的时候,操作系统会在内核空间给这个socket分配一个发送缓冲区和一个接收缓冲区(64KB)
> 3. 进程中定义的recvBuf和sendBuf是在用户空间申请空间
> 4. 当数据到达操作系统的时候,会根据socket绑定的端口号,把数据写入到socket对应的接收缓冲区中
> 5. 当进程调用recvfrom/recv函数的时候,就是把接收缓冲区中的数据拷贝到recvBuf中
> 6. 当进程调用sendto/send函数的时候,就是把sendBuf中的数据拷贝到发送缓冲区中,由操作系统通过网卡发送出去

_获取缓冲区大小_
```cpp
  //> 获取接收缓冲区大小 
  int recvBufLen = 0;
  int sendBufLen = 0;
  int size = sizeof(int);
  getsockopt(s, SOL_SOCKET, SO_RCVBUF, (char*)&recvBufLen, &size);
  getsockopt(s, SOL_SOCKET, SO_SNDBUF, (char*)&sendBufLen, &size);
```

# 阻塞/非阻塞
_阻塞_ : 老王烧水,把水壶放在炉子上,就在旁边等着水烧开
1. 等待的事情发生的时候第一时间知道
2. 等待的过程中不占用CPU

_非阻塞_ : 老王烧水,把水壶放在炉子上,就去看电视了,每隔一段时间回来看看水开没开,如果没开就继续去看电视
1. 等待的事情发生的时候不能够第一时间知道
2. 等待的过程中占用CPU -- _不推荐使用_


_socket默认是阻塞的_,所以接收和发送数据都是阻塞的
把`SOCKET`设置成非阻塞
```cpp
  u_long iMode = 1;
  int rt = ioctlsocket(s, FIONBIO, &iMode);
```

__发送函数的阻塞和非阻塞__ -- 面试常问问题
1. 发送缓冲区空间不足够大的时候 阻塞发送等发送缓冲区空间足够大,再往里拷贝数据
2. 发送缓冲区空间不足够大的时候 非阻塞发送就是有多大空间就往缓冲区中拷贝多少数据 剩余的数据由进程自行处理

# UDP协议特点
用户数据报协议 不可靠传输
- 可1对1 1对n(组播 广播) 
- 发送效率高 (相对TCP)
- 没有差错校验 会出现丢包和乱序
