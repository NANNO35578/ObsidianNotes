# 数据库介绍
> 什么是数据库
- 数据库是“按照数据结构来组织、存储和管理数据的仓库 是一个长期存储在 _计算机_ 内的、有组织的、可共享的、统一管理的大量数据的集合。
- _查找更快_ 

> 数据库的由来?
- 规范化的本地存储
- 加密
- 共享

> 数据库的分类
- 关系型数据库 : 二维表,典型代表mysql,oracle,SQL Server

| name     | age |
| -------- | --- |
| zhangsan | 18  |
| xiaoming | 18  |

- 非关系型数据库 : 也叫NoSql 是一维映射key-value 典型代表 `redis` `MongoDB`

| key    | value                    |
| ------ | ------------------------ |
| "id=0" | zhangsan                 |
| "id=1" | name = zhangsan age = 12 |
| "id=2" | name =lucy age =16       |

# 数据库范式
> 什么是范式?
- 要想设计一个好的关系 必须使关系满足一定的约束条件 此约束已经形成了规范 按照这种规范可以使设计简洁的、结构明晰 不会因为插入删除 更新数据导致异常
常见名词 : 
 - 属性 : 特征--> 表中的一列--> 字段-->A
 - 元组 : 表中一行
 - 码 : 能唯一确定表中一行的 _属性_. 码不止一个 称为候选码 
 - 主码 : 从候选码中挑选一个主要确定这一行的属性
 - 主属性 : 在任何一个候选码中出现过 成为主属性
 - 非主属性 : 没有出现在任何一个候选码中

##### 第二范式(2NF)
> 第二范式(2NF) 不存在组合关键字中的某些字段决定非关键字段.(组合关键字不可拆) _非关键字字段全都由组合关键字决定_
![[组合关键字不可拆.png]]

选课课表 `SelectCourse(学号, 姓名, 年龄, 课程名称, 成绩, 学分)`
问题 : 1.数据冗余 2.更新异常 3.插入异常
解决 : 拆表 分为
	`学生 (学号, 姓名, 年龄)`
	`课程 (课程名称, 学分)`
	`选课 (学号, 课程名称, 成绩)`
	三个表

##### 第三范式(3NF)
> 不存在依赖传递 
> 传递 : 关键字段 -> 非关键字段1 -> 非关键字段2

例如 : 学生的关系表:(学号,姓名,年龄,所在学院,学院地点,学院电话)
解决 : 拆表 

##### BCNF(鲍依斯-科得范式)
> 不存在关键字段决定关键字段.

例如 : 仓库管理系统(仓库ID,存储物品ID,管理员ID,数量)
解决 : 拆表 
	仓库管理:仓库ID,管理员ID
	仓库:仓库ID,存储物品ID,数量
