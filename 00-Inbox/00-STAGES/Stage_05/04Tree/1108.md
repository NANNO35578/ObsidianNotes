# 哈夫曼树 Huffman Tree
"赫夫曼树" "最优二叉树"
> [!bug] __逻辑__ 结构 类似堆排序 不需造出树的结构

- 用于生成哈夫曼编码
---
##### 带权路径长度 (WL)（Weighted Path Length, WL）
- **定义**：带权路径长度（WL）是指从树的根节点到某个特定节点的路径长度（即边的数量）与该节点的权重的乘积。计算公式为：
$$  WL = \text{权重} \times \text{路径长度}$$
- **路径长度**：  路径长度是从根节点到该节点的边的数量。
**示例**：  如果一个节点的权重是5，且从根节点到这个节点的路径有3条边，则这个节点的WL为：
$$  WL = 5 \times 3 = 15$$
##### 带权路径长度总和 (WPL)（Weighted Path Length, WPL）
- **定义**：  带权路径长度总和（WPL）是树中所有节点的带权路径长度的总和。计算公式为：
$$
  WPL=\sum_{i} WL_i
$$

  其中 $WL_i$ 是第 $i$ 个节点的带权路径长度。

- **重要性**：  WPL 是衡量编码效率的重要指标。在哈夫曼树中，WPL 越小，表示整体编码的平均长度越短，压缩效果越好。

- **示例**：
  假设有三个节点，权重和路径长度如下：

| 节点  | 权重  | 路径长度 | WL  |
| --- | --- | ---- | --- |
| A   | 5   | 2    | 10  |
| B   | 3   | 3    | 9   |
| C   | 2   | 1    | 2   |
  则 WPL 的计算为：
$$
  WPL = 10 + 9 + 2 = 21
$$

- **WL** 是指单个节点的带权路径长度，反映了该节点在树中的位置和其权重对编码长度的影响。
- **WPL** 是整个树的带权路径长度总和，反映了整个树的编码效率。对于哈夫曼树，WPL 越小，表示数据压缩效果越好。
---
##### 生成哈夫曼编码

> [!quote] 哈夫曼编码
> 实现无损压缩和恢复
> 是一种可变长度编码方法，常用于对字符进行编码，使得频率较高的字符使用较短的编码，而频率较低的字符使用较长的编码，从而减少整体数据的存储空间。
> __特点__
> - **无前缀编码**：哈夫曼编码是一种无前缀编码，这意味着没有任何一个编码是另一个编码的前缀，从而避免了解码时的歧义。
> - **最优性**：在给定字符频率的情况下，哈夫曼编码可以生成最小的平均编码长度。

- **构建过程**：
    - **统计频率**：首先统计每个字符在文本中出现的频率。
    - **创建节点**：为每个字符创建一个节点，节点的权重即为该字符的频率。
    - **构建优先队列**：将所有节点放入一个优先队列（通常使用小根堆）。
    - **合并节点**：重复以下步骤，直到队列中只剩下一个节点：
        - 从优先队列中取出两个权重最小的节点。
        - 创建一个新节点，其权重为这两个节点的权重之和。
        - 将这两个节点作为新节点的子节点，并将新节点加入优先队列。
    - **树的形成**：最终得到的节点就是哈夫曼树的根节点。
- **编码生成**：
    - 从根节点开始，为每个字符生成编码：向左子树走为“0”，向右子树走为“1”。遍历整棵树，可以为每个字符生成唯一的二进制编码。


##### 建树
对节点按优先度排序 
假设字符及其频率如下：

| 字符  | 频率  |
| --- | --- |
| A   | 5   |
| B   | 9   |
| C   | 12  |
| D   | 13  |
| E   | 16  |
| F   | 45  |

构建哈夫曼树的步骤如下：
1. 将每个字符和频率放入优先队列。
2. 取出频率最小的两个节点（A 和 B）_min_1_ _min_2_，合并成新节点（AB，频率14）。_Union_
3. 继续这一过程，直到所有节点合并成一棵树。_pushback_

最终的哈夫曼编码可能如下：
- A: 000
- B: 001
- C: 01
- D: 10
- E: 11
- F: 1

# 字典树 
字典树（Trie，又称为前缀树或单词树）是一种用于存储字符串集合的树形数据结构，特别适用于搜索和处理字符串的应用。它的主要特点是能够高效地进行前缀匹配和单词查找。

> [!bug] 三大功能 __查找 计数 排序__

### 字典树的基本概念

1. **结构**：
   - 每个节点代表一个字符。
   - 从根节点到某个节点的路径表示一个字符串的前缀。
   - 节点的子节点表示以该字符为前缀的字符串。

2. **节点属性**：
   - 每个节点可以包含多个子节点，通常使用一个数组或哈希表来表示。
   - 节点可能包含一个布尔值，表示是否为某个完整单词的结尾。

### 构建字典树

1. **插入操作**：
   - 从根节点开始，逐个字符插入。
   - 如果字符对应的子节点不存在，则创建一个新的子节点。
   - 最后一个字符的节点标记为单词的结束。

2. **查找操作**：
   - 从根节点开始，逐个字符查找。
   - 如果找到完整的路径并且最后一个节点标记为单词结束，则表示找到该单词。

3. **删除操作**：
   - 逐个字符查找并删除节点。
   - 需要考虑是否删除节点的子节点是否为空，以决定是否需要删除父节点。

### 时间复杂度

- **插入**：O(m)，其中 m 是要插入字符串的长度。
- **查找**：O(m)，其中 m 是要查找字符串的长度。
- **空间复杂度**：取决于存储的字符串集合。

### 应用场景

- **单词自动补全**：根据前缀查找所有可能的单词。
- **拼写检查**：快速查找是否存在某个单词或找到相似单词。
- **IP路由查找**：用于高效的前缀匹配。

### 示例

以下是一个简单的字典树示例，展示如何插入和查找单词。

```plaintext
          (root)
         /   |   \
        a    b    c
       /     |     \
      p      a      a
     / \     |      |
    p   l    t      t
   /     \    |      \
  l       e   e       o
 /         \            \
e           s            g
```

在这个例子中，我们插入了单词 "apple"、 "app"、 "bat" 和 "cat"。通过遍历树，可以快速找到这些单词或它们的前缀。

这个警告是因为你在析构函数中试图使用 `delete[]` 删除一个指针数组 `nextChar`，但是 `nextChar` 是一个在栈上分配的数组，而不是动态分配的。这导致了不匹配的删除操作，从而引发了警告。

### 解释：

1. **数组定义**:
   ```cpp
   TrieTree* nextChar[26];
   ```
   `nextChar` 是一个固定大小的数组，这个数组在 `TrieTree` 的构造函数中被创建，并存储在对象的栈上。

2. **析构函数**:
   ```cpp
   ~TrieTree() { delete[] nextChar; };
   ```
   这里尝试用 `delete[]` 删除一个在栈上分配的数组，这会导致未定义的行为。`delete[]` 只能用于动态分配的内存（即通过 `new[]` 分配的内存）。

### 解决方案：

你可以简单地将析构函数修改为不删除 `nextChar`，因为它不需要被手动删除：

```cpp
~TrieTree() {
    for (int i = 0; i < 26; i++) {
        delete nextChar[i]; // 递归删除子节点
    }
}
```

### 完整的结构体修改：

```cpp
/// @brief 字典树结构体
struct TrieTree {
  TrieTree* nextChar[26];
  int count;

  TrieTree() : nextChar{nullptr}, count(0) {};
  
  // 这里的构造函数应当初始化字符对应的子节点
  TrieTree(char c) : nextChar{nullptr}, count(0) {
    nextChar[c - 'a'] = new TrieTree(); // 使用 'a' 而不是 97
  }

  ~TrieTree() {
    for (int i = 0; i < 26; i++) {
      delete nextChar[i]; // 递归删除子节点
    }
  }
};
```

### 总结

- 不要使用 `delete[]` 来删除在栈上分配的数组。
- 在析构函数中递归删除子节点，以确保内存管理的正确性。
