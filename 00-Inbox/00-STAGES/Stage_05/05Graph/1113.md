# 图 Graph

在计算机科学和数学中，**图(graph)** 是一种用于表示对象之间关系的结构。图由**顶点(vertices)** 和**边(edges)** 组成，顶点表示对象，边表示对象之间的关系。

$G=(V,E)$

1. __依附__ : 边$E_1$ 依附于顶点$V_1$ $V_2$ 
2. __完全图__ : 任意两点相连 无向图边数量 $C_n^2$ 有向图边数量 $A_n^2$
3. __路径__ : 在图中从一个顶点到另一个顶点的边的序列。
	- ==长度==：路径中边的数量。
4. __简单路径__ : 路径中不包含重复的顶点。即每个顶点最多出现一次。
5. __连通__ : 对于无向图，任意两个顶点之间都有路径相连。
	- ==强联通== : 对于有向图，任意两个顶点之间都有路径相连。
6. __连通图__ : 无向图中，任意两个顶点都有路径相连。
	- ==弱连通==：有向图中，如果将所有边视为无向边后，图是联通的。
7.  __子图__: $V^1∈V$  
8. 极大连通图(__连通分量___) ==强连通分量==

> n 顶点的连通图最少有 n-1 条边
> n 顶点的图一定连通 有 $C_n^2 +1$ 条边
##### 1. 依附 (Adjacency)
- **依附矩阵**：用于表示图中顶点之间的连接关系。如果顶点 \(i\) 和顶点 \(j\) 之间有边，则矩阵的相应位置为1，否则为0。
- **邻接表**：每个顶点维护一个列表，列出与其相连的所有顶点，适用于稀疏图。
##### 2. 完全图 (Complete Graph)
- **无向完全图** $C_n^2$：每一对不同的顶点都有一条边。总边数为 $\frac{n(n-1)}{2}$。
- **有向完全图** $A_n^2$：每一对不同的顶点都有两条方向相反的边。总边数为 $n(n-1)$。
##### 其他相关概念
- **环 (Cycle)**：路径的起点和终点相同的情况。
- **树 (Tree)**：一种特殊的连通图，没有环，且有 \(n-1\) 条边（\(n\) 为顶点数）。
- **图的遍历**：常见的遍历方法包括深度优先搜索 (DFS) 和广度优先搜索 (BFS)。

图的基本概念
1. **顶点**：图中的基本单位，通常表示某种实体。
2. **边**：连接两个顶点的线，表示这两个实体之间的关系。
3. **有向图和无向图**：
   - **有向图**：边有方向，表示从一个顶点到另一个顶点的关系。
   - **无向图**：边没有方向，表示两个顶点之间的双向关系。

4. **加权图**：边上有权重，通常表示两个顶点之间关系的强度或成本。
5. **简单图**：没有自环（顶点到自身的边）和多重边（两个顶点之间的多条边）。
6. **多重图**：允许多重边和自环。

图的表示方法
- **邻接矩阵**：一个二维数组，表示顶点之间的连接关系。
- **邻接表**：使用链表或数组，表示每个顶点的相邻顶点。

图的类型
- **连通图**：任意两个顶点之间都存在路径。
- **完全图**：每两个顶点之间都有边相连。
- **树**：一种特殊的无向图，连通且无环。
- **有向无环图（DAG）**：有向图且不存在环。

图的应用
1. **社交网络**：用户作为顶点，朋友关系作为边。
2. **交通网络**：交叉口作为顶点，道路作为边。
3. **网络流**：在网络中传递信息或物资的模型。
4. **推荐系统**：基于用户和物品之间的关系进行推荐。

##### 图的算法
- **深度优先搜索（DFS）**：一种用于遍历或搜索图的算法。
- **广度优先搜索（BFS）**：另一种图遍历算法，通常用于寻找最短路径。
- **Dijkstra算法**：用于加权图中寻找最短路径。
- **Kruskal和Prim算法**：用于求解最小生成树。

图的存储方法主要有以下四种：

### 1. 邻接矩阵（Adjacency Matrix）
- **描述**：使用一个二维数组来表示图中的顶点，数组的行和列分别代表图的顶点。如果存在边 $u\to v$，则在矩阵中设置 `matrix[u][v] = 1`（或边的权重），否则设置为 `0`。
- **优点**：
  - 简单且易于实现。
  - 查找边的时间复杂度为 $O(1)$。
- **缺点**：
  - 占用空间较大，尤其是稠密图，空间复杂度为 $O(V^2)$。
  - 对于稀疏图，许多元素为0，浪费空间。

### 2. 邻接表（Adjacency List）
- **描述**：使用一个数组或链表，其中每个元素是一个链表（或动态数组），表示与该顶点相邻的所有顶点。
- **优点**：
  - 节省空间，尤其适合稀疏图，空间复杂度为 $O(V + E)$。
  - 遍历邻接节点时效率较高。
- **缺点**：
  - 查找特定边的时间复杂度为 $O(V)$（最坏情况下）。

### 3. 边列表（Edge List）
- **描述**：使用一个列表（或数组）来存储图中的所有边，每条边可以表示为一个二元组（或三元组，包含权重）。
- **优点**：
  - 存储简单，适合表示边的数量远小于顶点数量的稀疏图。
  - 易于实现和修改。
- **缺点**：
  - 查找特定边的时间复杂度为 $O(E)$。
  - 难以快速访问特定顶点的邻接边。

### 4. 十字链表（Cross List）
- **描述**：一种改进的邻接表，适用于有向图和带权图，使用两个表分别存储出边和入边的信息。
- **优点**：
  - 对于复杂的图结构，可以更高效地进行遍历和查找。
  - 适合处理稀疏图和复杂的边关系。
- **缺点**：
  - 实现较为复杂，存储开销较大。

### 总结
这四种存储方法各有优缺点，选择合适的存储方式取决于图的性质（稠密或稀疏）、操作需求（查找、遍历等）以及空间效率等因素。
