- 主窗口开启事件循环
- 接收到信号或事件后执行对应槽函数
- 若槽函数阻塞
- 主窗口将无法接收其他事件
- 造成主窗口无响应

> [!abstract] `connect`也会出现阻塞，但有定时
> 若收方滑动窗口不够大，`send`有延迟
> `recv`默认阻塞

- 使用多线程处理，避免主事件循环阻塞

`CreateThread()` winapi 退出不会回收内存块
`_beginthreadex()` 使用CreateThread, CRT library 退出时会回收内存块
`__stdcall` 调用约定 约定栈的回收怎么回收 函数编译之后长什么样子

- 非Qt线程函数创建的线程无法与主控件ui交互

使用Qt 多线程 实现
##### 1. 通过实现QThread子类, 调用`start`, 重写`run`
##### 2. 通过 `QObject` 子类 调用 moveToThread方法 移动到另一个QThread 线程里面实现.
1. 创建`QObject`子类 比如叫`WorkObject`  添加`Q_OBJECT`支持信号槽函数机制
2. 申请一个 `QThread` 对象,将 `WorkObject` 对象`obj.moveToThread(QThread*)`移动到新建的线程
3. `connect` 链接 信号槽函数 主对话框 发送信号 执行 `WorkObject` 对象 的线程函数(模拟发送)
4. 到新建的线程中 执行 模拟发送



*区别 适用场合*
方法1 触发方式 start 执行期间再次运行start*会丢失*
方法2 只要发送信号 一定会去执行 **不会丢失**


> [!abstract] 信号槽第五个参数
> - `Qt::AutoConnection` : *默认使用* 若sender与reciver在同一线程, 使用`Qt::DirectConnection`, 若在不同线程, 使用`Qt::QueuedConnection`
> - `Qt::DirectConnection` : 直接连接, 相当于在发送信号处直接调用槽函数,增加函数栈,槽函数执行完返回发送信号处继续运行. 在sender线程
> - `Qt::QueuedConnection` : 队列执行, 同一个信号发送多次, 槽函数排队进入主事件循环, 逐个执行. 在reciver线程
> - `Qt::BlockingQueuedConnection` : 阻塞队列执行, sender与reciver在不同线程,sender会阻塞,直到槽函数执行完成返回. 若在同一个线程, 会产生死锁
> - `Qt::UniqueConnection` : 与其他连接方式并用, 多次绑定会失效. 若信号绑定多个槽函数,槽函数按绑定顺序排队执行

- 当线程阻塞,信号绑定的槽函数会排队进入主事件循环,依次执行
