> [!example] C/C++ 结构体区别?
>
> 1. C++ 中结构体可以继承，默认是 `public`，且支持构造函数、析构函数等成员函数。
> 2. C++ 中结构体可以定义成员函数，而 C 语言的结构体只能包含数据成员。
> 3. C++ 中结构体无需使用 `typedef` 也能直接使用名称定义变量。
> 4. C++ 结构体可以定义运算符重载、模板函数等复杂操作。
> 5. C 语言中结构体不支持访问修饰符，所有成员默认都是 `public`，不能像 C++ 那样区分 `private` 或 `protected`。
> 6. C++ 中的结构体支持类的所有特性，包括封装性（通过成员函数和访问控制），而 C 语言中的结构体仅作为简单的数据容器使用。

> [!example] 指针和引用的区别?
>
> 1. 指针是变量, 有独立的存储空间, 其值是一个内存地址。引用是变量的别名，必须绑定到已有变量且不占独立空间。
> 2. 指针可以有二级指针（如 `int**`），而引用无法有“二级引用”，它总是指向一个已有对象。
> 3. 定义指针时可以不初始化，而引用在定义时必须初始化，并且一旦绑定，不能改变引用对象。
> 4. 作为函数参数传递时，指针会传递地址，可以修改指针所指向的内容，但指针本身指向哪个地址不会影响原始指针；引用则直接传递原始对象的引用，可以修改原对象的值。
> 5. 指针可以为空（`nullptr` 或 `NULL`），而引用不能为空，始终需要指向某个对象。
> 6. 指针支持算术运算（如 `ptr++`），可以进行内存跳转；而引用不支持指针运算，它只充当对某个对象的别名。
> 7. 指针的生命周期可以独立于它所指向的对象，而引用的生命周期与它所引用的对象绑定在一起，不能独立于被引用的对象存在。

> [!example] `const` 修饰成员
>
> 1. `const` 修饰成员变量表示该变量在对象生命周期内不可修改。通常与 `mutable` 配合使用，允许在 `const` 成员函数中修改 `mutable` 变量
> 2. `const` 修饰成员函数时，表示该函数不会修改对象的状态（成员变量）。即该函数内部只能调用其他 `const` 成员函数
> 3. `const` 修饰指针时，`const` 可能修饰指针本身或指向的对象。`const T*` 表示指针指向的内容不可修改，而 `T* const` 表示指针本身不可修改
> 4. `const` 可以修饰类中的引用类型成员，确保该引用在整个对象生命周期内不会改变引用的对象

> [!example] `static`
> 1. `static` 修饰成员变量时，表示该变量是类的所有对象共享的，而不是每个对象有独立的副本。所有对象共享同一份内存。
> 2. `static` 修饰成员函数时，表示该函数可以在不创建对象的情况下调用，且不能访问非静态成员变量和成员函数。
> 3. `static` 修饰局部变量时，表示该变量的生命周期延续整个程序运行周期，尽管它只在函数调用时可见。
> 4. `static` 在类外定义时，限制了该成员函数或变量的作用域，仅在当前源文件中有效，防止外部链接。

> [!example] `virtual`
>
> 1. `virtual` 修饰成员函数时，表示该函数支持多态（动态绑定），允许通过基类指针或引用调用派生类重写的函数。
> 2. `virtual` 构造函数在 C++ 中是不允许的，但析构函数可以是虚函数，用来确保派生类对象正确析构。
> 3. 当使用 `virtual` 函数时，编译器会根据对象的动态类型来决定调用哪个版本的函数，而不是编译时的类型。
> 4. 如果派生类没有重写基类的虚函数，调用基类的虚函数。
> 5. 虚函数表（VTable）是由编译器生成的，它维护着虚函数的指针，以支持运行时多态。

> [!example] `inline`
>
> 1. `inline` 修饰函数时，表示编译器会尽量将函数体内联到调用处，避免函数调用的开销。
> 2. `inline` 对小函数特别有效，减少函数调用的栈操作，可以提升程序的性能。
> 3. `inline` 并不是强制的，编译器可以根据具体情况决定是否内联函数，编译器通常会忽略过于复杂的函数。
> 4. 在类定义内定义的成员函数默认是 `inline` 函数，编译器会尝试内联这些函数。
> 5. 使用 `inline` 可以减少代码的执行时间，但如果滥用可能导致代码膨胀，增加程序的大小。

> [!example] `friend`
>
> 1. `friend` 关键字允许其他类或函数访问当前类的私有和保护成员
> 2. `friend` 修饰的函数可以访问类的非公有成员，打破了封装性限制，通常用于类之间的协作
> 3. `friend` 函数不是类的成员函数，但可以像成员函数一样访问类的私有成员
> 4. `friend` 类可以访问另一个类的私有和保护成员，适用于两个类密切合作时
> 5. `friend` 关键字的作用仅限于类或函数的定义中，它不会改变类的访问控制


> [!example] 纯虚函数
>
> 1. 纯虚函数是没有函数体的虚函数，通常用来定义接口或抽象行为。它在基类中声明为 `virtual void func() = 0;`，表示派生类必须重写该函数。
> 2. 纯虚函数使得类成为抽象类，无法直接实例化对象。只有派生类实现了所有的纯虚函数，才能实例化该类。
> 3. 纯虚函数可以有默认参数，但派生类必须实现该函数，并提供合适的实现。
> 4. 纯虚函数不必在基类中定义函数体，编译器会在类的构造过程中检查该函数是否被派生类重写。
> 5. 纯虚函数可以在派生类中重写为非虚函数，但为了保持多态性，通常在派生类中仍然定义为虚函数。

> [!example] 抽象类, 接口类(所有成员函数全是纯虚函数)
>
> 1. 抽象类是包含至少一个纯虚函数的类，不能被实例化。它的目的是为派生类提供一个接口或默认实现。
> 2. 接口类是一种特殊的抽象类，所有成员函数都是纯虚函数，且通常不包含成员变量。接口类的目的是为多个类提供共同的操作接口。
> 3. 接口类中的纯虚函数通常没有任何实现，派生类需要提供具体的实现来完成接口功能。
> 4. 接口类可以通过继承和多态实现不同类的相同接口，例如 `class IShape { virtual void draw() = 0; };`。
> 5. C++ 中没有单独的接口机制，接口类是一种约定，通常所有函数都定义为纯虚函数。

> [!example] 重载操作符
>
> 1. 操作符重载允许我们为内置操作符提供自定义行为，例如重载 `+`、`-`、`[]` 等操作符，使其适应自定义类型。
> 2. 操作符重载函数通常是成员函数或非成员函数（友元函数），成员函数接受一个隐式的 `this` 指针，非成员函数接受两个显式参数。
> 3. 不是所有操作符都能被重载，例如 `::`（作用域解析符），`sizeof`，`typeid` 等不能被重载。
> 4. 操作符重载需要保持操作符的基本语义，例如重载 `+` 操作符时应保持其“加法”的语义，不能做不符合直觉的操作。
> 5. 重载操作符应当有合理的副作用（如 `=` 赋值操作符，通常需要执行深拷贝或资源管理）。

> [!example] 空类包含的函数
>
> 1. 即使是一个空类（没有成员变量和成员函数），它仍然会有一个隐式的构造函数、析构函数、拷贝构造函数和赋值操作符
> 2. 空类的构造函数和析构函数是默认的，编译器自动生成。如果定义了其他构造函数，编译器将不再自动生成默认构造函数
> 3. 如果空类有虚函数，那么它会有一个虚函数表（VTable），即使没有显式的成员函数
> 4. 空类通常用于标识类型（例如空接口类）或占位符，以便在类设计时留下空间(1)

> [!example] 不能修饰虚函数的关键字
>
> 5. 关键字 `const` 不能修饰虚函数，因为 `const` 表示不修改成员变量的状态，而虚函数需要具备动态多态性，因此不能限制其可修改性
> 6. 关键字 `static` 不能修饰虚函数，因为虚函数依赖于对象的动态类型来进行动态绑定，而静态函数与对象实例无关
> 7. 关键字 `friend` 不能修饰虚函数，`friend` 是用来定义访问权限的，而虚函数是为实现多态性设计的，二者在目的上不兼容
> 8. `inline` 也不适合修饰虚函数，因为虚函数在运行时决定调用哪个函数，而内联函数在编译时直接展开，不支持动态多态

> [!example] 类之间关系(横纵)
> *横向*:
> - **组合 (Composition)** : 组合表示强拥有关系，一个类包含另一个类的对象，且被包含对象的生命周期由包含类管理。当包含类对象销毁时，被包含的对象也会被销毁
> - **依赖 (Dependency)** : 依赖表示一个类在某一时刻使用另一个类，通常出现在方法参数、返回值类型或局部变量中。被依赖类的生命周期不受依赖类影响，依赖关系一般是临时性的
> - **关联 (Association)** : 关联表示类之间的交互关系，通常通过指针或引用传递。类之间的生命周期独立，关联的对象不由当前类管理，通常表现为对象间的弱关系
> - **聚合 (Aggregation)** : 聚合是一种“整体-部分”关系，其中部分对象可以独立于整体存在。与组合不同，聚合关系中的部分对象的生命周期不依赖于整体类，它们可以在多个类中共享
> 
> *纵向*: 
> - **继承 (Inheritance)** : 继承是一种“是一个”的关系，表示子类继承父类的属性和方法，从而实现代码复用。子类可以扩展或修改父类的行为，继承支持单继承和多继承，并能实现多态
> - **多态 (Polymorphism)** : 多态允许通过父类指针或引用调用子类重写的方法，使得同一接口可以表现出不同的行为，增强了程序的灵活性和可扩展性。它通常通过虚函数和方法重写实现 


> [!example] 继承方式

| 继承方式        | 基类`public`  | 基类`protected` | 基类`private` |
| ----------- | ----------- | ------------- | ----------- |
| `public`    | `public`    | `protected`   | 不可访问        |
| `protected` | *protected* | `protected`   | 不可访问        |
| `private`   | `private`   | `private`     | 不可访问        |

> [!example] 多态
> *允许程序在运行时根据对象的实际类型来决定调用哪个函数*
> 1. 静态多态: 函数重载和运算符重载实现. 速度快,效率高,但缺乏灵活性
> 2. 动态多态: 代码不变功能可变(运行时创建对象, 虚表指针->虚表-> 确定调用; 根据对象行为调用某一个具体的函数)
>    要点:
> 	- 基类声明虚函数, 会有一个虚函数表. 派生类继承虚函数表
> 	- 派生类重写虚函数, *覆盖*虚函数表中虚函数地址.
> 	- 基类指针指向派生类对象, 派生类对象运行时构建, 前4(8)字节存储虚指针指向虚函数表.
> 	- 基类指针调用虚函数, 通过派生类对象虚指针找到虚函数表, 遍历虚函数表, 找到对应虚函数并执行, 即完成多态
> 3. 优缺点

`[!!|message-square|comment:如何判断是否为多态|var(--color-cyan-rgb)]` : 首先看基类指针(引用)是否调用了虚函数. 其次参看指向的派生类对象是否重写了该虚函数. 若未实现, 则调用基类虚函数.

> [!example] 成员函数的重载，重写以及隐藏
> 4. 成员函数重载(Overloading): 即函数重载
> 5. 成员函数重写(Overriding): 在派生类中重新定义基类中的虚函数，以提供特定的实现。通过基类指针或引用调用派生类的重写函数实现多态性
> 6. 成员函数*隐藏(Hiding)*: 如果在派生类中定义了与基类同名的*非虚函数*（参数列表不同），则基类中的所有同名函数都会被隐藏. 避免名称冲突，但可能会导致基类的同名函数无法访问

> [!abstract] 什么是*协变*?
> 在面向对象编程里，协变主要用于函数返回类型和数组类型
> - _函数返回类型协变_ : 在继承体系中，当子类重写父类的虚函数时，*返回类型可以是父类返回类型的派生类类型*。这种协变要求函数必须是虚函数，且函数名和参数列表要相同。例如，父类虚函数返回基类指针或引用，子类重写的函数可返回派生类指针或引用
> - _数组协变_ : 在某些语言中数组是协变的，意味着如果 `Derived` 是 `Base` 的子类，那么 `Derived[]` 可以隐式转换为 `Base[]` 。不过这种协变可能会带来运行时错误

   `{cpp}void** vtable = (void**) *(void**)pbase;`
2. 基类指针指向为(fb48), 转为`{c++}void**`后解引用才能得到一个指向虚表的指针(bcf8)(即虚表地址), 否则直接解引用会得到基类.

# C++11
##### `auto` 关键字作用:
- 让编译器编译时就推导出变量的类型, 可根据等号右边的类型推导出相应类型

##### `decltype` 作用:
- 用于推导表达式的类型, 只用于分析类类型, 不做运算
- 若推导表达式, 和表达式类型相同. 若为函数, 与返回值相同. 若为左值, 推到为左值引用

```cpp title:"auto 与 decltype组合使用"
template <typename T, typename U>
auto add(T t, U u) -> decltype(t + u) {
  return t + u;
}
```
- 若无`auto` 而是直接返回推导, 会编译不过. 因为t和u类型未确定
- `auto`关键字用于推导函数返回类型，紧接着是`->`，它明确指定了返回类型的推导方式。这里使用了**尾返回类型**（trailing return type）。通过`-> decltype(t + u)`明确了返回类型是`decltype(t + u)`，编译器可以通过这个提示推导出具体的返回类型
- `auto`用来推导函数的返回类型，而`-> decltype(t + u)`告诉编译器返回类型应该是`decltype(t + u)`
- 通过`->`后置返回类型，编译器可以正确地在函数定义处推导出返回类型，而不需要在函数签名时进行直接推导

##### C++11之前不允许两个`>`同时出现, 会被认为是右移操作符`>>`

##### C++11引入`{cpp}using` 可以轻松定义类型别名, 而不是繁琐的`{c}typedef`

# 四种类型转换

- / 为什么C++不沿用C中的强制类型转换, 而提出这四种类型转换? 
- C++ 在设计时强调类型安全, 但C中类型转换可谓无所不能, 若继续沿用, 会破坏C++的类型系统, 同时留下安全隐患
- 此外, 四种类型转换有不同使用场景和功能, 相较于C的强制类型转换更强大

##### `{cpp}static_cast<"类型">("待转换量")` 静态转换 
- 编译时确定相关内容的转换. 用于基本类型转换, 以及类之间的安全转换,例如子类对象地址转换为父类指针
- 而不相关类型不能转换, 例如`int*`与`int`

##### `{cpp}dynamic_cast<"类型">("待转换量")` 
- 只适用于有继承关系的两个类
- 继承向上转换效果等同于`static_cast`, 向下转换会检验即是安全的. 
- 若父类指针指向子类对象, 而转出类型就是该子类类型, 可以正常转换
- 若父类指针指向的不是转出类型的子类对象, 返回结果为空
- 同时, 向下转换, 父类必须包含虚函数, `static_cast`无这个要求

> [!example] `static_cast` `与dynamic_cast` 区别总结
> - `static_cast` 支持相关数据类型转化 `dynamic_cast`不支持
> - 对于继承关系中的转换,`static_cast`可以向上和向下转换, dynamic_cast可以交叉转换
> - `dynamic_cast`向上转换与`static_cast`一致, 向下转换, 父类要有虚函数, 并且存在检验机制.

##### `{cpp}const_cast<"类型">("待转换量")` 
- 去常转换
- `const int -> int`
- `volatile int -> int`
- volatile : 防止修饰变量编译优化, 避免修饰变量缓存和内存不一致(每次到其地址读取,先写后读)
##### `{cpp}reinterpret_cast<"类型">("待转换量")` 
- 重解释类型转换
- C++ 强制类型转换符
- 相当于`(type)` ~~无所不能~~ 
- 有安全隐患

# 右值引用

> [!abstract] 什么是左值和右值?
> - **左值**：左值是指可以在赋值语句的左侧的表达式，表示一个持久的对象. 具有持久的内存地址, 可以被修改, 可以取地址
> - **右值**：右值是指不能在赋值语句的左侧的表达式，表示一个临时的值. 没有持久的内存地址，通常是临时对象, 通常用于表达式的计算结果, 不可取地址

> [!abstract] 什么是纯右值和将亡值?
> - *纯右值*: 运算表达式产生的临时变量, 不和对象关联的原始字面量, 非引用返回的临时变量, lambda表达式等都是纯右值.
> - *将亡值*: 即将要销毁的值

临时对象是右值对象

* **左值引用** `T&`：只能绑定到左值(有名称的对象)
* **右值引用** `T&&`：只能绑定到右值(没有名称的临时对象). 与 **完美转发**(Perfect Forwarding)相关, 通过 **引用折叠**(reference collapsing)规则实现了这种灵活性

 *常引用*: 和右值引用一样都能接收右值，并且它们都通过引用的方式延长右值的生命周期，直到引用的生命周期结束. 但是 **常引用**不能修改绑定的右值。即使是右值，它也会被视为一个常量，无法修改. **右值引用**：可以修改绑定的右值，通常用于实现“移动语义”

> [!example] 移动语义 & 完美转发
> *移动语义*: 转移资源所有权, 被移动的对象在移动后资源为空
> *完美转发*: 将参数完全转发给调用对象, 将区分右值引用与常引用

- / `{cpp}std::move` 将左值转换为右值. 其实是在编译期, 告诉编译器返回值是一个右值, 在运行期不做任何时


`[!!|message-square|comment:右值引用其他作用|var(--color-cyan-rgb)]`  除了作为引用基本的, 延长绑定对象生命周期外, 还包括 
1. 实现移动语义与完美转发, 消除两个对象交互时不必要的拷贝构造, 提高程序性能 
2. 能够更明确地定义泛型函数 
3. 抹去了临时对象的维护(创建~~?~~和销毁)对性能的影响

`[!!|dice|roll:右值引用用法举例|214,153,182]` `{cpp}std::vector`, 如果需要创建`vector`临时量或者从函数中返回`vector`, 只能通过创建一个新的并拷贝所有存于右值中的数据来存储数据. 然后这个临时的`vector`则会被销毁, 同时删除其包含的数据. 
- 有了右值引用, 返回值就能通过转移构造器简单地将该右值中C式数组的指针复制到新的`vector`, 然后将该右值清空. 
- 这里没有数组拷贝, 并且销毁被清空的右值也不会销毁保存数据的内存. 返回的`vector`的函数现在只需要返回一个`{cpp}std::vector<>&&`

# `lambda`表达式

允许在函数内部定义*匿名函数*，可以在需要时直接传递或调用，适用于临时的函数对象，简化代码，尤其在STL算法中非常常见

##### 1. 基本语法：
```cpp
[捕获列表](参数列表) -> 返回类型 {
    // 函数体
}
```
* **捕获列表**：指定lambda函数如何访问外部变量
* **参数列表**：定义lambda函数的参数（可选）
* **返回类型**：可选，指定返回值的类型，如果推断不了，可以手动指定
* **函数体**：lambda表达式的主体部分，定义了执行的内容

##### 2. 捕获列表：
捕获列表用于指定lambda函数如何访问外部作用域中的变量。它有几种写法：
* **`[]`**：不捕获任何变量
* **`[=]`**：按值捕获所有外部变量
* **`[&]`**：按引用捕获所有外部变量
* **`[var]`**：按值捕获指定的`var`变量
* **`[=, &var]`**：按值捕获所有变量，但按引用捕获`var`
* **`[this]`**：捕获当前对象的`this`指针

##### 3. `mutable`关键字：

`mutable` 关键字是lambda表达式的一个特性，表示即使lambda按值捕获了外部变量，lambda函数体内仍然可以修改这些变量

通常，lambda表达式按值捕获外部变量时，这些变量的值会被复制到lambda中，并且默认情况下，lambda无法修改这些复制的变量。然而，如果在lambda的定义中使用了`mutable`关键字，就可以修改这些按值捕获的外部变量

* **关键点**：虽然`x`被按值捕获，但由于`mutable`关键字，它在lambda内部被允许修改。修改只会影响lambda函数内部的`x`，外部的`x`值保持不变
主要用于:
* 需要修改lambda内部捕获的外部变量，但又希望捕获时不通过引用
* 在需要为lambda定义一些状态时，且该状态是临时的、仅供lambda函数内部使用

##### 4. 返回类型推导：
- 在C++14及以后的版本中，lambda表达式的返回类型可以自动推导，无需手动指定

# 设计模式
## 设计原则
- 低耦合, 高内聚: 减少依赖,羁绊. 职责尽量单一

> [!example] 七个设计原则?
> - 单一职责原则(SRP) ：功能单一, 方便组合和使用. 
> - 开闭原则(OCP) ：类、模块、函数等应该对扩展开放，对修改关闭
> - 里氏替换原则(LSP) ：子类可以替换其父类并且出现在父类能够出现的任何地方(返回值, 参数). 
> - 接口隔离原则(ISP) ：使用多个隔离接口. 如订单系统中, 订单类继承三个接口, 三个接口指针指向订单类对象, 从而实现接口隔离.
> - 依赖倒置原则(DIP) ：面向接口编程. 如网络中, 写一个接口, 核心类调用接口完成网络各种功能, 一旦写好, 不再需要改子类实现.
> - 迪米特法则(LoD) ：一个对象应该对其他对象有最少的了解，即一个类应该尽量减少与其他类的交互。降低类之间的耦合度，使系统的各个模块相对独立，提高系统的可维护性和可扩展性
> - 合成复用原则(CRP) ：尽量使用对象组合/聚合，代替继承. 降低类之间的耦合度，使系统更加灵活，提高代码的复用性

# 四种智能指针

##### `{cpp}std::auto_ptr`

- 一个提供严格所有权语义的简单智能指针
- 标准规定:
<pre> 一个 auto_ptr 拥有它所指向的对象。复制 auto_ptr 会复制指针并将所有权转移至目标。<br> 如果多个 auto_ptr 同时拥有同一个对象，则程序的行为未定义. <br> auto_ptr 的用途包括为动态分配的内存提供临时的异常安全性、将动态分配的内存的所有权传递给函数以及从函数返回动态分配的内存.<br> auto_ptr 不符合标准库<a href="https://gcc.gnu.org/onlinedocs/libstdc++/libstdc++-html-USERS-4.0/tables.html#65">容器</a>元素的 <a hred="https://en.cppreference.com/w/cpp/named_req/CopyConstructible">CopyConstructible</a> 和 <a href="https://en.cppreference.com/w/cpp/named_req/CopyAssignable">Assignable</a> 要求，因此使用 auto_ptr 实例化标准库容器会导致未定义的行为.
</pre>
- *@deprecated* 在 C++11 中已弃用，自 C++17 起不再符合标准. 改用 `unique_ptr`

##### `{cpp}std::unique_ptr`

- 用于单个对象的 `std::unique_ptr` 
- 用于管理资源唯一所有权的仅移动智能指针

##### `{cpp}std::shared_ptr`

- 具有引用计数复制语义的智能指针
- `shared_ptr` 对象要么为空，要么 _拥有_ 传递给构造函数的指针
- `shared_ptr` 的副本共享同一指针的所有权. 
- 当拥有该指针的最后一个 `shared_ptr` 被销毁或重置时，所拥有的指针将被释放, 通过 `delete` 或调用传递给构造函数的自定义删除器*仿函数*
- `shared_ptr` 还存储另一个指针，该指针通常（但不总是）与它拥有的指针相同. 可以通过调用 `get()` 成员函数来检索存储的指针. 
- `shared_ptr` 的相等和关系运算符仅比较 `get()` 返回的存储指针，而不是所拥有的指针.
- 要测试两个 `shared_ptr` 对象是否共享同一个指针的所有权，参阅 `std::shared_ptr::owner_before` 和 `std::owner_less`

 `[!!danger:线程安全问题]` 使用空间多线程不能保证安全. 引用计数+1 -1可以保证线程安全 
 
##### 循环引用
`std::shared_ptr` 的循环引用问题发生在两个或多个对象之间相互持有 `shared_ptr`，导致它们的引用计数永远不会归零。具体来说，`shared_ptr` 会管理对象的生命周期，直到所有指向该对象的 `shared_ptr` 都被销毁为止。然而，如果两个对象 A 和 B 互相持有对方的 `shared_ptr`，它们的引用计数永远不会变为零，导致它们即使超出了作用域，也无法正确释放内存，产生内存泄漏。这种情况被称为循环引用

为了解决这个问题，可以使用 `std::weak_ptr`，它是一种不增加引用计数的智能指针，用来打破循环引用。`weak_ptr` 允许一个对象观察另一个对象，但不会干扰其生命周期管理，从而避免了引用计数循环增加的问题

##### `{cpp}std::weak_ptr`
- `weak_ptr` 是弱引用计数的共享类型智能指针, 通过`shared_ptr`间接地指向堆区空间,当指向堆区空间时,引用计数 不会+1. 同理 不指向 或回收的时候 引用计数也不会-1
- 使用堆空间 要通过`shared_ptr`来调用,方法 使用`lock()`来获取`shared_ptr`
- 与原始指针不同的是，`weak_ptr` 在其指向的对象被销毁后不会变为“悬空”. 相反，`weak_ptr` 会变为“过期”，并且无法再转换为拥有被释放指针的 `shared_ptr`，因此无法在指向的对象被销毁后意外访问它
- 一个由 `shared_ptr` 拥有的指针的非拥有的观察者 . 意思是观察对象为 一个`shared_ptr`拥有的指针, 但无该指针的立即使用权


##### 手写实现`std::shared_ptr`
- **引用计数如何实现?**: 关于 引用计数 和空间 是如何共享的? 
	- 每个空间可以定义一个*控制器* 他有2个成员: 一个是指针 指向堆区对象. 一个是引用计数
	- `shared_ptr` 通过指向这个控制器,完成共享. 空间通过控制器的指针间接访问,通过控制器里面的计数,读出当前的引用计数.

```cpp title:"manual write std::shared_ptr"
namespace mine {  
  template <class T>  
  class shared_ptr { // * ---------------- mine::shared_ptr<T> Declaration  
  private:  
    struct pMAPcnt {  
      T* pointer;  
      std::atomic<int> count;  
  
      friend class shared_ptr<T>;  
  
      pMAPcnt(T* _t);  
      ~pMAPcnt();  
    };  
  
  private:  
    pMAPcnt* m_obj = nullptr;  
  
  public:  
    shared_ptr(T* _t);  
    shared_ptr(const shared_ptr<T>& other);  
    ~shared_ptr();  
  
    T* get();  
    T* operator->();
    const int use_count();  
    shared_ptr& operator=(const shared_ptr<T>& other);  
  };  

  
  // * =================================================== mine::shared_ptr<T> Implementaion  
  
  template <class T>  
  shared_ptr<T>::pMAPcnt::pMAPcnt(T* _t) : pointer(_t), count(1) {}  
  
  template <class T>  
  shared_ptr<T>::pMAPcnt::~pMAPcnt() { delete pointer; }  
  
  template <class T>  
  shared_ptr<T>::shared_ptr(T* _t) { m_obj = new pMAPcnt(_t); }  
  
  template <class T>  
  shared_ptr<T>::shared_ptr(const shared_ptr<T>& other) {  
    this->m_obj = other.m_obj;  
    ++(this->m_obj->count);  
  }  
  
  template <class T>  
  shared_ptr<T>& shared_ptr<T>::operator=(const shared_ptr<T>& other) {  
    if (&other == this) {  
      return *this;  
    }  
  
    // 临时保存旧对象  
    pMAPcnt* old_obj = m_obj;  
  
    // 复制目标对象  
    this->m_obj = other.m_obj;  
    ++(this->m_obj->count);  
  
    // 更新旧对象  
    if (old_obj) {  
      --(old_obj->count);  
      if (old_obj->count == 0) {  
        delete old_obj;  
      }  
    }  
  
    return *this;  
  }  
  
  template <class T>  
  const int shared_ptr<T>::use_count() { return m_obj ? m_obj->counta.load() : 0; }  
  
  template <class T>  
  T* shared_ptr<T>::get() { return m_obj ? m_obj->pointer : nullptr; }  
  
  template <class T>
  T* shared_ptr<T>::operator->() { return m_obj ? m_obj->pointer : nullptr; }

  template <class T>  
  shared_ptr<T>::~shared_ptr() {  
    if (m_obj && --(m_obj->count) == 0) {  
      delete m_obj;  
    }  
  }  
  
};  // namespace mine
```

###### 懒汉式 Lazy Initialization
- 程序开始什么都没有. 延迟加载. 调用接口创建对象. *得自己保证线程安全*
```cpp
class Singleton {  //! 饿汉式
 private:
  // 私有构造函数
  Singleton()                            = default;
  Singleton(const Singleton&)            = delete;
  Singleton& operator=(const Singleton&) = delete;

 static Singleton* instance;
 static std::once_flag _flag;

 public:
  static Singleton* getInstance() {// ! 回收考虑判断两次
  
    //! 1. 线程不安全
    if(!instance){
        instance=new Singleton();
    }
    return instance;

    //? 2. 加锁
    // 效率问题: 首次调用锁保证并发不会多创建,但是后续调用每次上锁解锁, 增加程序运行开销
    lock.lock();
    if (!instance) {
      instance = new Singleton();
    }
    lock.unlock();
    return instance;

    //? 3. double check
    // 首次判断是否已创建单例, 没有再上锁, 后续调用单例对象即可不上锁
    if (!instance) {
      lock.lock();
      if (!instance)
        instance = new Singleton();
      lock.unlock();
    }
    return instance;

    //* 4. C++ 11 call_once
    std::lock_guard
    std::call_once(_flag, []() { instance = new Singleton(); });
    return instance;
  }
};
/// @brief Lazy Initialization
/// *懒汉式. 开始什么都没有.
Singleton* Singleton::instance = nullptr;
std::once_flag Singleton::_flag;
```


**智能指针**

```cpp
class Singleton {  //! 饿汉式
 private:
  //* 定义删除器(仿函数)
  struct deleter {
    void operator()(Singleton* ins) { delete ins; }
  };

  // 私有构造函数
  Singleton()                            = default;
  Singleton(const Singleton&)            = delete;
  Singleton& operator=(const Singleton&) = delete;

  static std::unique_ptr<Singleton, deleter> instance;
  static void destroyInstance() {
    // ! 析构私有. 
    //* 使用删除器
    if(instance.get()){
        instance.reset();
    }
  }

 public:
  static Singleton& getInstance() {
    if(!instance.get()){
        std::lock_guard<std::mutex> guard(lock);
        if (!instance.get())
          instance.reset(new Singleton());
    }
    return *instance.get();
  }
};
/// @brief Lazy Initialization
/// *懒汉式. 开始什么都没有.
std::unique_ptr<Singleton, Singleton::deleter> Singleton::instance = nullptr;
```

# 多继承 & 虚继承
- 普通继承, 子类虚表是从父类拷贝而来. 此时子类新增加的虚表会添加到这个来自父类的虚表中
- 在多继承中, 若子类新增虚函数, 应当存到第一个父类的虚表中. 
- 若父类声明有相同虚函数, 若子类重写该虚函数, 会将第一个父类虚表中的值覆盖. 
## 菱形继承
- *定义*: 两基类有相同基类. 会造成空间冗余以及**继承向上的二义性**, 因此不通过编译
##### 解决方法: 虚继承
- 继承方式声明为`{cpp}virtual public`等
特性:
1. 基类与第一派生类在空间上是一种倒置关系
2. 第一派生类特有的虚函数, 会有自己的虚表而不是覆盖基类的虚表. 同时会有自己的虚指针, 即两个虚表
3. *子类存在指向虚基类(基类)的虚基表, 虚基表里面内容是指向自己及虚基类的地址偏移量, 子类会有虚基表指针vbptr*
4. 对于虚基类的初始化由第二派生类负责

###### derived 非虚继承
- 空间从上到下`Base1 Base2 derived Base`

###### derived 虚继承
- 空间从上到下`derived Base Base1 Base2`

## 4. 仿函数 functor

 ##### `[!!example:什么是仿函数?]`
- 仿函数（Functor / Function Object）：重载了 `operator()` 的类或结构体
- 本质上就是一个可调用对象，可像普通函数一样被“()”调用

*关键要点*:
- 仿函数就是重载 `operator()` 的类/结构体
- 为了与 STL 适配器（binders）兼容，重载函数应声明为 `const`
- 继承 `binary_function` / `unary_function`，可以获得统一的类型接口
- 使用 STL 预定义仿函数（如 `std::less`）可避免重复造轮子

#####  `[!!flag:为什么使用仿函数?]`
1. 灵活性高
2. 可以作为模板参数，支持类型识别
3. 执行效率高，往往比普通函数或函数指针更快
4. 在 STL 算法中，能够通过不同的行为定制算法逻辑，而无需修改算法本身

```cpp title:"仿函数的基本定义与示例"
// 二元比较仿函数示例
struct IntLess {
    bool operator()(int left, int right) const {
        return left < right;
    }
};
```

- `operator()` 一般定义为 `const`，以便对 `const` 对象也可调用
- 可以写成 `inline`，提示编译器内联

##### STL 中预定义的仿函数

- 定义在 `<functional>` 头文件中
- 常见算术、比较、逻辑运算符的封装，如：
    - `std::less<T>` （对应 `<`）
    - `std::greater<T>` （对应 `>`）
    - `std::plus<T>` （对应 `+`）
    - `std::multiplies<T>` （对应 `*`）  
        ……

```cpp
template<class _Ty>
struct less : public binary_function<_Ty, _Ty, bool> {
    bool operator()(const _Ty& a, const _Ty& b) const {
        return a < b;
    }
};
```

##### `binary_function` 与 `unary_function`

- 提供类型成员定义，方便在模板和适配器中统一使用

```cpp title:"binary_function<Arg1, Arg2, Result> 定义："
    template<class Arg1, class Arg2, class Result>
    struct binary_function {
        typedef Arg1 first_argument_type;
        typedef Arg2 second_argument_type;
        typedef Result result_type;
    };
```

```cpp title="unary_function<Arg, Result> 定义类似："
    template<class Arg, class Result>
    struct unary_function {
        typedef Arg argument_type;
        typedef Result result_type;
    };
```


**自定义仿函数规则**

1. 继承自 `unary_function` 或 `binary_function`（用于与 STL 适配器兼容）
2. 重载 `operator()`，并加上 `const` 修饰
3. 可根据需要声明为 `inline`

示例：

```cpp
template<typename T1, typename T2>
struct func_equal
  : public binary_function<T1, T2, bool>
{
    bool operator()(T1 a, T2 b) const {
        return a == b;
    }
};
```

## 5. 适配器(配接器) adapter


适配器就是用来“改造”其他组件接口的工具，分为三大类：

1. 容器适配器（Container Adapters）
2. 迭代器适配器（Iterator Adapters）
3. 函数适配器（Function Adapters）

## `[!!emergency:何时使用适配器?]`

- **容器适配器**：当只需栈、队列、堆抽象接口时，不要直接用 `vector`/`deque`/`list`。
- **迭代器适配器**：需要反向遍历、将输出插入到容器时，用反向/插入/流迭代器。
- **函数适配器**：在算法中需要把通用函数对象改为一元谓词、取反、绑定参数、用函数指针等场景。
- 在 C++11 及以后，`std::bind`、`std::function`、`lambda` 已大大简化函数适配器的使用。

---

##### 5.1 容器适配器

- **作用**：在内部封装一个底层容器（默认是 `deque`），对外只暴露有限的接口，屏蔽底层容器的其他功能
- **三大类型**：
    1. `std::stack<T, Container = deque<T>>`
        - 接口： `push()`, `pop()`, `top()`, `empty()`, `size()`
        - LIFO（后进先出）
    2. `std::queue<T, Container = deque<T>>`
        - 接口： `push()`, `pop()`, `front()`, `back()`, `empty()`, `size()`
        - FIFO（先进先出）
    3. `std::priority_queue<T, Container = vector<T>, Compare = less<T>>`
        - 接口同 `stack`/`queue`，额外提供 `top()` 为最大（或最小）元素
        - 可指定比较器，实现最大堆/最小堆


---

##### 5.2 迭代器适配器

- **作用**：在已有迭代器基础上“添加”新功能或改变遍历方向
- **常见类型**：
    1. `std::reverse_iterator<Iterator>`
        - 反向遍历：`rbegin()`, `rend()`
    2. 插入迭代器
        - `std::back_insert_iterator<Container>`（`back_inserter`）
        - `std::front_insert_iterator<Container>`（`front_inserter`）
        - `std::insert_iterator<Container>`（`inserter`）
        - 将写操作定向到容器的指定位置
    3. 流迭代器
        - `std::istream_iterator<T>` / `std::ostream_iterator<T>`
        - 可将输入/输出流当作序列读写

    ```cpp title:"示例:"
    // reverse_iterator
    std::vector<int> v = {1,2,3};
    for (auto it = v.rbegin(); it != v.rend(); ++it)
        std::cout << *it; // 输出 3 2 1
    
    // back_inserter
    std::vector<int> a = {1,2}, b;
    std::copy(a.begin(), a.end(), std::back_inserter(b));
    // b == {1,2}
    
    // istream_iterator
    std::istream_iterator<int> in_it(std::cin), eof;
    std::vector<int> nums(in_it, eof);
    ```

##### 5.3 函数适配器

- **作用**：将已有的函数对象或函数指针“改造”为新的函数对象（改变参数个数、顺序，或取反等）
- **常见类型**（位于 `<functional>`）：
    1. **否定器**
        - `std::not1(UnaryPredicate)`
        - `std::not2(BinaryPredicate)`
        - 生成对原谓词逻辑取反的新谓词
    2. **绑定器**
        - `std::bind1st(BinaryFunction, value)` → 绑定第一个参数，生成一元函数
        - `std::bind2nd(BinaryFunction, value)` → 绑定第二个参数
        - C++11 后推荐 `std::bind`
    3. **函数指针适配器**
        - `std::ptr_fun(FunctionPointer)` → 将普通函数指针包装为函数对象
        - `std::mem_fn`, `std::bind` / `std::placeholders`
    4. **成员函数适配器**（旧）
        - `std::mem_fun`, `std::mem_fun_ref`
 
    ```cpp title:"示例:"
    #include <functional>
    #include <algorithm>
    #include <vector>
    #include <iostream>
    
    std::vector<int> coll = {10, 42, 7, 42, 99};
    
    // bind2nd + greater<int>()，查找第一个 > 42
    auto it = std::find_if(
        coll.begin(), coll.end(),
        std::bind2nd(std::greater<int>(), 42)
    );
    if (it != coll.end())
        std::cout << *it; // 输出 99
    
    // C++11 用 bind / lambda
    auto it2 = std::find_if(
        coll.begin(), coll.end(),
        std::bind(std::greater<int>(), std::placeholders::_1, 42)
    );
    // 或
    auto it3 = std::find_if(
        coll.begin(), coll.end(),
        [](int x){ return x > 42; }
    );
    ```

## 6. 配置器 allocator

- STL 的空间配置器（Allocator）负责为容器分配与回收内存，并配合对象的构造与析构
- 统一的内存管理提升了可用性、可移植性和效率

---
以 SGI-STL 为例介绍其两级分配器及相关工具

- STL 分离了“原始内存分配/回收”与“对象构造/析构”，可针对不同类型做优化  
- SGI-STL 默认两级分配器：大块走 `malloc/free`，小块走内存池  
- `simple_alloc` 按元素包装字节级接口，符合容器需求  
- `uninitialized_copy` / `uninitialized_fill` 系列算法完成“未初始化内存”上的安全构造  

理解 Allocator 体系，有助于深入掌握 STL 容器的性能与定制化内存管理。

## 6.1 概述

- **职责分离**  
  - `allocate` / `deallocate`：只做内存（原始字节）的分配和释放  
  - `construct` / `destroy`：只做对象的构造和析构  

- **优势**  可根据类型特性（type traits）优化：  
    - 对于 POD 类型，构造可用 `memset`、析构可跳过  
    - 对于非平凡类型，保证正确调用构造/析构  

- **默认分配器**  
  - SGI-STL 中称为 `std::alloc`  
  - C++ 标准库中对应 `std::allocator<T>`  

---

## 6.2 SGI 二级分配器（Two-Level Allocator）

1. **第一级 allocater**  
   - 直接封装 `malloc` / `free`  
   - 处理大块内存申请  

2. **第二级 allocator**  
   - 如果请求字节数 > 128 B → **转交第一级**  
   - 如果请求字节数 ≤ 128 B → **内存池（memory pool）管理**  
     - 将小块内存按 8 B、16 B、…、128 B 分级  
     - 空闲链表（free list）快速分配/回收，减少碎片与系统调用

## 6.3 `simple_alloc`：元素化的包装

容器（如 `vector<T>`）内部即通过 `simple_alloc<T, alloc>` 来按元素而非按字节进行分配


```cpp title:"SGI 将上述字节级接口进一步封装，按元素数量进行分配／释放："
// T: 容器元素类型；Alloc: 第一级或第二级分配器
template<class T, class Alloc>
class simple_alloc {
public:
    // 分配 n 个 T
    static T* allocate(size_t n) {
        return 0 == n
            ? nullptr
            : static_cast<T*>(Alloc::allocate(n * sizeof(T)));
    }
    // 分配 1 个 T
    static T* allocate() {
        return static_cast<T*>(Alloc::allocate(sizeof(T)));
    }
    // 释放 n 个 T
    static void deallocate(T* p, size_t n) {
        if (p && n > 0)
            Alloc::deallocate(p, n * sizeof(T));
    }
    // 释放 1 个 T
    static void deallocate(T* p) {
        Alloc::deallocate(p, sizeof(T));
    }
};
```

## 6.4 未初始化的拷贝与填充工具

当内存已经分配好，但未对其中的对象逐一调用构造函数时，可使用以下算法，在“原始内存”上完成对象构造：

```cpp
// 拷贝 [first, last) 到 result 开始处，构造对象
template<class InputIterator, class ForwardIterator>
ForwardIterator
uninitialized_copy(InputIterator first,
                   InputIterator last,
                   ForwardIterator result);

// 在 [first, last) 区间用 x 构造对象
template<class ForwardIterator, class T>
void uninitialized_fill(ForwardIterator first,
                        ForwardIterator last,
                        const T& x);

// 在 [first, first + n) 区间用 x 构造对象
template<class ForwardIterator, class Size, class T>
ForwardIterator
uninitialized_fill_n(ForwardIterator first,
                     Size n,
                     const T& x);
```

- **特点**  
  - 对每个目标位置**逐一**调用 `new (地址) T(…)`  
  - 若其中途出现异常，可“回滚”已构造对象并释放内存

# STL 是线程安全的吗?

> [!example] STL 并不是“开箱即用”的全局线程安全库，但它在不同层面上对并发访问提供了有限的保证
>    - **同一容器**的并发“读写”或“写写”都必须**外部加锁**（`mutex`）；并发只读可不锁
>    - **不同容器实例**之间互不影响，可自由并发使用
>    - 对于自定义 Allocator 或自建内存池，要确认其内部是否线程安全；若不确定，最好在容器外层加互斥
>    - C++11 后可借助 `std::atomic`、并发容器（如 TBB、folly）、`std::shared_mutex`／`std::shared_lock` 实现更高性能的读写锁策略

##### 1. C++11 前：

- 标准并未定义“线程”或“并发执行”，也就没有对线程安全的要求
- 大多数 STL 实现（包括 SGI、MSVC、GCC）依赖于底层 `malloc`/`free`（或自建内存池），这些通常是线程安全的（内部有锁）
- 对同一个容器或同一份数据，任何一个写（或写+读）操作都可能破坏数据，务必外部加锁；多个线程对不同容器实例进行各自的读写，一般不存在冲突

##### 2. C++11 及以后：  
标准明确了并发执行模型（memory model），并对容器的并发访问做了最小保证：

- 不同容器对象：可以并发读写、读写混合，无需额外同步
- 同一容器对象：  
    · 多线程**只读**（`const` 成员函数）——安全；  
    · 至少有一个线程执行**写**（非 const 成员）——不安全，未定义行为，必须同步
- 全局/静态变量初始化：C++11 保证局部静态变量首次初始化是线程安全的（线程互斥）

##### 3. I/O 与全局状态

- `std::cout`、`std::cerr` 等流对象对每次输出操作（通常以字符或字符串为单位）内部带锁，保证“单次写入”不交错，但若多次连续输出需要自己加锁以保证整体原子性
- `std::locale` 的更改、全局状态（如 `std::setlocale`）非线程安全，需要外部同步

##### 4. 迭代器与失效
- 任何并发写操作可能使其它线程持有的迭代器或引用“失效”，需要特别关注容器的扩容、插入、删除等操作的迭代器失效规则

##### 中介者模式

中介者模式用一个中介对象来封装一系列对象交互，降低各对象间的耦合度。以下是一个简单的 C++ 中介者模式示例代码：


```cpp title:"Mediator"

#include <iostream>
#include <string>
#include <vector>

// 前向声明
class Mediator;

// 抽象同事类
class Colleague {
protected:
    Mediator* mediator;
public:
    Colleague(Mediator* m) : mediator(m) {}
    virtual void send(const std::string& message) = 0;
    virtual void receive(const std::string& message) = 0;
};

// 抽象中介者类
class Mediator {
public:
    virtual void sendMessage(const std::string& message, Colleague* sender) = 0;
};

// 具体同事类
class ConcreteColleague1 : public Colleague {
public:
    ConcreteColleague1(Mediator* m) : Colleague(m) {}
    void send(const std::string& message) override {
        std::cout << "ConcreteColleague1 sends message: " << message << std::endl;
        mediator->sendMessage(message, this);
    }
    void receive(const std::string& message) override {
        std::cout << "ConcreteColleague1 receives message: " << message << std::endl;
    }
};

class ConcreteColleague2 : public Colleague {
public:
    ConcreteColleague2(Mediator* m) : Colleague(m) {}
    void send(const std::string& message) override {
        std::cout << "ConcreteColleague2 sends message: " << message << std::endl;
        mediator->sendMessage(message, this);
    }
    void receive(const std::string& message) override {
        std::cout << "ConcreteColleague2 receives message: " << message << std::endl;
    }
};

// 具体中介者类
class ConcreteMediator : public Mediator {
private:
    ConcreteColleague1* colleague1;
    ConcreteColleague2* colleague2;
public:
    void setColleague1(ConcreteColleague1* c) { colleague1 = c; }
    void setColleague2(ConcreteColleague2* c) { colleague2 = c; }
    void sendMessage(const std::string& message, Colleague* sender) override {
        if (sender == colleague1) {
            colleague2->receive(message);
        } else {
            colleague1->receive(message);
        }
    }
};

int main() {
    ConcreteMediator* mediator = new ConcreteMediator();
    ConcreteColleague1* colleague1 = new ConcreteColleague1(mediator);
    ConcreteColleague2* colleague2 = new ConcreteColleague2(mediator);

    mediator->setColleague1(colleague1);
    mediator->setColleague2(colleague2);

    colleague1->send("Hello from Colleague1");
    colleague2->send("Hello from Colleague2");

    delete colleague1;
    delete colleague2;
    delete mediator;

    return 0;
}
```
 

 
代码解释
- 抽象同事类（ Colleague ） ：定义了同事类的基本接口，包含发送和接收消息的方法。
- 抽象中介者类（ Mediator ） ：定义了中介者的基本接口，包含发送消息的方法。
* 具体同事类（ ConcreteColleague1  和  ConcreteColleague2 ） ：实现了抽象同事类的接口，通过中介者发送和接收消息。
* 具体中介者类（ ConcreteMediator ） ：实现了抽象中介者类的接口，负责协调同事之间的通信。
  main  函数：创建中介者和同事对象，设置中介者与同事的关系，并测试消息的发送和接收。
