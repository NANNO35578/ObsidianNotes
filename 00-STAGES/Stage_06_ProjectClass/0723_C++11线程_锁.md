# C++ 11线程`std::thread`
- 头文件`<thread>`
- 创建`std::thread`的对象 对象会拥有一个线程
- `std::thread(F&&, Args&&...)` 构造函数参数 `F&&`: 线程函数 `Args&&`: 函数参数,可有多个
- 构造完即执行 线程函数返回忽略 对象析构时线程需结束
- 线程对象正确析构:
	1. `join()` : 阻塞调用线程, 直到`*this`线程完成执行, 完成与join返回同步
		- 多个线程调用对象的join会导致未定义行为
	2. `detach()` : 设置线程分离态, 线程执行完退出. 使用标志位退出
		- 调用之后`*this`不在拥有任何线程

```cpp
#include <iostream>
#include <thread>

class MyThread {
public:
    MyThread() : running(true) {
        // 创建线程并分离
        std::thread(&MyThread::run, this).detach();
    }

    ~MyThread() {
        // 清理资源，确保不再运行
        running = false;
    }

    void run() {
        while (running) {
            // 模拟工作
            std::this_thread::sleep_for(std::chrono::milliseconds(100));
            std::cout << "Thread is running.\n";
        }
        std::cout << "Thread is exiting.\n";
    }

private:
    volatile bool running; // 使用 volatile 防止优化
};
```

## 数据竞争(Data Race)
- 多个线程同时访问同一*共享资源*，且至少有一个线程在修改该资源，可能导致不可预测的结果。这种情况称为数据竞争

| 死锁(Deadlock)            | 当两个或多个线程互相等待对方释放资源时，导致所有线程都无法继续执行。死锁会使程序永久挂起。                |
| ----------------------- | ------------------------------------------------------------ |
| 活锁(Livelock)<br>        | 线程虽然在不断执行，但因为相互影响而无法完成任务。与死锁不同，线程仍在运行，但没有进展。<br>             |
| 资源饥饿(Starvation)<br>    | 某些线程因为资源被其他线程长期占用而无法获得执行的机会，导致无法完成任务。可能是由于优先级调度或不当的资源分配。<br> |
| 不一致性(Inconsistency)<br> | 共享数据在不同线程中可能会导致不一致状态。例如，多个线程修改同一数据结构时，可能会导致数据损坏或状态不一致。<br>   |
| 线程安全性问题<br>             | 如果类或函数没有正确设计为线程安全，可能会导致上述问题。因此，设计和实现时必须考虑到并发安全<br>           |

## 线程同步
- 解决数据竞争: 同一时间只允许一个线程访问公共资源
- 方式: 原子访问, 互斥锁, 关键段, 事件, 条件变量...

## 原子访问

- 原子访问: 读写不可分割, 是原子的
- `std::atomic<int> g_val = 0;`
- `g_val.load()` 获取int值

## 互斥锁
- 头文件`<mutex>` 
- `std::mutex g_mutex` 对象构造时初始化, 析构回收锁
- 上锁 `g_mutex.lock();` 解锁`g_mutex.unlock();`

互斥锁提供独占、非递归的所有权语义:
- 调用线程从成功调用lock 或 try_lock到调用unlock期间拥有该互斥锁
- 当一个线程拥有该互斥锁时,所有其他线程如果试图声明对该互斥锁的所有权,将会阻塞(对于lock调用)或收到false返回值(对于try_lock调用)
- 调用线程在调用lock或try_lock之前不得拥有该互斥锁

> 如果互斥锁在仍由任何线程拥有时被销毁,或者线程在拥有互斥锁时终止,则程序的行为是*未定义*的
- 互斥锁类满足[Mutex](https://en.cppreference.com/w/cpp/named_req/Mutex.html)和[StandardLayoutType](https://en.cppreference.com/w/cpp/named_req/StandardLayoutType.html)的所有要求
- std :: mutex既不可复制也不可移动

## `std::lock_guard<std::mutex>`
- 用于实现对互斥量（mutex）的自动锁定 *RAII*原则的一个典型示例
- 在对象的生命周期内互斥量保持锁定，并在对象超出作用域时自动释放锁
```cpp
void thrdFunc(int num) {
    std::cout << __func__ << '\n';
    for (int i = 0; i < num; ++i) {
		
        {
            std::lock_guard<std::mutex> g_guard(g_mutex);
            ++g_val;
        } // 当 g_guard 被销毁时，自动释放锁
        
        _sleep(5);  // *放弃CPU 10ms 就绪
    }
}
```


## `std::unique_lock<std::mutex>`
- 在lock_guard 基础之上,加入接口`unloack`可以主动释放锁
```cpp
        std::unique_lock<std::mutex> g_unique(g_mutex);
        ++g_val;
        g_unique.unlock();
```
