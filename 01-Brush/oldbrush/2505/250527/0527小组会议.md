# 通信模式`C/S`与`P2P`的区别？
C/S即Client/Server P2P即Peer-to-Peer
##### C/S（Client/Server）模式

1. **架构**：
    - 客户端和服务器两部分。
    - 客户端发起请求，服务器处理请求并返回响应。
2. **管理**：
    - 服务器集中管理资源和数据。
    - 适合需要集中控制和安全性高的场景。
3. **扩展性**：
    - 服务器负载可能成为瓶颈，扩展性相对较差。
    - 需要增加服务器硬件来提升性能。
4. **示例**：
    - Web应用、在线游戏等。

##### P2P（Peer-to-Peer）模式
1. **架构**：
    - 所有节点（peer）平等，各自可以作为客户端和服务器。
    - 直接交换数据，无需集中服务器。
2. **管理**：
    - 去中心化，节点之间直接通信。
    - 更加灵活，适合分布式应用。
3. **扩展性**：
    - 更具扩展性，节点增加时可以提升整体网络的能力。
    - 负载分散在所有节点上。
4. **示例**：
    - 文件共享（如BitTorrent）、区块链等。

# 在数据模式中，全网状与星状区别？

##### 全网状（Mesh Topology）
1. **结构**：
    - 每个节点与网络中的所有其他节点直接连接。
    - 形成一个高度互联的网络。
2. **优点**：
    - 高可靠性，若某个节点失效，其他节点仍可通信。
    - 数据传输路径灵活，减少延迟。
3. **缺点**：
    - 复杂性高，维护成本大。
    - 随着节点增加，连接数量迅速增加。
4. **应用**：
    - 多用于需要高可靠性和低延迟的场景，如军事通信。

##### 星状（Star Topology）
1. **结构**：
    - 所有节点通过单一中心节点连接。
    - 中心节点负责管理和转发数据。
2. **优点**：
    - 结构简单，易于维护和管理。
    - 新节点添加方便，故障影响有限。
3. **缺点**：
    - 中心节点故障会导致整个网络瘫痪。
    - 数据传输依赖中心节点，可能成为瓶颈。
4. **应用**：
    - 常见于家庭和小型办公室网络。

# 在网络同步中，状态同步与帧同步区别？

##### 状态同步
 **定义**：所有客户端定期更新并共享当前的游戏或应用状态。
 
1. **工作方式**：
    - 客户端通过发送状态数据（如位置、生命值等）给服务器，服务器再将状态广播给所有客户端。
2. **优点**：
    - 更容易处理大规模数据，适合实时性要求较低的应用。
    - 灵活性高，允许不同的帧率和延迟。
3. **缺点**：
    - 状态更新可能导致不同步，容易出现“画面撕裂”现象。
    - 需要额外的逻辑来处理状态一致性。
4. **应用**：
    - 多用于MMORPG、策略类游戏等。

##### 帧同步
**定义**：所有客户端在同一时间步进行同步，确保每个帧的数据一致。

1. **工作方式**：
    - 客户端在每一帧发送输入数据，服务器根据这些输入计算并发送回合的状态。
2. **优点**：
    - 更加精确，所有客户端的游戏状态始终一致。
    - 适合对实时性和同步性要求极高的应用。
3. **缺点**：
    - 对网络延迟敏感，可能导致卡顿。
    - 扩展性差，处理大规模玩家时困难。
4. **应用**：
    - 多用于对抗类游戏（如格斗、射击类游戏）。

# TCP的四种拥塞控制算法

> 网络中的链路容量和交换结点中的缓存和处理机都有着工作的极限

- 当网络的需求超过它们的工作极限时 就出现了拥塞
- 在网络出现拥堵时 如果继续发送大量数据包 可能会导致数据包时延、丢失等 这时TCP就会重传数据 但是一重传就会导致网络的负担更重 于是会导致更大的延迟以及更多的丢包 这个情况就会进入恶性循环被不断地放大 ...
![[拥塞控制.png]]

四种算法 :
 1. 慢开始(慢启动)
 2. 拥塞避免
 3. 快重传
 4. 快恢复


## 慢开始与拥塞避免

- 发送方维持一个叫做 _拥塞窗口cwnd_(congestion window)的状态变量。
- 拥塞窗口的大小取决于网络的拥塞程度,并且动态地在变化。
- 发送方让自己的发送窗口等于拥塞窗口,另外考虑到接受方的接收能力,发送窗口可能小于拥塞窗口。

$发送方发送数据大小 <= min(滑动窗口, 拥塞窗口)$ 

> 慢开始算法的思路就是,不要一开始就发送大量的数据,先探测一下网络的拥塞程度,也就是说由小到大逐渐增加拥塞窗口的大小。

 为了防止cwnd增长过大引起网络拥塞,还需设置一个 _慢开始门限ssthresh_ 状态变量。
ssthresh的用法如下:
- 当cwnd<ssthresh时,使用慢开始算法。
- 当cwnd>ssthresh时,改用拥塞避免算法。
- 当cwnd=ssthresh时,慢开始与拥塞避免算法任意。

拥塞避免算法让拥塞窗口缓慢增长,即每经过一个往返时间RTT就把发送方的拥塞窗口cwnd加1,而不是加倍。这样拥塞窗口按线性规律缓慢增长。
![[慢开始与拥塞避免.png]]

 ==慢开始== : 指一开始向网络注入的报文段少,并不是指拥塞窗口cwnd增长速度慢(指数增长);
 ==拥塞避免== : 并非指完全能够避免拥塞,而是指在拥塞避免阶段将拥塞窗口控制为按线性规律增长(加一),使网络比较不容易出现拥塞;

发生超时重传(时间点12),判断网络可能出现拥塞:
1. 将ssthresh的值更新为发生拥塞时的cwnd的一半
2. 将cwnd的值减少为1,并重新开始执行慢开始算法
