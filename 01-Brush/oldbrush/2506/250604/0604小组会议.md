# cookie和session的区别
Cookie 和 Session 是两种用于在 Web 应用中存储用户数据的技术

##### 1. 存储位置
- **Cookie**：存储在用户的浏览器中，是客户端数据。
- **Session**：存储在服务器端，客户端只保存一个 Session ID。
##### 2. 数据大小
- **Cookie**：每个 Cookie 的大小限制通常为 4KB。
- **Session**：可以存储更大数量的数据，具体取决于服务器的配置。
##### 3. 安全性
- **Cookie**：由于存储在客户端，容易受到 XSS 攻击，安全性较低。
- **Session**：数据存储在服务器上，相对安全，但需防范 CSRF 攻击。
##### 4. 生命周期
- **Cookie**：可以设置过期时间，过期后自动删除。
- **Session**：通常在用户关闭浏览器或超时后失效。
##### 5. 用途
- **Cookie**：常用于存储用户偏好设置、登录信息等。
- **Session**：常用于跟踪用户会话状态，如登录状态、购物车内容等。

# `socket` 阻塞和非阻塞的发送和接收缓冲区分别是什么样的?
##### 1. 阻塞模式
- **发送缓冲区**：当应用程序调用发送函数（如 `send`）时，如果缓冲区已满，调用会阻塞，直到有足够的空间可用。发送操作会一直等待，直到数据被成功发送到网络中。
- **接收缓冲区**：当应用程序调用接收函数（如 `recv`）时，如果没有数据可用，调用会阻塞，直到有数据到达。接收操作会等待数据到达。

##### 2. 非阻塞模式
- **发送缓冲区**：在非阻塞模式下，如果发送缓冲区已满，调用发送函数会立即返回一个错误（通常是 `EWOULDBLOCK` 或 `EAGAIN`）。发送操作不会等待，可以选择稍后再尝试发送。
- **接收缓冲区**：在非阻塞模式下，如果没有数据可用，接收函数也会立即返回一个错误。接收操作不会等待，应用程序可以继续执行其他任务。

# `select`, `poll`, `epoll`都是干什么的，区别

- **`select`**：简单、兼容性好，但文件描述符数量有限。
- **`poll`**：没有数量限制，适用于中等规模的应用。
- **`epoll`**：高性能，适合处理大量文件描述符的场景。

`select`、`poll` 和 `epoll` 是用于 I/O 多路复用的系统调用，主要用于监视多个文件描述符（如套接字）的状态，以便在某些文件描述符上进行非阻塞 I/O 操作
##### 1. `select`
- **功能**：监视多个文件描述符，等待其中至少一个变为“就绪”状态（可读、可写或异常）。
- **限制**：最大文件描述符数量通常为 1024（可通过系统参数调整）。
- **效率**：对于大量文件描述符，性能会下降，因为每次调用都需要复制文件描述符集合。
- **使用场景**：适合处理少量文件描述符的简单应用。
##### 2. `poll`
- **功能**：类似于 `select`，也用于监视多个文件描述符。
- **限制**：没有文件描述符数量的限制，只受系统内存限制。
- **效率**：使用一个数组来存储文件描述符，避免了 `select` 的文件描述符集合复制问题，但在文件描述符数量增加时仍然可能导致性能下降。
- **使用场景**：适合中等数量文件描述符的应用。
##### 3. `epoll`
- **功能**：专为 Linux 设计的 I/O 多路复用机制，支持大规模的文件描述符监视。
- **特点**：
    - **边缘触发和水平触发**：支持两种触发模式，灵活性更高。
    - **事件通知**：只在文件描述符状态变化时通知，减少不必要的检查。
- **效率**：在处理大量文件描述符时，性能优于 `select` 和 `poll`，因为它只关注活跃的文件描述符。
- **使用场景**：适合高性能、高并发的网络应用。
