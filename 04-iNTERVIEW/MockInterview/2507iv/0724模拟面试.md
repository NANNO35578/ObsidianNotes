# 多态主要分为哪两类
C++中的多态是面向对象编程的重要特性之一，它*允许程序在运行时根据对象的实际类型来决定调用哪个函数*。这种机制主要通过虚函数实现。多态的主要形式有两种：编译时多态（静态多态）和运行时多态（动态多态）。

### 1. 编译时多态
编译时能够确定调用哪个函数，编译时多态通常通过函数重载和运算符重载实现。
速度快，效率高，缺乏灵活性
- **函数重载**：同一个函数名可以有不同的参数列表。
    ```cpp
    void print(int i) {
        std::cout << "整数: " << i << std::endl;
    }
    
    void print(double d) {
        std::cout << "浮点数: " << d << std::endl;
    }
    ```
- **运算符重载**：允许用户定义自己的运算符行为。
    ```cpp
    class Complex {
    public:
        double real, imag;
        Complex operator+(const Complex &c) {
            return Complex{real + c.real, imag + c.imag};
        }
    };
    ```

### 2. 运行时多态
编译时不能确定调用的哪个函数，而在程序运行过程中才动态的确定具体操作对象，运行时多态通过基类指针或引用来调用派生类的重写函数，主要使用虚函数。
- **虚函数**：在基类中声明为`virtual`，在派生类中重写。
    ```cpp
    class Base {
    public:
        virtual void show() {
            std::cout << "Base class" << std::endl;
        }
        virtual ~Base() {}  // 虚析构函数
    };
    
    class Derived : public Base {
    public:
        void show() override {
            std::cout << "Derived class" << std::endl;
        }
    };
    ```
- **使用示例**：
    ```cpp
    void display(Base *b) {
        b->show();
    }
    
    int main() {
        Base *b = new Derived();
        display(b);  // 输出: Derived class
        delete b;
        return 0;
    }
    ```

### 优点
- **灵活性**：可以在运行时决定调用哪个函数，提升代码的扩展性和灵活性。
- **代码重用**：通过基类和派生类的关系，可以重用代码，减少冗余。
- **接口一致性**：通过统一的接口，增加了代码的可读性和可维护性。
### 4 注意
- **虚函数表**：每个类有一个虚函数表，存放虚函数的指针。在对象创建时，会生成指向该表的指针。
- **性能开销**：多态会引入一定的性能开销，因为需要通过虚函数表进行查找。
- **对象切片**：当基类*对象(非指针)*被赋值为派生类对象时，可能会丢失派生类特有的数据和行为。

# C++函数重载如何实现的,为什么C没有
## 调用约定 [# Calling convention](https://en.wikipedia.org/wiki/Calling_convention) [x86](https://en.wikipedia.org/wiki/X86_calling_conventions#thiscall)
约定参数怎么传递,谁来管理出栈,编译后名字的修饰方式
- 默认 : `__cdecl` 另有`__stdcall` `__fastcall`
- 如`scanf` `printf`等边长参数函数,不知道参数大小,只能由调用者回收
- Win32的API绝大部分是__stdcall调用约定 WINAPI只是__stdcall别名

[实际上C++名称修饰没有标准,不同编译器或同一编译器不同版本也不相同](https://en.wikipedia.org/wiki/Name_mangling#How_different_compilers_mangle_the_same_functions)

参数传递中对于类的成员函数(包括静态成员函数),`this`指针的传递是否在显示参数之前或之后也无标准

| 调用约定         | 管理出栈方 | 参数传递                                             | 名称修饰                                                               | C++名称修饰<br>(MSVC)      |
| ------------ | ----- | ------------------------------------------------ | ------------------------------------------------------------------ | ---------------------- |
| `__cdecl`    | 函数调用方 | 从右至左的顺序压参数入栈                                     | 下划线+函数名(c编译)                                                       | ?+函数名@@YA+参数表@Z(c++编译) |
| `__stdcall`  | 函数本身  | 从右至左的顺序压参数入栈                                     | 下划线+函数名+@+参数的字节数,如函数`int func(int a,double b)`的修饰名是`_func@12`(c编译) | ?+函数名@@YG+参数表@Z(c++编译) |
| `__fastcall` | 函数本身  | 头两个DWORD(共4字节)类型者占更少字节的参数被放入寄器,其他剩下的数按从右到左的顺序压入栈 | @+函数名+@+参数的字节数(c编译)                                                | ?+函数名@@Yl+参数表@Z(c++编译) |

## C++调用约定与`this`指针
- C++自己还有一种特殊的调用惯例,称为`thiscall`,专用于类成员函数的调用
- 其特点随编译器不同而不同,在VC(MSVC)里是this指针存放于ecx寄存器,参数从右到左压栈
- 而对于gcc(Linux/MinGW),`thiscall`和`__cdecl`完全一样,只是将this看作是函数的第一个参数
